# Workspaces

Part of [[Web board]].

## In plain words
Workspaces: each project's folders and branches listed in the side menu, the cards for the agents working in them, and the page a workspace opens into.

## Where it lives
- Projects list = workspaces (since run 2026-10-29-board-workspace-sidebar; `drawList()` in `web/board/workspace.ts`): every project from `/state` `projects` with its `workspaces` (`workspaces()` in `cli/worktree.ts`: `git worktree list --porcelain`, main checkout first as the registered folder, prunable/bare and detached-outside-project skipped, real paths, 10 s cache; a non-git folder is one "workspace"; the global queue is its own). No run rows. Each `/state` run card carries `ws` (`wsOf()`: its `state.json` `worktree` while on disk, else the project); the rail puts a card whose `ws` is not listed, and every task, under the main checkout (`wsOfCard`), so a waiting run never vanishes. A row: `stateOf` dot of its most urgent listed card, count of the runs the panel's picker lists (`pickable()`: waiting + active, a button that opens the picker, a sibling of the row's link inside `div.wsr`, not nested in it), link `/?view=ws&dir=&ws=`. A ws address opens the workspace centre (next bullet); `markCurrent()` lights the ws row, also for an old `?view=run&id=` link. Filter "done" = workspaces holding only finished runs. The project row's `+` (git projects, hover) opens the add sheet's New workspace form (project, branch name, base branch) → `POST /worktree {dir, branch, base?}` (`strict()`, registered non-global dir, `addWorktree()`: `git check-ref-format --branch`, no leading `-`, `git worktree add -b <branch> <project>/.kaizen/wt/<slug>`, argv only).

- Workspace cards (since run 2026-10-29-board-sidebar-agent-cards; `drawList()` in `web/board/workspace.ts`, pure parts in `web/board/ws-tabs.ts`): each workspace row is a card (dot + branch (no `primary` chip, no count on the project row: both hidden as confusing), folder/worktree line, then the agents open in it). `/state` carries one top-level `agents` array built once per tick in `cli/web.ts` (agent shells plus each card's `pty.all`, live ones only, deduped by key): `{key, dir, ws, agent, name, run, asking, busy, born, last, at}` (`last`/`at` only when Host is loopback, the remote address is loopback and none of `x-forwarded-for`/`x-forwarded-host`/`forwarded`/`tailscale-user-login`/`tailscale-user-name` is present: a tailnet host, phone or proxied request gets status alone). Status: asking first, working = `busy` (the agent's `WORK` line drawn within `QUIET_MS`; plain output such as a status-line refresh or a repaint is not work), else done; `agentStatus()` holds working for 3 s after the last busy tick (`SETTLE_MS`, `settleIn()` schedules the redraw). One agent: "Done - Claude" + age; several: chips grouped asking/working/done plus a chevron that expands an "N agents" list (open state in localStorage `kz-wsopen`, `dir\0ws` to true). `last` is the agent's latest output line only (`lastLine()`/`grab()` in `cli/pty.ts`): ANSI, boxes, spinners and TUI footers stripped, and the input is never shown: a line led by a prompt marker (`❯ › > $ #`) or inside the box-drawn input region (`╰…╭`) is skipped; keystrokes are never stored (`writePty` keeps only a timestamp), and nothing is read while the pty asks or within 1.5 s of a keystroke (terminals echo input). Memory only. The row shows status + agent name when there is none. `seenBusy` is keyed by pty key + `born`, so a restarted pty is not held at working. Every string goes through `html` (escaped); a mark click fires `kz-open-term {dir, ws, key}` (run-view selects that tab; notes/video just open the workspace). `drawList()` skips the DOM write when the markup is unchanged. Card CSS is one block copied into `board.html`, `notes.html`, `video.html`; the notes/video sprites gained `i-claude`, `i-codex`, `i-gemini`, `i-ai`. The class is `wsc`: a bare `.card` carries a 12px/14px padding of its own.

- Terminal follows its run (since run 2026-10-31-worktree-ask-agent-placement): board terminals get `KAIZEN_TERM=<key>`; `kaizen worktree start` writes `sessions/<key>.run` (`linkTerm`). `linkedWs()` gives the live run's worktree, null on done, abandoned or a missing worktree. `shown()` in `cli/web.ts` overrides `ws` and `run` in `/shells` and the `/state` agents; the shell record itself keeps its launch values. It also refreshes a stale worktree list, since `workspacesNow` answers from cache until a later tick.

- Workspace centre (since run 2026-10-29-board-workspace-centre; `?view=ws&dir=&ws=`, `web/board/run-view.ts` with the pure parts in `web/board/ws-tabs.ts`): one centre per workspace, its saved layout under `kz-runtabs` key `ws:<dir>:<path>` (`wsKey`). `migrate()` moves old per-card keys (`run:`/`idea:`) into their workspace once, merging tabs, hidden ids and screens (an item stays in one screen); a key no card on the board owns is left alone. **Runs are not tabs** (run 2026-10-29-board-run-picker-panel): the centre holds only terminals and the Browser. Tabs: for each live run (`liveIn()`: not archived, not `finished()`; a `done` run with `accept: "needs"` still counts) and each task with an open agent, its terminals (`stageTabs()`: a terminal a stage claimed is titled `Plan · Claude Code`, `Build · …`, `Review · …`, the rest keep the agent's name, numbered when several; ids `agent:<pty key>`), shells whose `run` is that run's key, and the `wait:` note; then the workspace's own shells (`/shell {ws, run: <ws key>}`; the server stores `ws` on each shell record) and tabs opened by hand (Browser, Preview, notes, History). Saved `kind:"run"` tabs and `rn:` hidden ids from older layouts are dropped in `saved()`. Nothing about run tabs is stored server-side: `kept.json`, `POST /kept`, `readKept`/`setKept` and `Run.kept` are gone (a stale `kept.json` is ignored). One xterm per tab, mounted once per pane. **The run panel** `#panel` stays docked in `.app`'s right column (340px, icon strip inside) and shows one run, picked in the picker at the top of its header (`web/board/run-pick.ts`: `#ppick` trigger with the run's state dot and title, `#ppop` popover, class `.ppop`/`.pk`, not `.menu-pop`, which `main.ts` removes on an outside press). `pickable()` lists the runs not over, waiting on you first (`awaiting()`), then newest; a History group at the bottom lists `historyOf()` (done/abandoned, newest first, shown read-only: panel class `ro`, whose CSS hides only the edit buttons (Archive/Restore/Resume/Abandon/Approve); the git buttons stay). A done, approved run whose `/state` card `git` mark is `pending` (commit or push still to do; `gitDue()`) is not `finished()`: it stays pickable, counts as `awaiting()`, shows `stateOf` `wait` (via `gitDue()`, so an archived run does not) and "waiting on you · commit" or "· push" (the card's `gitDue` field from `cardsGit`'s optional `due` map: `commit` while files are changed, `push` once committed and ahead; `dueWord()`) until the mark turns `pushed`, then moves to History. `chosen()` keeps the pick (`picked` map per workspace key, sticky) while it is still pickable or History, else the first of the list (the waiting run, else the newest), else none: the panel is then `parked` (`display:none`) and `#rside` hidden, so the terminal is full width. A run created while the workspace is open takes the pick (`followNew()` in `run-view.ts`, `newRun()` in `ws-tabs.ts`: a pickable run not in `seenRuns`, the cards seen this visit, which only grows, so a restored run or a tick missing cards is not new; a run created while another workspace is open is not followed). A run that starts waiting later does not replace the pick: the trigger gets an amber `.pdot`, and with the panel collapsed `#rside` gets `data-dot` (desktop collapsed = `rflip`, phone collapsed = no `rflip`); the panel never pops open. Picking a run, or the panel's Plan / Work / Review strip, never touches the centre. `mountPanel()` calls `open(c)` only when `store.openKey` differs. An address `?view=run&id=` or `&idea=` resolves to the card's workspace (`wsOfCard`) and sets that run as the pick on every navigation; a fresh visit to a workspace (another workspace or another page before) drops the old pick, so waiting-first applies again; one made during the visit stays; (`showRunView(nav)`; a `/state` refresh does not), a finished one read-only. The side menu shows no run counts (removed on the user's request); the picker opens from the panel header. The tab bar's `#rside` collapses the panel (`rflip`, a width slide). Phones (≤640px): the panel is a bottom sheet opened by `#rside` (sticky at the bar's right, 44px; `rflip` means open there, closed on desktop) and closed by its `#pclose` (which also shuts the picker); picker trigger and rows are 44px. A workspace with no tab at all opens a plain shell (`POST /shell {dir, ws, run: <ws key>}`, no agent) once per visit; "New agent here" in + starts the default agent. Tab titles cap at 180px with an ellipsis. Settings in the side menu is the gear icon only. A live run with no agent terminal still resumes its recorded Claude session (`openAgent(c, false, false)`, `ws` sent). A run started with `kaizen worktree start` from inside another workspace of the project records `workspace` in `state.json` (`adoptWorkspace()`, read by `wsOf()`), not `worktree`: `land` removes a run's own worktree and branch and must never touch one the user made. Per-stage terminals: `/decide` on `approvals.plan` records the launched terminal as `impl`, `/decide` on findings and `/fix` record `review`, in `runs/<id>/terminals.json`; `/state` cards carry them as `pty.stages`. `stageKeys()` (`ws-tabs.ts`) maps them to Plan/Build/Review and records the task's agent as plan once its run exists (`markStage`, only into an existing `runs/<id>`); a session not recorded falls back, only when it is the run's lone one, to the run's current stage by `column` (1 Plan, 2 Build, 3 Review), else it stays the plain agent name. The project group's fold chevron sits at the right of the header row, hidden until hover or keyboard focus (always visible under `@media(hover:none)`); the rail CSS is repeated in `notes.html` and `video.html`.

## Explore integration (2026-11-08)

Run details show an optional Explore step and brief before Plan, with per-run Skip Explore. Active exploration terminals are labelled Explore. See [[Web board/Cards]].

## Persistent Tasks (2026-11-08)

Shared durable task projections supply the workspace task links/reasons and waiting counts. A task may own multiple linked runs while one task page remains visible; the rail uses its stable task URL. Technical workspace tools are preserved under the task page details.
