# Cards

Part of [[Web board]].

## In plain words
The cards on the board: how they sort, what each shows, the one button that says what a run needs from you, and the search and add sheets.

## Where it lives
- `web/board/badge.ts` reads `/state?all=1` at most once per 2 s (overlapping calls still coalesce). The run view's right panel (`#panel`) is resized by dragging `#rgrip` on its left edge (`initGrip` in `web/board/run-view.ts`, width in `--rpanel-w`, kept in localStorage `kz-rpanel-w`, double-click resets, clamped 260 px to 60% of the window); the desktop window follows the refresh rate of the monitor it is on (the app measured 60 fps on a 60 Hz screen and 144 fps on a 144 Hz one).

- Child cards: a card whose `parent` (from a `Parent:` / `Follow-up of:` line, `parentOf` in `cli/state.ts`) names a run on the board that is not archived and not done is drawn only as a row inside that run's card (`kidsOf`/`nested` in `web/board/cards.ts`): a collapsed `N children · M done` toggle, an orange dot when a child waits on you, and rows that open the child's own panel; a run row is labelled with its run name (like the card header), wrapped, title in the tooltip. Once the parent is done, archived or gone, children are back in their own columns.

- Global search (since run 2026-10-29-global-search; `web/board/search.ts`, modelled on Orca's "Jump to..." palette, studied with REA): `#gsearch`, the first rail item in board/notes/video.html, and Ctrl/Cmd+K anywhere (plus Cmd+J on mac; not Ctrl+Shift+J, Chrome's console; never inside `.xterm`) open a `<dialog class="gs">`. `initSearch()` runs first in `initRail()` and injects its own CSS. Items come from `railData()` (workspaces, projects, runs, tasks, agent terminals) and `GET /chats`, plus pages and actions that click the rail's own controls. Groups: Current, Workspaces, Tabs, Chats & terminals, Runs, Tasks, Projects, Actions, Create (`New task "q"`); typed, the group with the best match comes first. Rows are title, project and a short age; no hint footer (run 2026-10-29-search-open-tabs). Tabs are read from the run view's saved layouts (`localStorage kz-runtabs`, `wsKey`): local/preview/note/history/shell, not hidden ones; a pick raises `kz-open-tab {dir, ws, id}`, which `run-view.ts` answers by selecting the screen holding the tab, and off the board search writes that `on` to storage and loads the workspace. The palette redraws on `kz-rail`. Matching (`search-match.ts`, tested): every word present; title prefix > title contains > rest, then recency. Picks open in place through `kz-open-ws`/`kz-open-card`/`kz-open-term`, else navigate. Hidden on phones. Not done: notes and settings rows by name.

- Add sheet (since run 2026-10-29-board-new-project-form; `openAdd()` in `web/board/add-project.ts`, modelled on Orca's "Add a project"): the Projects header `+` (`#padd`, `initRail()` in `web/board/workspace.ts`, no longer New idea: that lives on the Tasks/Board header button) opens a chooser, Existing folder, then "Other ways to add": Clone from URL, Create new project, New workspace (only when a git project exists), each a form with Back to add options and an inline `.err` line. The project picker's "New project…"/"Clone…" and a project row's `+` open the same sheet (`start: create|clone|ws`). A project added closes the sheet, toasts "Project added/created/Cloned/already added", and is picked in place through `pick()` in `web/board/projects.ts` (`/cd`, `kz-proj`, `load()`), no page reload. Server side, all in `cli/web.ts` before the generic POST block (which would `canonState()` a `..` away) and all `strict()` (same host:port, JSON content type), argv only, validators in `cli/add-project.ts`: `POST /add-project {path}` (existing folder, `.kaizen` made, `already` true when registered), `POST /new-project {name,to,git,check}` (folder + `.kaizen` + `git init -q -- <to>`, a failed init is reported as `git:false`, not rolled back; non-empty target 409), `POST /clone {url,to,check}` (`cloneInto()`: `git clone -- url to`, `GIT_ALLOW_PROTOCOL=https:ssh`, no prompts, ssh BatchMode, 5 min kill, a folder it made is removed on failure; `gitUrl()` takes only `https://`, `ssh://`, `user@host:path`, host letters/digits/dots/dashes not leading `-`, no credentials, no `..`; ext::, file:, git://, http://, local paths refused), `GET /branches?dir=` (known project only; `branchesOf()`: `for-each-ref` local + origin, `def` = origin/HEAD, else main/master, else current), `POST /worktree {dir,branch,base?}` (base must be one of `branchesOf()`, never option-like; `git worktree add --no-track -b <branch> -- <path> <base>`). `destDir()` refuses root, home, `~/.kaizen`, any `.git`/`.kaizen` segment, `..` in the text, Windows-bad names and any place below a known project or a folder with a `.kaizen` (a nested `.kaizen` shadows the outer project's runs; home's own `.kaizen` is exempt). Tests: `cli/add-project.test.ts` (validators, branchesOf, cloneInto with an injected spawn and, with the protocol list opened, a real local repo), guards and happy paths in `cli/usage.test.ts`. Not done: a clone's progress, sparse checkout, setup scripts, hosts; the old `kz-new-idea` listener in `main.ts` has no sender now.

- New workspace form (since run 2026-10-30-create-workspace-orca; workspace branch of `openAdd()`, `dialog.wsnew`, read from Orca 1.4.244's composer, simplified): Project, a "Create from [Optional]" name box with the start branch on its label row, Advanced for an exact branch name, Ctrl/Cmd+Enter. Precedence: Advanced branch, else `branchSlug()` of the name (`web/board/ws-tabs.ts`), else `workspace-<4 random>`.

- Board modes: a Workspaces | Runs switch in the header (`#hx`, `initWsBoard()` in `web/board/ws-board-ui.ts`; `localStorage` `kz-board-mode`, default Workspaces). Workspaces draws four columns of cards, one per workspace (`groupWs()`), into `#board` from `render()` in `cards.ts` (`body.wsb` hides the Runs status strip). `columnOf()` in `ws-board.ts` places it: In review if an open run is `wait` or `review`, else In progress if any run is open, else Done if the newest finished run (archived ones count) is done, else Todo. Tasks never move a column (a waiting task only lights the dot). Search and the project filter never hide a workspace in In review, even one from another project while the board is scoped to a single project: a run waiting on the user is always shown. A card matching no listed workspace goes to the project's main checkout (else its own row). A run waiting on the user reads "waiting on you · plan approval" (`cardLine()`). A card is `<a.wcard>` that dispatches `kz-open-ws`. The Runs mode is the old five-column board. Its `kz-rail` listener ignores the echo of its own render (a render publishes the cards, which raises `kz-rail` at once); without that guard every Workspaces load overflowed the stack.

## Watch out
- Done cards are one line (`.card.compact`): they show the run name (`short(id)`), with the request's first line as its tooltip.

- `render()` (`web/board/cards.ts`) rebuilds `#board` on every `changed` event; fields need a `draft()` key (`.kaizen/memory.md`).

- A card's one ask is a button on its face (`.act`): a waiting run's `actionOf()` label ("Review plan", "See findings", "Review work") opens it, a resumable stalled run gets Resume (`approvals.ts` `resume`). The card menu's Open item uses the same `actionOf()`; `cli/board.test.ts` lifts that declaration out of the source with the menu.

- Each column sorts waiting runs first, then by its Newest/Oldest order: runs by `moved`, tasks by `added` (the inbox stamp, on the card from `cli/state.ts`) across every project, inbox position only as tiebreak.

- `render()` sets `document.title` to `(n) kaizen` while n cards need you: runs waiting on you plus cards whose live agent is asking (`pty.asking`). `badge.ts` uses that same count for the Board rail badge, once per unarchived card; Board uses its `/state` cards when showing all projects, while a selected project, Notes and Video fetch `/state?all=1` on change so the badge covers every project. Zero hides the badge, and its title and accessible label name the count.

- The header filter box `#bq` sits outside `#board`, so redraws keep its text; `draft()` keeps it over a reload. `/` focuses it when no panel is open (in an open panel `/` still goes to `#sq`); Escape clears it. It matches title, request text and run id.

- Card notes (`chat()` in `web/board/chat.ts`): each plain line written as `Label: … Label: …` renders one paragraph per label with the label bold (`pretty()`, built on `brief()` in `web/board/markdown.ts`); markdown lines (lists, headings, tables, quotes) and fenced code are left as written.  The note box itself formats as you type (`rich()` in `web/board/rich.ts`): a contenteditable editor over the hidden textarea, which stays the value for drafts, dictation and send; `toMd()` turns the editor back into markdown on each edit, and typing `**b**`, `` `c` ``, `- `, `1. ` or `# ` re-renders it with `md()`. `*i*` formats as italic. Ctrl/Cmd+B bold, Ctrl/Cmd+E code; Shift+Enter is a soft line break in a paragraph (written as two trailing spaces, which `md()` renders as `<br>`) and a new item in a list; pasted text comes in plain. `brief()` labels are a capitalised word plus up to three lowercase words, or two to four ALL-CAPS words (`OPEN QUESTION`), each optionally followed by `(…)` before the colon.

- `render()` in `web/board.html` empties and rebuilds `#board`, so any field that lives in the board loses its text and focus on every server `changed` event. A new field there needs a `draft()` key, and event-driven loads go through `load(true)`, which leaves an open form alone.

- `openSources()` in `web/board.html` rebuilds the whole panel after every action and every server `changed` event, and restores focus only to elements with an id. A native `<select>` wired to act on `change` fires on each arrow key in Chromium, so a control there must act on an explicit step and carry an id.

- Board sweeps keyed on run stage + state.json mtime must exclude sessions launched after that mtime: /fix on a done run does not touch state.json.

- `openSources()` in `web/board.html` once had a local `shown` (drawer state) that shadowed the board's global `shown` (project filter): any use of the global inside it threw a TDZ ReferenceError and blanked the Icebox. The local is now `drawer`; check for local shadows before reading a board global in a long render function.

- A run's `moved` (the running-vs-stalled signal) is the newer of `state.json` and `progress.md`, so a builder ticking its Work list stays running. Session owner lookups read every run once per call through `runIndex` (`ownerOf`'s third argument); `openSessions` drops `.pid` files whose process is gone or whose number another process now holds (`isSession` false; `null` when the system cannot say keeps it).

- Card fields needing git go in `cardsGit` (`/state`), not `boardCards()` (`.kaizen/memory.md`).
