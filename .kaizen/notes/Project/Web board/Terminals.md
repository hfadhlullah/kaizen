# Terminals

Part of [[Web board]].

## In plain words
The agent terminals inside the board: how typing reaches the agent, the terminal page with every live agent, font size and theme, and the resource monitor.

The phone terminal message box uses the placeholder “Paste text here...”.

## Where it lives
- `cli/pty.ts` + `web/term.ts` — the in-card terminal (agent runs inside the board). Bun has no PTY on Windows, so there `cli/conpty.ts` runs a ConPTY host: Windows PowerShell compiles C# with `Add-Type` and talks to the board over pipes. Resize is the in-band `ESC]kzr;c;r BEL`, and the agent runs under an inner `powershell -EncodedCommand` so `.cmd` shims resolve. On Windows, child processes launched through ConPTY receive `defaultChildEnv()` with `AGY_CLI_DISABLE_AUTO_UPDATE=1`, `CLAUDE_CODE_DISABLE_AUTO_UPDATER=1`, and `DISABLE_AUTO_UPDATER=1`: on Windows 11 with Windows Terminal registered as the system-wide default console handler, background update processes spawned by CLI tools (such as agy's background updater or Claude Code's updater) detached or launched without `CREATE_NO_WINDOW` trigger an unwanted visible Windows Terminal popup window that immediately flashes and closes. When that agent ends, the footer offers Resume: `/resume` continues an in-flight run with a prompt, and on a waiting or done run reopens its conversation with nothing sent (refused when none is on disk). `launchRun` drops inherited Claude Code session variables (`CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, …): a board started inside a Claude session would otherwise launch child agents that save no transcript, leaving nothing to resume (#14). While the agent sits on a question (`asking()` in `cli/pty.ts`: Claude Code / Codex prompt text, read after 700 ms of quiet, only output since the last keystroke, and not when an agent's working line (`WORK`: Claude Code `(Ns ·`, Codex `•`/`esc to interrupt`, Gemini `(esc to cancel, N`, opencode `esc interrupt`; never a bare "Esc to cancel", Claude's question footer) follows the last question — a redraw used to keep it amber for a minute) `/state` carries `pty.asking` and the card shows an amber `i-ask` mark. A decision on a run started in Yolo keeps Yolo (`launchRun`). A conversation that opens another run (a follow-up) hands its session to that run: `ownerOf()` (`cli/state.ts`) gives a launch to the newest run that recorded its conversation id after it started, ahead of the run it was launched for, unless that run is still in flight, so the new card gets the terminal and Resume; the parent can still resume that conversation (`firstSession`). xterm.js has no touch scrolling, so `web/term.ts` turns a swipe into `scrollLines`, or into SGR wheel reports when the agent tracks the mouse (a full-screen Claude Code does). It renders with `@xterm/addon-webgl` (the DOM renderer lagged on constant redraws; context loss falls back to DOM), and resizes are debounced 100 ms since each makes the agent redraw. Copy: Ctrl/Cmd+Shift+C, or Ctrl+C while text is selected (nothing selected, Ctrl+C stays the interrupt), and the selection is `--dim` at 35% so it shows in the dark theme; the desktop app adds a right-click Copy/Paste menu (`context-menu` in `desktop/src/main.ts`), which Electron lacks. `@xterm/addon-unicode11` sets Unicode 11 widths, so emoji and CJK take two cells as agents and tmux count them. `@xterm/addon-web-links` makes URLs clickable (new tab) and `@xterm/addon-search` backs a `.termtools` strip top-right of every terminal: ⌕ opens a search box (Enter/Shift+Enter, Esc; Ctrl/Cmd+Shift+F from the terminal), plus Paste when there is no phone key bar. On a phone (`pointer: coarse`) the terminal gets a swipeable chip row (1 2 3 Esc ^C arrows ↵ ⇧⇥ Ctrl Alt ⋯; keys fire on click, not pointerdown, so a swipe of the row presses nothing; Ctrl opens an a–z pad, ⋯ holds Search, Paste, Raw keyboard) and a message box whose Send types the text and presses Enter 60 ms later, so a TUI does not take it as a paste. The run panel header shows a Plan → Build → Review → Done step bar (`steps()` in `web/board/panel.ts`; abandoned runs and tasks keep chips); with the terminal open the panel is 62% wide above 900px, full width on phones. `/file` serves a card's `attachments/` only; in Preview and notes, `attach()` (`web/board/markdown.ts`) rewrites those links and shows any other relative link as its path, since it would open the board's "not found". A plain left click on a `/file` or `/ice-image` link opens it in a `<dialog>` over the board (`web/board/viewer.ts`: `<img>` for images, else an `<iframe>`), with Open in new tab beside Close; a modifier or middle click keeps the browser's tab.
- Images into a terminal: `mountTerm` catches a `paste` (capture phase, before xterm's text-only handler) or `drop` holding image files, POSTs each to `/term-image` (`cli/term-image.ts`: type from the magic bytes, random name, 10 MB cap, `~/.kaizen/term-images/`) and types the saved paths (`web/term-paste.ts` `pathsText`, quoted when they contain a space). A text paste is left to xterm; a refused image or a non-image drop shows a short note in the corner. Phones keep ⋯ Paste / Pick image on the same upload (run `2026-11-13-term-image-paste`).

- Terminal output to a page goes through `frames` in `cli/pty.ts`: the first chunk after quiet is sent at once (typing echo is not delayed), a burst within 16 ms goes as one message. Measured before this: 3 busy agents were 85 messages/s and 1.7% of the page's main thread, so it trims wake-ups, it was not a bottleneck. A hidden terminal is deliberately NOT paused: an agent started in a hidden tab would get no answer to its startup queries (cursor, colour) until shown.

- Terminal theme: `web/term.ts` recolours xterm on the toggle and sends `CSI ?997;1n` (dark) or `?997;2n` (light) only to a program that enabled mode 2031, and answers its `?996n`. An agent follows only if its own theme is auto (Claude: `/theme`).

- Terminal font size (run 2026-11-01-terminal-font-size): one size per browser in `kz-term-font`, 8 to 24px, default 12 (`web/term-font.ts`). In `web/term.ts` the one custom key handler takes Ctrl/Cmd+= (bigger), Ctrl/Cmd+- with or without Shift (smaller) and Ctrl/Cmd+0 (reset); Settings → Terminal → Terminal font size shares the store. `fontSet` raises `kz-term-font`, every mounted terminal sets `options.fontSize` and calls `size()`, so the agent gets the new grid.

- Resource monitor (run 2026-11-01-resource-monitor, after Orca's Resource Manager): `#res`, left of the terminal count, shows kaizen's memory; `web/board/resources.ts` opens `#respop` with Memory (headline, a graph of the last 60 samples kept in the page, split bar), Storage (headline, split bar of the top 4 plus Other, its list folded by default, `kz-res-disk`) and Terminals by project and workspace, the last two in `#resr` so a memory tick does not drop button focus, polling 15 s closed, 3 s open. `GET /resources` (`cli/resources.ts`): system memory from MemAvailable, `ps` trees per terminal, deduplicated for the total, a tmux-kept agent measured from `panePid`; Windows has no `ps`, so it reports the board's own memory and a dash per terminal. Resident sizes count shared pages more than once, so totals run a little high. `GET /resources/storage` never waits: `storage()` scans `~/.kaizen`, the install and each project's `.kaizen` in the background, 5-minute cache, `?refresh=1`; `lstat`, no symlinks, one row per real folder, nested roots left to their own row. `POST /pty/kill` (`strict()`, live key only) calls `killPty`: SIGKILL of the group plus `killTmux`, no `/exit`. Kill asks in its row. Not done: Kill all, CPU.

- `POST /shell` `{dir, agent?, ws?}` (`ws` must equal a path of `workspaces(projectOf(dir))`, else 400; it becomes the PTY cwd): a login shell (or a bare `KNOWN_AGENTS` cmd that is on PATH, never a page string) in a PTY keyed `sh-<random>` in the project folder; exact board Origin (or none) plus an opted-in web host, `content-type: application/json` (else 415), registered non-global dir only, at most 8 live terminals per project (429), 501 without PTY support. Each shell record carries `ws` (its cwd) and `run` (the card key, or the workspace key `ws:<dir>:<path>`); an empty workspace opens the default agent (see the Workspace centre bullet); runs started outside the board (a Claude Code session in the user's terminal) have no board pty, so no Agent tab. An agent typed into a board shell shows in the sidebar agents while it runs (`shellAgent()` walks the shell's child processes, Linux only); its tab stays the shell. Terminals drop an inherited `NO_COLOR` (`colorEnv()` in `cli/pty.ts`). `GET /shells?dir=` lists live ones. The socket is the ordinary `/pty` (exact-origin check) and × is `/pty/exit`. Trust: an allowed tailnet host (web-hosts) can open a shell here, as it can already drive agents. The run workspace calls it; shells show as tiles on the Terminal page too (`store.shells`, fed by the footer's `/shells` read, `kz-shells` event; no Open card button on them).

- Terminal page (`?view=terminal`, `web/board/terms.ts`, opened from the footer's terminal count; no side-menu item): every card with an in-card session (`pty` from `/state`), Tasks to Done, as tiles headed `<run name> - <project name>`. A layout switch (Grid √n with the last tile spanning its row, Side by side, Stacked); drag a header onto a tile to swap, drag the borders to resize, maximise / hide / open card per tile. Layout is per browser in `localStorage` `kz-terms`. Each tile is another `kzTerm` mount on `/pty` (`attachPty` takes several listeners); mounts survive `/state` ticks and close when a session goes or the page is left. A phone (≤640px, `matchMedia` made on first show) shows one tile at a time, full height, picked from a row of tabs above it (dot + name, close ×, the first by default, not saved); the tile header, board combos, and desktop window controls are hidden on phone, with a single-row navigation header matching Home and Chat. Stacked tiles made every swipe land on a terminal, so the page could not be scrolled. A tile whose agent is asking gets `.asking`: a pulsing amber border (static ring under reduced motion), and on any board page, while the tab is hidden, a session that starts asking after the first `/state` raises `notifyUser()` tagged `ask:<pty key>` so several tabs show one (`load()` in `web/board/api.ts`). A dropped `/pty` socket (any close but `ended`) shows Reconnect in the tile's top-right strip and retries by itself after 1, 2, 4, 8, 15 s (`connect()` in `web/term.ts`, card panel too); a reopen resets the screen, since the board replays the whole session on attach. The side menu's Terminal entry carries a count of live hidden tiles (`termsBadge()`, `data-n` pill, called from `render()` and `openTerms()`; board.html only). An ended session's tile sorts last, is dimmed and labelled `ended`, offers Resume when it is a run (`resume()`, the page stays put), and its × closes it with no Hidden chip; when the board drops the session after `KEEP_MS` (10 min, `cli/pty.ts`) it calls `onChange`, so the tile leaves at once. A done or abandoned run's ended session is not shown at all (`ptyOf` in `cli/web.ts`), and a done run's live agent is left open: the minute sweep (`sweepSessions`) only drops PID files of ended sessions. Agents end on a board decision (the new window replaces the waiting one), on abandon, or when the user closes them. `writePty` still ignores xterm's focus, mouse and query answers (`REPORT`) when deciding the user typed, for `asking`.

## Watch out
- The board's main thread relays every terminal's bytes, so sync work there stalls typing in all open agents. `GET /state` builds its file-and-git half on a Worker (`cli/state-snap.ts`); keep slow work out of the main thread.

- `/decide` and `/fix` type into the run's live agent tab; a new agent starts only when none is open (run 2026-10-30-board-approve-reaches-chat).

- The run panel's tab names live twice: `TABS` in `web/board.html` (label + doc key, order = button order) and `TABS` in `web/notes-lib.ts` (link names for `[[run:x#tab]]`, `work` meaning the `impl` doc). Change both together.

- A card terminal's tty also receives what the page's xterm sends by itself (focus `ESC[I`/`ESC[O` — Claude Code enables `ESC[?1004h` — mouse reports, query answers). Anything judging "the user typed" for a board-owned session uses `ptyState().typed` (`REPORT` filter in `cli/pty.ts`), never tty atime. (2026-10-24-done-run-terminal-close)

## Phone dock (2026-11-08)

The coarse-pointer controls in `web/term.ts` use a compact composer with an accessory toggle at its far right. Opening it dismisses native input and replaces the quick-key row with a grouped shortcut panel with an inverted-T arrow cluster and a tall Enter key beside it; the panel footer has only Keyboard and History icon tabs. Separate groups hold the primary controls, navigation with Paste and Image, symbols, and F1–F12. Ctrl opens the letter pad and Alt stays sticky. The panel keeps the original shortcut set; it has no QWERTY or number rows. History merges the last 100 distinct composer messages (per browser in `kz-term-history`) with up to 500 saved shell commands from the board machine. `POST /pty/history` requires the same-origin JSON guard and a known terminal key; `cli/term-history.ts` reads bounded tails of bash, zsh, fish and PowerShell history files, honoring exported `HISTFILE`, `ZDOTDIR` and XDG paths. The configured shell is preferred; entries are newest first within each file and deduplicated. The panel reloads on opening and filters both sources. Commands still only in a running shell’s memory are unavailable; raw agent input is not recorded. No shell startup files are executed. Selecting a history entry fills the composer without sending. Focusing the composer closes the accessory panel. Styling and safe-area spacing live in `web/board.html`.

## Phone navigation (2026-11-08)

The phone Terminal menu opens the terminal page across every project, independent of the project picker. `badge.ts` exposes the shared all-project cards and dispatches `kz-all-cards`; `terms.ts` uses that snapshot, including each `pty.all` session, plus the existing global shell list. Existing mounts survive refreshes.

## Agent launch and phone keyboard (2026-11-08)

The composer now has an icon-only Raw keyboard button where Send was; the phone Enter key submits composer text. Raw input focuses xterm directly. `web/board/terminal-viewport.ts` fits the phone app to `visualViewport.height` while the terminal or composer is focused and the keyboard reduces the visible area; it ignores pinch zoom and cleans up listeners when the last terminal unmounts. Actual iOS keyboard behavior still needs device verification.

## Persistent Tasks (2026-11-08)

The task queue dispatches into a live run terminal only after a structured acknowledged safe boundary. Busy/quiet flags never authorize a new task writer. Stop kills the supported board process and reports stopping until termination is observed; unsupported external sessions require technical reconciliation. Session records retain task identity.

## Windows ConPTY & native launch parity (2026-11-11)

`KzPty.Run` in `cli/conpty.ts` passes `STARTF_USESTDHANDLES | STARTF_USESHOWWINDOW` (`0x101`) with `SW_HIDE` (`0`), suppresses PowerShell progress records, and `innerCommand` (along with `findTerminal` in `cli/state.ts`) escapes embedded double quotes for non-`.ps1` targets so PowerShell 5.1 does not strip quotes from native executable arguments. `startPty` in `cli/pty.ts` strips `#< CLIXML ... </Objs>` blocks from `stderr`, terminates the full Windows process tree via `taskkill.exe /T /F /PID` on exit/kill, receives task/run environment variables via `opts.env` on Windows, and `adoptLoginEnv` reads `HKLM` and `HKCU` `Path` entries from the Windows Registry plus standard Windows agent (`%LOCALAPPDATA%\agy\bin`, `%USERPROFILE%\.local\bin`, `%APPDATA%\npm`) and Git paths when missing from `PATH`.

## Orca-style resize, palette and tabs (2026-11-13-orca-terminal)
`web/term.ts` resizes the way Orca does: nothing refits while a divider or the window moves (the pane clips, its background is the terminal's own), and one fit plus one `{t:"r"}` goes out 150 ms after the size settles, on the next frame; a pane that just appeared (width 0 before) fits at once. `fitTerm` replaces FitAddon's fit: the cell is `dimensions.device.cell / devicePixelRatio` (stable column count on scaled screens) and the container's own padding is subtracted (box-sizing is border-box, so its computed width includes it). Measured on a scratch board: a 2 s window drag sent 36 resizes before, 0–1 after. Colours are Orca's defaults, `ORCA_DARK` (Ghostty Default Style Dark) and `ORCA_LIGHT` (Builtin Tango Light), picked by the board's light/dark; `theme()` sets `--term-bg` on `<html>`, which `.term`, `.rpane:has(>.term)`, `.rstage` and `.hwsb` use. Font weight 500/700, line height 1, block cursor. Workspace tabs (`#rtabs .rtab`, desktop only) are flat with an `--ink-hi` underline on the active tab and × at the end. A pause longer than 150 ms in the middle of a drag sends a resize then, as Orca's does.

## Theme queries (2026-11-13-home-tilde-light-term)
`web/term.ts` answers `CSI ?996n` ("dark or light?") with `?997;1|2n` whether or not the program subscribed with 2031, and OSC 10/11 `?` with the Orca palette's foreground/background as `rgb:RRRR/GGGG/BBBB` (xterm.js answers neither by itself). Claude Code on theme `auto` reads these, so it draws light on the light terminal. Output arriving in the first 150 ms after the socket opens is the attach replay (`replaying`): its old queries are not answered again, or the reply would be typed into whatever runs now.

- The resource monitor panel is laid out like macOS Control Center (run 2026-11-13-resource-monitor-control-center, approved kaizen-concept prototype in `.preview/resource-monitor/`): Memory and Storage tiles open in place (`kz-res-mem`, `kz-res-disk`), Storage has icon buttons (Clean up, Rescan), terminals are sorted heaviest first and scroll after about 5 rows.
