# Run workspace

Part of [[Web board]].

## In plain words
The page a run opens into: its plan, review and backlog tabs, the browser and preview of the app being built, notes you can pin on that preview, split panes, and how agents pick up again after the board restarts.

## What it does
- **Annotator (Browser tab, run `2026-11-04-native-annotator`).** The Annotate button reloads the frame through `cli/annotate-proxy.ts`: one `Bun.serve` per target origin on its own `127.0.0.1` port (never the board's, so the framed app's scripts cannot reach board APIs), loopback targets only, Host checked against rebinding, redirects off the target refused, `x-frame-options` and CSP dropped, WebSockets relayed for hot reload, and `<script src="/__kz/annotate.js?t=<token>">` added to HTML. `web/annotate.js` (plain JS, served as text, no build) is the picker, note box, markers, pause and crop; it speaks to the board only by `postMessage`, and `web/board/annotate-lib.ts` `accept()` takes a message only from the frame window, the proxy origin and the token `POST /annotate/open` returned. The board side (`web/board/annotate.ts`) keeps the notes (`kz-ann:<workspace>` without crops), the toolbar, the list and the settings (`kz-annotate`). Routes (all `strict()`): `/annotate/open`, `/annotate/format` (markdown for Copy), `/annotate/send` (needs a live agent, else 409 and nothing saved; crops are saved under `runs/<id>/attachments/annotations/` with names the server makes; the text goes through `submitPty` as one fenced, flattened paragraph — `cli/annotate.ts`). Agentation is not used, bundled or loaded; its strip was removed. Not built: layout mode, MCP/webhook delivery. Static dev servers give no source file.

- **Restart resume.** `saveLive` (`cli/web.ts`) also writes the + menu's terminals and agents (`shells`, argv in `shellCmd`, Claude's conversation id via `claudeSid`, Linux `/proc` only) into `resume-after-upgrade.json`; the next board starts them again, Claude with `--resume`. A shell whose run's own resume already brought the agent back (`viaRun`) is skipped. Closing an agent tab hides it per agent (`hb` born in the saved layout in `run-view.ts`): the same key started again shows its tab.

**Preview button (run view).** The eye icon beside + (phone too) opens the workspace's app in the Browser tab: a port from `/devports` (never the board's own port) opens at once; else `POST /shell {dev:true}` runs the folder's `dev`/`start` script from package.json (`devCommand()`, lockfile picks bun/pnpm/yarn/npm, through a login shell, never a command from the page), reuses a live one, sets `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=.ts.net` so Vite accepts the tailnet name, then polls `/devports`. No script: the run's Preview tab and a toast. `/expose` serves whichever loopback answers (Vite listens on `[::1]` only) and returns a `hint` when the dev server still refuses the tailnet host.

**Agent reports.** `kaizen report` (`cli/report.ts`, run `2026-10-31-agent-reporting`) writes `runs/<id>/report.json`, a file so it needs no board or secret; from a worktree it goes to the project's state dir. `signalOf` gives a card `blocked`, `stale` (a live board terminal silent, with no report, for two `agent.heartbeat_minutes`) or `unverified` (the board's terminal ended in a build or review with no hand-back for that stage and fix round, report file or not). A card with no board terminal gets no stale or unverified, since quiet and dead look alike from outside. Agents can't run on a timer: they report at each step. The running phase shows on the Runs board. `KAIZEN_RUN_ID` and `KAIZEN_STAGE` reach an agent resumed on a known run (not on Windows); a new run passes `--run`.

## Where it lives
- Run workspace (`?view=run&dir=&id=` or `&idea=<text>`, `web/board/run-view.ts`, `#runv`, `body.runv`): (centre tabs and `kz-runtabs` keys are now per workspace, see the Workspace centre bullet above; the rest holds) rail rows and Tasks Open land here (`openWorkspace()` pushes the address; `go("run")` calls `showRunView()` in a microtask, after go's own panel close). `#panel` is docked as `.app`'s second grid column with `!important` geometry over the drawer rules; `#ptabs` buttons carry a `t-<tab>` icon and a label (labels on the Board, icons in the strip); `#pnotes` + `#pnlist` list `/vault` notes. In the run view the Preview strip button fires `kz-run-preview` (a centre tab) and `open()` never picks the `term` tab; Edit, Reject and Abandon open over the page as `formPopup()` (`cards.ts`); the workspace is never left, and Abandon is no longer on Board cards. Back to task is also in the panel's More menu. Centre tabs: the card's `pty` (agent), `/shells?dir=` (shells and bare agents), plus `kz-runtabs` per card key (localhost, preview, notes, hidden agent tabs, shown tab, split). Panes are made once per tab and kept hidden, so tab switches and `/state` ticks never reopen `/pty` (checked by counting WebSockets in CDP). Split reuses `layout()` exported from `terms.ts` (shape key `run:cols|rows`). The localhost URL is `kz-browse:<dir>` (back/forward are the tab's own history; cross-origin frames give none). Note tabs frame `/notebook?…&embed=1` (`body.embed` hides the rail and header). The waiting-on-you count is on the Tasks entry (`badge.ts`). Tasks rows take ↑/↓ and Enter. Open sorts running-first by default. The Keyboard shortcuts button is hidden (`#kbd`). Tasks uses the Board's `#combo` and `#showc` in the header and docks `#bq`, `#newtop` and `#hx` in its toolbar; Open = not-started tasks + runs in flight, sorted ideas-first or running-first (`kz-ideas-sort`). Side-menu project groups fold (`kz-rail-folded`). The side menu's Projects list shows runs only, plus a task with a live agent terminal: `planning · starting` while that agent works (`pty.busy`: its `WORK` line drawn within the last 700 ms, `cli/pty.ts`; a working agent redraws it many times a second), `waiting on you` while it asks, and `agent · open` once it sits quiet with no run (it answered a question); its filter has Active runs and Done. Tasks page: Open = tasks not started, Running = runs in flight, Done = finished. Every page's top bar is 52px with one `--line` divider, except the run view's tab bar `#rtabs`, which is 36px (`--tabbar`). A deep link to a run of a project other than the picked one switches the board to that project once (`showRunView()`, `pick()`); the project pane's Files shows "Pick a project" instead of requesting `/project-tree` with no project. Resume refuses (409) when the board already has a live agent pty for the run. A done run with `accept: "needs"` (see Workflow's final-approval gate) shows `done, not approved` with the amber wait icon in the rail, and its panel footer has a note and Approve (`POST /accept`) in place of Commit & push; `auto` shows `auto-accepted`. Fix all/Fix N (`/fix`, `web/board/fixes.ts`) types the fix prompt into that live agent pty when there is one, busy or not, and answers `reused: true`; only with none does it launch a new agent and close the waiting sessions. Panes move between tabs: drag a tab (it carries its focused pane) or a split pane's header onto a tab, onto + or onto a pane edge, or use its ⋯ Move to menu (`moveItem`). Agent tabs show the agent's mark. Splits are tmux-style: a tab's layout is a tree (`id | {dir, kids, sizes}`); split right/down divides the focused pane; gutters resize. Opening a run shows every board agent terminal it has (`pty.all`); with none, `POST /shell {resume:true}` resumes the Claude session recorded in its `state.json` unless `sessionLive()` sees it running elsewhere (409, an Agent tab says so). When that session runs in a board terminal (a Terminal page shell opened by another run or none), `/shell` adopts it instead: `shellHosts()` (`cli/web.ts`) matches the shell's pid to `~/.claude/sessions/<pid>.json` up the `/proc` parent chain, sets the shell's `run` to this card and returns it, so the run view shows that terminal (Linux; elsewhere the 409 stands). The + menu offers every installed agent from `/agents`. Footer usage: agent mark + 5-hour %, details on hover. The Board drawer sits beside the board (the `.app` makes room). Tasks uses the shared `.hdr` header. Tabs are screens (`kz-runtabs` per card: `screens [{id, panes, dir}]`, `on`): + opens an item in a new tab, split right/down menus add an item to the shown tab (n panes, `layout()`), a tab's × closes all its items, a pane's × one. The Board drawer stops above the footer (`--foot-h`, set by `initFooter`). Each run has its own centre: `/shell` takes the workspace's card key as `run`, a workspace lists only its own shells, and switching runs unmounts the previous run's panes (the shells keep running; the Terminal page tiles them all). On desktop the Board drawer uses the same panel layout (meta + stage bars, icon strip, close kept, no notes book). Preview is only ever a centre tab: the panel turns a `preview` tab into `review` in the run view, and the centre Preview shows the run's screenshots with a URL bar when it names a localhost address, framing the address only when there are no images. Phone: the strip is a bottom sheet toggled by the panel button (`rflip`); its × only hides the sheet. On desktop `rflip` hides the panel by width (0, `transition:width .18s`), so it slides like the rail. A lone pane hides its own header on every width; only split panes show one.

- Split resize (`build()` in `run-view.ts`): a gutter drag writes `sizes` into the live layout node, so `screens()` updates screens in place and `prune()` (`ws-tabs.ts`) returns the same node when it drops nothing; copies made on every redraw used to orphan the drag, and the next tick snapped the panes back. While dragging, `body.rdrag` turns off pointer events on frames, or a Browser/Preview iframe under the pointer swallowed the moves. Tested in `ws-tabs.test.ts`.

- `POST /open-url` `{url}`: the Browser tab's and Preview bar's Open in app window. Same `strict()` guard as `/shell` (exact Origin, JSON), only a loopback http(s) URL (localhost, 127.0.0.1, [::1]; anything else is 400), then `openApp(url, ~/.kaizen/app-window)`: a Chromium-family `--app=` window with its own profile on the board's computer, `openDefault` fallback. The button shows only when the page itself is on loopback and so is the URL. `GET /frameable?url=` (`local()`, loopback http(s) only via the shared `isLoopback`, 4 s) answers whether X-Frame-Options / CSP frame-ancestors allow framing; the Browser tab then shows the card "This page refuses to be shown inside the board" with Open in new tab and Open in app window. Browser tab (was localhost; `browser()` in `run-view.ts`): address kept per workspace in `kz-browse:<ws key>`, Back/Forward/Reload and a New tab link. It opens by itself: `autoBrowse()` on each `kz-state` compares the workspace's runs with the last tick (`was`, `toOpen()` in `ws-tabs.ts`); a run that moves into review (column 3) or done and whose `## Preview` holds a localhost address (`loopbackUrl()`) sets the address, adds and shows the Browser tab (its iframe is sandboxed without allow-top-navigation), once per run id (`seen` in the workspace's `kz-runtabs` entry). Runs already in review when the workspace is first drawn do not open it. Only `## Preview` signals it; there is no `kaizen preview` command and no proxy. Preview screenshots render as a captioned grid.

## Watch out
- `tendHandoff` in `cli/web.ts` opens the second agent of a handed-off run, watches it, and wakes the first when idle with no draft; `handoff.json` moves only through `move()`.

- On a building run the Backlog tab draws progress.md (`showProgress` in web/board.html) above the backlog, so anything that finds backlog rows by DOM order or text in `#pbody` must skip `.prog`.

- The board's plan-approval answer form is driven by `planQuestions()` in `web/board.html`, which reads the Open questions shape pinned in `spec-plan.md` item 9 (`Q:` line, `- label (recommended) — why` options). Changing that shape in the spec, or the heading name, silently drops the board back to a plain Approve that sends no answers.
