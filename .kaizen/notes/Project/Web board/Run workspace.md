# Run workspace

Part of [[Web board]].

## In plain words
The page a run opens into: its plan, review and backlog tabs, the browser and preview of the app being built, notes you can pin on that preview, split panes, and how agents pick up again after the board restarts.

## What it does
- **Annotator (Browser tab, run `2026-11-04-native-annotator`).** The Annotate button reloads the frame through `cli/annotate-proxy.ts`: one `Bun.serve` per target origin on its own `127.0.0.1` port (never the board's, so the framed app's scripts cannot reach board APIs), loopback targets only, Host checked against rebinding, redirects off the target refused, `x-frame-options` and CSP dropped, WebSockets relayed for hot reload, and `<script src="/__kz/annotate.js?t=<token>">` added to HTML. `web/annotate/annotate.ts` (TypeScript, bundled by `bun run build:web` into `web/dist/annotate.js`, one wrapped script; the server serves it at `/annotate.js` and the proxy at `/__kz/annotate.js`) is the picker, note box, markers, pause and crop; it speaks to the board only by `postMessage`, and `accept()` in `web/lib/annotate/rules.ts` takes a message only from the frame window, the proxy origin and the token `POST /annotate/open` returned. The board side is React (roadmap 2 phase 7): `lib/annotate/session.ts` is a Zustand store per Browser tab (notes, settings, picking/pause/hide, the proxy and its token, the window's key and message listeners, Copy and Send), `components/annotate` draws the toolbar, the notes list and the settings box (`AnnotatePanel`, mounted by `BrowserPane` inside `.annrow`); notes are kept in `kz-ann:<workspace>` without crops and the settings in `kz-annotate`, both as before. The page-side rules that need no page (selection geometry, where the note box opens, what a note holds, the plan for the picture) are `lib/annotate/page.ts`, tested, and imported by the script. Routes (all `strict()`): `/annotate/open`, `/annotate/format` (markdown for Copy), `/annotate/send` (needs a live agent, else 409 and nothing saved; crops are saved under `runs/<id>/attachments/annotations/` with names the server makes; the text goes through `submitPty` as one fenced, flattened paragraph — `cli/annotate.ts`). Agentation is not used, bundled or loaded; its strip was removed. Look (2026-11-12): the toolbar is one dark icon pill floating bottom-right over the page (`AnnotateBar`, Tailwind classes; `.annbar` is gone from `board.html`): four modes (a click on the active mode turns picking off), pause, markers, copy, send, clear, notes list (with a count badge), settings, close. The notes list is an overlay panel (`NotesList`, opens from the pill, the pill steps left while it is open), no longer a permanent column; a comment is edited in place (a textarea, saved when you leave it), and the settings box uses the kit's Select and Checkbox. Close is the same as turning Annotate off: the url bar's Annotate button stays and brings it back, notes kept (it used to hide that button until the board reloaded). The in-page composer (`web/annotate/annotate.ts`) is dark with the element's quoted text as its header, intent and severity as small pills, Cancel and an amber Add. Not built: layout mode, MCP/webhook delivery. Static dev servers give no source file.

- **Restart resume.** `saveLive` (`cli/web.ts`) also writes the + menu's terminals and agents (`shells`, argv in `shellCmd`, Claude's conversation id via `claudeSid`, Linux `/proc` only) into `resume-after-upgrade.json`; the next board starts them again, Claude with `--resume`. A shell whose run's own resume already brought the agent back (`viaRun`) is skipped. Closing an agent tab hides it per agent (`hb` born in the saved layout in `run-view.ts`): the same key started again shows its tab.

**Run app button (run view).** The play icon beside + (phone too; named Preview with an eye icon before 2026-11-09-board-ui-consistency, which looked like the + menu's Preview item, the run's Preview tab) opens the workspace's app in the Browser tab: a port from `/devports` (never the board's own port) opens at once; else `POST /shell {dev:true}` runs the folder's `dev`/`start` script from package.json (`devCommand()`, lockfile picks bun/pnpm/yarn/npm, through a login shell, never a command from the page), reuses a live one, sets `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=.ts.net` so Vite accepts the tailnet name, then polls `/devports`. No script: the run's Preview tab and a toast. `/expose` serves whichever loopback answers (Vite listens on `[::1]` only) and returns a `hint` when the dev server still refuses the tailnet host.

**Agent reports.** `kaizen report` (`cli/report.ts`, run `2026-10-31-agent-reporting`) writes `runs/<id>/report.json`, a file so it needs no board or secret; from a worktree it goes to the project's state dir. `signalOf` gives a card `blocked`, `stale` (a live board terminal silent, with no report, for two `agent.heartbeat_minutes`) or `unverified` (the board's terminal ended in a build or review with no hand-back for that stage and fix round, report file or not). A card with no board terminal gets no stale or unverified, since quiet and dead look alike from outside. Agents can't run on a timer: they report at each step. The running phase shows on the Runs board. `KAIZEN_RUN_ID` and `KAIZEN_STAGE` reach an agent resumed on a known run (not on Windows); a new run passes `--run`.

## Where it lives
- Run workspace (`?view=run&dir=&id=` or `&idea=<text>`, `web/board/run-view.ts`, `#runv`, `body.runv`): (centre tabs and `kz-runtabs` keys are now per workspace, see the Workspace centre bullet above; the rest holds) rail rows and Tasks Open land here (`openWorkspace()` pushes the address; `go("run")` calls `showRunView()` in a microtask, after go's own panel close). `#panel` is docked as `.app`'s second grid column with `!important` geometry over the drawer rules; `#ptabs` buttons carry a `t-<tab>` icon and a label (labels on the Board, icons in the strip); `#pnotes` + `#pnlist` list `/vault` notes. In the run view the Preview strip button fires `kz-run-preview` (a centre tab) and `open()` never picks the `term` tab; Edit, Reject and Abandon open over the page as `formPopup()` (`cards.ts`); the workspace is never left, and Abandon is no longer on Board cards. Back to task is also in the panel's More menu. Centre tabs: the card's `pty` (agent), `/shells?dir=` (shells and bare agents), plus `kz-runtabs` per card key (localhost, preview, notes, hidden agent tabs, shown tab, split). Panes are made once per tab and kept hidden, so tab switches and `/state` ticks never reopen `/pty` (checked by counting WebSockets in CDP). Split reuses `layout()` exported from `terms.ts` (shape key `run:cols|rows`). The localhost URL is `kz-browse:<dir>` (back/forward are the tab's own history; cross-origin frames give none). Note tabs frame `/notebook?…&embed=1` (`body.embed` hides the rail and header). The waiting-on-you count is on the Tasks entry (`badge.ts`). Tasks rows take ↑/↓ and Enter. Open sorts running-first by default. The Keyboard shortcuts button is hidden (`#kbd`). Tasks uses the Board's `#combo` and `#showc` in the header and docks `#bq`, `#newtop` and `#hx` in its toolbar; Open = not-started tasks + runs in flight, sorted ideas-first or running-first (`kz-ideas-sort`). Side-menu project groups fold (`kz-rail-folded`). The side menu's Projects list shows runs only, plus a task with a live agent terminal: `planning · starting` while that agent works (`pty.busy`: its `WORK` line drawn within the last 700 ms, `cli/pty.ts`; a working agent redraws it many times a second), `waiting on you` while it asks, and `agent · open` once it sits quiet with no run (it answered a question); its filter has Active runs and Done. Tasks page: Open = tasks not started, Running = runs in flight, Done = finished. Every page's top bar is 52px with one `--line` divider; on a computer the run view's bar `#rbar` is 52px too (the tabs inside stay 36px, `--tabbar`), so its tabs, the run picker and the panel's icon strip sit on the side menu's top line. A deep link to a run of a project other than the picked one switches the board to that project once (`showRunView()`, `pick()`); the project pane's Files shows "Pick a project" instead of requesting `/project-tree` with no project. Resume refuses (409) when the board already has a live agent pty for the run. A done run with `accept: "needs"` (see Workflow's final-approval gate) shows `done, not approved` with the amber wait icon in the rail, and its panel footer has a note and Approve (`POST /accept`) in place of Commit & push; `auto` shows `auto-accepted`. Fix all/Fix N (`/fix`, `web/board/fixes.ts`) types the fix prompt into that live agent pty when there is one, busy or not, and answers `reused: true`; only with none does it launch a new agent and close the waiting sessions. Panes move between tabs: drag a tab (it carries its focused pane) or a split pane's header onto a tab, onto + or onto a pane edge, or use its ⋯ Move to menu (`moveItem`). Agent tabs show the agent's mark. Splits are tmux-style: a tab's layout is a tree (`id | {dir, kids, sizes}`); split right/down divides the focused pane; gutters resize. Opening a run shows every board agent terminal it has (`pty.all`); with none, `POST /shell {resume:true}` resumes the Claude session recorded in its `state.json` unless `sessionLive()` sees it running elsewhere (409, an Agent tab says so). When that session runs in a board terminal (a Terminal page shell opened by another run or none), `/shell` adopts it instead: `shellHosts()` (`cli/web.ts`) matches the shell's pid to `~/.claude/sessions/<pid>.json` up the `/proc` parent chain, sets the shell's `run` to this card and returns it, so the run view shows that terminal (Linux; elsewhere the 409 stands). The + menu offers every installed agent from `/agents`. Footer usage: agent mark + 5-hour %, details on hover. The Board drawer sits beside the board (the `.app` makes room). Tasks uses the shared `.hdr` header. Tabs are screens (`kz-runtabs` per card: `screens [{id, panes, dir}]`, `on`): + opens an item in a new tab, split right/down menus add an item to the shown tab (n panes, `layout()`), a tab's × closes all its items, a pane's × one. The Board drawer stops above the footer (`--foot-h`, set by `initFooter`). Each run has its own centre: `/shell` takes the workspace's card key as `run`, a workspace lists only its own shells, and switching runs unmounts the previous run's panes (the shells keep running; the Terminal page tiles them all). On desktop the Board drawer uses the same panel layout (meta + stage bars, icon strip, close kept, no notes book). Preview is only ever a centre tab: the panel turns a `preview` tab into `review` in the run view, and the centre Preview shows the run's screenshots with a URL bar when it names a localhost address, framing the address only when there are no images. Phone: the strip is a bottom sheet toggled by the panel button (`rflip`); its × only hides the sheet. On desktop `rflip` hides the panel by width (0, `transition:width .18s`), so it slides like the rail. A lone pane hides its own header on every width; only split panes show one.

- Split resize (roadmap 2 phase 3): a pane is placed by its rectangle (`rects()` in `web/lib/run/layout.ts`, fractions of `#rpanes`) and never moved in the DOM, so a gutter drag is `resizeAt()` on the layout store (`layout-store.ts`, no save until the pointer is up) and a split, drop or redraw reparents nothing: a frame is no longer reloaded by a split. The old copy-the-node trouble (a drag writing into a node a redraw replaced) cannot happen: every tree function returns a new value and the store compares by identity. `PaneGutter` listens for pointermove and pointerup on the `window` as well as capturing the pointer, because a driven browser (CDP) does not retarget moves to the captured bar. While dragging, `body.rdrag` turns off pointer events on frames, or a Browser/Preview iframe under the pointer swallowed the moves. Tested in `layout.test.ts`.

- `POST /open-url` `{url}`: the Browser tab's and Preview bar's Open in app window. Same `strict()` guard as `/shell` (exact Origin, JSON), only a loopback http(s) URL (localhost, 127.0.0.1, [::1]; anything else is 400), then `openApp(url, ~/.kaizen/app-window)`: a Chromium-family `--app=` window with its own profile on the board's computer, `openDefault` fallback. The button shows only when the page itself is on loopback and so is the URL. `GET /frameable?url=` (`local()`, loopback http(s) only via the shared `isLoopback`, 4 s) answers whether X-Frame-Options / CSP frame-ancestors allow framing; the Browser tab then shows the card "This page refuses to be shown inside the board" with Open in new tab and Open in app window. Browser tab (was localhost; `BrowserPane` in `web/components/panes/browser-pane.tsx`): address kept per workspace in `kz-browse:<ws key>`, Back/Forward/Reload and a New tab link. It opens by itself: `autoBrowse()` on each `kz-state` compares the workspace's runs with the last tick (`was`, `toOpen()` in `ws-tabs.ts`); a run that moves into review (column 3) or done and whose `## Preview` holds a localhost address (`loopbackUrl()`) sets the address, adds and shows the Browser tab (its iframe is sandboxed without allow-top-navigation), once per run id (`seen` in the workspace's `kz-runtabs` entry). Runs already in review when the workspace is first drawn do not open it. Only `## Preview` signals it; there is no `kaizen preview` command and no proxy. Preview screenshots render as a captioned grid.

- **Browser tab in the desktop app (a `<webview>`).** `BrowserPane` (`browser-pane.tsx`) makes a `<webview>` instead of an iframe when `window.kaizenDesktop.browserPane` is set (`desktop/src/preload.ts`); browsers, and an app older than the flag, keep the sandboxed iframe, which now also carries `allow="display-capture; microphone; camera; …"`. Why: the board sits on `127.0.0.1`, so a framed `localhost:8000` is cross-site and its `SameSite=Lax` session cookie is not sent on a framed POST (a Laravel login answered 419; checked in Chromium). The webview lives in `persist:kaizen-browser` (`desktop/src/browser-pane.ts`: `paneAttach` forces the partition and our preload and drops node integration, a `src` that is not http(s) is refused, `paneAllows` gives media, display-capture and clipboard-read only to loopback pages; `main.ts` wires `will-attach-webview`, the session's permission and display-media handlers, and guest navigation and popup limits). `frameCheck` is skipped (a top-level page is never refused framing) and `did-navigate` keeps the address bar in step unless the annotator's proxy is reporting it. The annotator keeps working: `web/annotate/annotate.ts` runs when `window.parent !== window` or the preload's `__kzHost` is set, marks what it says with `out: 1`, and `desktop/src/pane-preload.ts` relays it to the board over `ipc-message` (`kz-ann`, accepted by `acceptHost()` on the per-open token) and the board's `webview.send` back as a message to the page. Checked in the real app (headless): login keeps the cookie, relay both ways, no `require` in the page. Not checked: the Browser tab's own UI path in the app, and an actual screen-capture prompt.

- The panel footer `#pfoot` is a React root (`web/components/run/run-footer.tsx` -> `DecisionBar` strip, run 2026-11-14-frontend-rewrite-phase1 phase 3); `openRun()` in `web/board/panel.ts` publishes `{card, plan, sourceControl}` through `react.drawFooter` and the Fix findings form through `react.drawFix` (a slot in the review tab). Nothing may write `#pfoot.innerHTML` any more: it would delete the root. Revise, plan answers and the task reply form are state inside the strip, keyed by run, status and what it awaits.

## Watch out
- `tendHandoff` in `cli/web.ts` opens the second agent of a handed-off run, watches it, and wakes the first when idle with no draft; `handoff.json` moves only through `move()`.

- On a building run the Backlog tab draws progress.md (`components/run/doc-body.tsx`, rules in `lib/run/doc.ts`) above the backlog, so anything that finds backlog rows by DOM order or text in `#pbody` must skip `[data-prog]`. The panel's document tabs (Request, Explore, Plan, Backlog, Work, Review, Preview) are React: `panel.ts` hands `react.drawDoc` the text and the Fix findings form is drawn under a review by `DocBody` (no portal slot); a backlog's `- open|done|rejected:` lines are checkboxes (`parse(src, true)`); a link to a finding or backlog item outlines its line for 2.4 s (`hitNeedle`).

- The board's plan-approval answer form is driven by `planQuestions()` in `web/html/board.html`, which reads the Open questions shape pinned in `spec-plan.md` item 9 (`Q:` line, `- label (recommended) — why` options). Changing that shape in the spec, or the heading name, silently drops the board back to a plain Approve that sends no answers.

## Agent launch and phone keyboard (2026-11-08)

Creating a workspace agent (including split menus) now opens the per-launch Yolo permission switch before starting it. Cancel starts no terminal; if the workspace changes while the dialog is open, the pending launch is discarded.

## Persistent Tasks (2026-11-08)

Persistent task pages link to the existing run workspace through Technical details. Task conversation, versioned results and Looks good belong to the task; terminals, plan/review artifacts and git operations remain in the run workspace. Structured Task events supplement existing report.json; terminal text and quiet/busy flags do not acknowledge task delivery or safe write boundaries.

## When Browser and Preview open by themselves (2026-11-13-preview-own-workspace)
`kaizen preview` writes one `<state>/preview.json` shared by the project and its worktrees. `pollPreview` in `run-view.ts` opens a tab for it only when `previewIn` (`ws-tabs.ts`) says it was written from this workspace or a folder inside it, never from a `.kaizen/wt/` worktree under it (main and its worktrees used to catch each other's previews). It opens only while you watch: every visit's first poll only records the newest (`previewOpens`, `previewAt` cleared when a visit starts), so a click, a workspace switch or a reload never opens a tab or reopens one you closed. A preview written while you were elsewhere stays reachable through + → Preview. A run's own `## Preview` address (`autoBrowse`) is unchanged: once per run, exact workspace.

- Run app button (▷) sits at the right end of the workspace tab bar, after the spacer, before the split buttons (run 2026-11-13-run-app-right). The floating Home window tabs (`.hwstab`) use the same flat, underlined style as `#rtabs .rtab`.

- Auto-open on review/done (`autoBrowse`) needs a localhost address in the run's `## Preview` (run 2026-11-13-browser-wrong-port); with none, nothing opens. `/devports` (`devPorts` in `cli/web.ts`) skips processes named like a known agent (`KNOWN_AGENTS` + `cursor-agent`): Claude Code listens on a local port of its own, which the fallback once opened ("not found").

- Annotate on public sites (run 2026-11-13-annotate-public-sites): in the desktop app (webview) a non-localhost page with Annotate on is loaded directly; on each `dom-ready` the board runs `window.__kzAnnToken=<per-open token>; <annotate.js>` in it (`injectNow` in `web/lib/annotate/session.ts`, script from `GET /annotate.js`), and `px.origin`/`target` follow the page's origin. `web/annotate/annotate.ts` takes the token from `__kzAnnToken` before its script URL. Localhost still goes through the proxy; a browser board (iframe) cannot annotate public sites.

- Saved annotations keep their marked box outlined (`.b.mk` in `web/annotate/annotate.ts`, dashed; solid while the number is hovered), not only their number (run 2026-11-13-annotate-area-outline).

## Run view chrome and panes are React (2026-11-14, frontend rewrite phase 3 chunk C, then roadmap 2 phase 3)
- **What is React:** the tab bar with its drag targets (`run-tabs.tsx`), the + / split right / split down menus with the Bypass switch (`run-add-menu.tsx`, one open at a time, `menu` in `web/lib/run/run-view-store.ts`, which Ctrl+Space c / r / d also sets), the empty-workspace note, the Ctrl+Space key hint, the Project notes list, the panel's run picker, header strip and tab strip, the Board header's Workspaces | Runs switch, and (roadmap 2 phase 3) the centre itself: `run-panes.tsx` draws every open item as a `Pane` (`pane.tsx`: header with title, move menu and close, drag handle and edge drop, focus ring) keyed by workspace and item, in the order they first appeared, laid out by rectangle with `PaneGutter`s between them. A pane body is `TerminalPane` (`terminal-pane.tsx`: owns one div React never draws into, mounts xterm once through `termLoad()` from `lib/run/term-loader.ts`, unmounts it only when the pane goes; xterm's own ResizeObserver refits it), `BrowserPane` (address bar, Back/Forward/Reload, New tab link, the "refuses to be framed" card, the Annotate button and the `AnnotatePanel`; history in `lib/run/browser.ts`), the History, wait and empty components, a note's `/notebook?…&embed=1` frame, or the Preview.
- **State:** the layout tree, screens, hidden tabs, extra tabs and the pane focus are `web/lib/run/layout.ts` (pure: `splitAt`, `prune`, `reconcile`, `moveItem`, `rects`, `resize`, `edgeOf`, `nearestPane`) and `layout-store.ts` (Zustand, saved to `kz-runtabs` exactly as before, same shape). `run-view.ts` asks the store (`placeItems`, `selectScreen`, `moveInLayout`, `patch`) instead of keeping `ALL`/`saved()`; an address for the Browser is a request in the store (`requestBrowse(k, url)`; the open tab takes it and goes there) and a new screenshot for the Preview is `refreshPreview()`. The panel's width grip is `panel-grip.tsx` (`lib/run/grip.ts` clamps it).
- **What stays old, on purpose:** `run-view.ts` (788 lines, was 1,191) is plumbing: which items a workspace has (`tabs()` from the board's cards, `/shells`, `/agents`), starting and ending sessions, opening and closing tabs, the Ctrl+Space keys (`paneKey`, `initPaneKeys`, they read `rects()` for the arrows), `autoBrowse` and `pollPreview`, the phone sheet's swipe, the panel picker. The **Preview** tab is `components/panes/preview-pane.tsx` over `lib/run/preview.ts` (what to show: a frame, a screenshot, or the report with its screenshots lifted into a grid; the board runs on a loopback host for a framed page and the app-window button); `lib/run/preview.ts` also holds `loopbackUrl`, `previewIn`, `previewOpens` and `fetchPreview` (`ws-tabs.ts` re-exports them). The three pane contents (`TerminalPane`, `BrowserPane`, `PreviewPane`) are `components/panes`; the Terminal page is `components/terminal`.
- The side menu's list and menus are React since roadmap 2 phase 2 (see Workspaces).
- Watch out: with many tabs the bar scrolls (tabs are at least 140 px) and Run app and the split buttons scroll out of sight, as before. A selector that builds a new array (`screens.filter(...)` inside `useRunView`) loops forever; filter after selecting.
- Watch out: the pane section, its header and the terminal div are inside a `kz-ui` root, where the kit's scoped preflight zeroes padding, margin and borders and beats the `@layer legacy` CSS. The section and header are Tailwind (they carry `rpane` and `ph` only as hooks for the phone-menu `:has()` rules); the terminal div, the Browser's `urlbar`, `annrow` and `rnote`, and the Preview host carry `kz-keep` so the board's own classes inside them (`.termtools`, `.annbar`, `.rprev`) keep working. A `hidden` attribute does not hide a Tailwind `flex` element: the pane also takes the `hidden` class.
- A marker on the page is clickable (it flashes its row in the list): `paint()` replaces every marker, and a hover used to replace the one under the pointer between press and release, so the click never landed; hovering the marker it is already on, or the 700 ms repaint while one is hovered, no longer repaints (roadmap 2 phase 7).
