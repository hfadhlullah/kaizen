# Layout and look

Part of [[Web board]].

## In plain words
How the board looks and is laid out: the side menu, the sizes and colours, light and dark, and how it folds into a bottom tab bar on a phone. Monochrome is the default; blue is a choice in Settings.

## What it does
- Board is reached by a toggle in the Projects header (`.pbd`, left of the filter): a second click goes back (`boardBack` in `web/board/views.ts`). Keep it equal on board, notes and video pages.

The visible menu is Search, Home, Icebox, Tasks and Board, then the Projects list, with Settings, Report an issue, Keyboard shortcuts and a single sun/moon theme toggle on one bottom row; Video remains at `/video` without a menu entry. Sizes follow Orca's scale through tokens on `:root` (same line in board/notes/video.html): `--row` 28px (rail items, Projects rows, run tabs), `--row-h` 32px (project group header), `--ico`/`--ico-s` 14/12px, `--btn-xs`/`--btn-s`/`--btn` 24/32/36px (`.theme button`, `.psec button`/`.rib`, `.rbtn` 24; `.ib`, `.btn` min-height 32), `--tabbar` 36px, `--pane-h` 24px (split pane header), `--fs-xs/-s/-l` 11/12/14px with `--fs` 13px, `--gap` 6px, `--padx` 8px; the rail is 280px; phone sizes are untouched. Radii were deliberately not taken from Orca. On wide screens only the centre panel is rounded (12px; everything else 4px) and the side menu and footer sit flat on the outer canvas with no borders. The other session's right project pane (`#context`, Files/Notes/Terminal) is hidden on desktop by one rule in `board.html` (`@media(min-width:641px){#context,#ctx-open{display:none!important}}`) and an override restores the Board's five columns over its three-column rule; its markup and `context.ts` are untouched, so reconcile both when that work lands. Selecting a task on the Board opens the detail drawer; a run card opens its workspace (`open()` in `panel.ts`, every entry point), except an archived run, which keeps the drawer for Restore. The drawer never shows the agent terminal (`#pterm` hidden, `panel.ts`), only the run view's centre tab does. On phones (max-width 640px) the bottom tab bar is Home, Chat, Runs and Settings only: the Board, Tasks and the Icebox are set up on a computer, and `go()` sends a phone asking for them to Home; a card opened on a phone opens its run workspace. Phone Home (`web/board/phone.ts`, `#phome`) lists Devices (this computer with project/active/waiting counts, then the other Tailscale computers from `/phone`'s `self`/`computers`, a tap opening `https://<tailnet name>/`), the 12 most recent runs and usage; Runs (`?view=device`) groups this computer's runs Waiting on you / Active / Done. Chat is `?view=chat` (desktop folds it into Home). The usage footer and the side-panel button are hidden on phones; the header is one row, title and one action. The rail's phone CSS sits inside the shared side-menu block, so notes.html and video.html carry it too. The top-left wordmark is smaller, and the new-idea planning details field is taller and labelled.

**Narrow settings.** Below a 520px card (`.scard` is a size container) every row stacks like the phone layout; the nav column and page padding scale with the window.

**Colour.** Monochrome is the default on board, notes and video: surfaces, ink, accent and `--run` are grey, while `--ok`, `--warn`, `--danger` keep their hue because they carry meaning. Settings → Appearance → Color picks Monochrome or Blue (the navy palette, `data-color=blue` on `<html>`, `:root[data-color=blue]` token rules), per browser in `kz-color` through `window.setColor` in the shared side-menu script; light/dark stays a separate choice (`kz-theme`). `--on-accent` is themed since the dark monochrome accent is near white. `web/popup.html` has its own grey tokens and no switch; Kaizen Bot and the terminal board are unchanged.

## Where it lives
- `web/board.html` — the page: markup, CSS, the side-menu script, and the notifier marker.

- Side menu (identical markup and CSS in `board.html`, `notes.html`, `video.html`; `cli/notes.test.ts` holds them equal): Home, Icebox (inbox-tray icon, `#rail-srcs` source icons and `#ice-n` count of `new` items), Tasks, Board, then the Projects list (`#plist`) and Settings + Report an issue + Keyboard shortcuts (`#kbd`, hidden on notes/video) at the bottom. The rail's own icons are `r-*` symbols inside the `<nav>`. `web/board/workspace.ts` draws it on all three pages: `onBoardCards()` in `badge.ts` hands it the cards of the badge's `/state?all=1` fetch (or the board's own all-projects cards), so no extra `/state`; `/sources` is fetched at most every 30 s. Rows: tasks plus unarchived runs, done/abandoned only for 24 h after `moved`; state icon `.si` (`stateOf`: idle/plan/build/review/wait/done/stalled/aband) and `subline()` (stage word plus awaiting label or age; no step or round counts, the data has none). Rows sort by state (waiting, planning, building, reviewing, stalled, task, done; newest first) and projects by their most urgent card; each row is one 28px line: title, then the subline in small mono at the right. The filter button opens a popover (All projects + a checkbox per project with search past 6, Active runs / Tasks / Done toggles; a dot while filtered; saved per browser). Every + New task (rail, Tasks, workspace) opens the form over the current page and stays there; the modal shows the project picker unless one project is pinned, preset to the page's project, and refuses Add until one is chosen. A row is the board's deep link (`?dir=&run=`/`&idea=`); on the board the `kz-open-card` event opens the card in place instead (a row of a project other than the picked one first switches the board to it with `pick()` from `projects.ts`, since `/state` holds only the picked project's cards), `kz-new-idea` likewise for +.

- Phone layout (since run 2026-10-30-phone-layout-tidy): an installed app is `100dvh` tall, the window and not the screen, so the tab bar cannot run past what iOS shows. `.rail` keeps the full bottom safe area. On a phone the run panel is a sheet opened by `#rside`, closed by a swipe down or a tap outside (`initSheet()` in `web/board/run-view.ts`; outside is judged from `composedPath()`, since strip tabs and the picker redraw the panel during their own click and leave the target detached; Preview closes it. Phone Paste takes a clipboard image, and ⋯ has Pick image: `POST /term-image` (same-origin check, `image/*` body, 10 MB, type read from the bytes, `cli/term-image.ts`) saves it under `~/.kaizen/term-images/` and the path is typed into the terminal. Haptics obey per-browser `kz-haptic` (Settings → Notifications), and the new-idea form always shows the project picker.

- Footer (`.foot`, board.html only, under the rail and app: `body` is a 2-row grid above 640px): `GET /usage` (installed claude/codex only, 60 s cache, `?refresh=1`) from `cli/usage.ts` — `codexUsage` reads the newest `~/.codex/sessions/**/rollout-*.jsonl` and its last `rate_limits` (300 min = 5h, 10080 = week), `claudeUsage` sends `~/.claude/.credentials.json` `claudeAiOauth.accessToken` to `api.anthropic.com/api/oauth/usage` (`anthropic-beta: oauth-2025-04-20`) server-side only; errors carry no token. `GET /phone` runs `tailscale status --json` (`phonePeers`: iOS/Android peers), `{tailscale:false}` when absent. The terminal count = cards with a live `pty` + `GET /shells`; it opens `?view=terminal`. The board's status strip (running/stalled/… filters and Archive) stays in `.ftr` under the board, without the old issue/shortcut links.

## Watch out
- Installed as a phone app (`display-mode:standalone`) the body is fixed to the top at `100dvh`; fixed strips at the top and, on phones, bottom edge stop the iOS 26 edge blur, and the root takes the tab bar colour so no band shows if the window stops short; both pages use `viewport-fit=cover` plus safe-area padding on phones and in standalone at any width; on phones the page background is `--bg` so the inset strips show no dark band.

- On phones (≤640px) every page header (Home, Chat, Runs, the run workspace, board, Icebox, Terminal, Video, and Notes in `notes.html`) matches the Settings header: a 20px title with 28px above it and 12px below; the round 38px `+` (`#newtop` and `#hnewtop`, both the `#i-plus` icon, one rule) takes `margin:-4px 0` so the header stays Settings' height. The run workspace on a phone is titled with the run's title (set in `run-view.ts`), lights the Runs tab, and a lone pane hides its own header. The Runs page (`device()` in `phone.ts`) lists Waiting, Active, Tasks (not started, opens the workspace) and Done. Every tap of a button, link, summary or label gives a haptic tick on phones (`haptic()` in `phone.ts`: `navigator.vibrate`, else a hidden iOS `<input switch>`, whose label stops the synthetic click's propagation: it once reached the run sheet's outside-tap listener and closed the sheet on every iOS tap). The tab bar's bottom padding is the safe-area inset minus 10px, and an installed phone app's body is `height:100lvh` (iOS 26 left a strip under the bar).

- A global `ul{display:flex}` in `board.html` hits lists in rendered markdown (`.kaizen/memory.md`).

- On phones the footer status strip (`.ftr`) is hidden. `#fbtn`, right of the project selects, opens it as a fixed sheet (`statusSheet()` in `cards.ts`). The button shows an amber dot while a run waits and an accent dot while a filter or the archive is on. Both the button and the sheet are off on desktop and on paged views.

- The "Showing" combo (`#showc`) opens its list from its right edge on phones, so it stays on screen.

- On phones (≤640px) the side menu is a bottom tab bar. It is CSS only, in the shared `/* side menu */` block of `board.html` and `notes.html`. The bar is in the page flow (`order:2`), not fixed, and it owns the bottom safe-area inset, so the body drops its own. The logo and the theme toggle are hidden there; theme is in Settings. It shows Icebox, Board, Notes, Terminal and a More tab (`<details class="mtab">`, phone only): Video and Settings (`a.it.fold`) fold into its popup, More lights when one of them is the page or Settings has an update dot, and a pick or a tap outside closes it. Open panels (`aside`, fixed) cover the bar.

- Settings and the Icebox are full width: `aside.docked` header and body pad 28px each side (16px under 900px), no centred column.

- The Icebox is titled in the board header (`markView()` sets the `h1`) and hides the docked panel's header; the project picker shows folder names only, full path in the tooltip. The rail lists Icebox first, in both `board.html` and `notes.html` (a test holds them line for line).

- Popups: `web/board/main.ts` closes every open `.menu-pop` on a capture-phase `pointerdown` outside it, so only the newest one stays (card menus use stopPropagation, so bubble listeners never saw those clicks). New popups should be a `.menu-pop` inside a `.combo` to get this for free.

- Motion: Settings → Browser → Motion (`system`/`full`/`reduce`, `kz-motion` in localStorage) sets `<html data-motion>` from the head script of both `board.html` and `notes.html` (`setMotion`, beside `setTheme`). The reduced-motion CSS rule applies under the OS preference unless `data-motion=full`, and always under `reduce`; it covers the `::view-transition-*` pseudos too. `motion()`/`vt()` in `web/board/dom.ts` gate JS motion: `load()` (`web/board/api.ts`) gives a card that changed column the same `view-transition-name` on its old and new element and renders inside `vt()`, so it slides; a card that starts waiting or asking gets `.flash` for one render (`store.flash`). Rail clicks and popstate run `go()` inside `vt()` (crossfade), but `go()` itself stays synchronous for callers that open a panel right after. Board ↔ Notes crossfade via `@view-transition{navigation:auto}`. Notebook's sheet deal (`lift()`) honours `data-motion` too.

- `web/board.html` has a global `ul{display:flex;list-style:none}` for the columns; it also hits lists inside rendered markdown in the panel. Any new surface that renders a list must reset it.

- A `disabled` checkbox ignores `accent-color` and draws grey in both themes. A read-only tick that must keep the accent uses `tabindex="-1" onclick="return false"` instead (backlog items in `md()`), and needs `aria-disabled` said separately.

- README/guide board screenshot URL is pinned to a commit SHA (raw.githubusercontent.com/.../<sha>/assets/board.png) because the `main/` URL kept serving cached old images or a cached 404 after renames. Refreshing the screenshot means: commit the png, then repoint both README.md and docs/guide.md at that commit.

## Phone navigation (2026-11-08)

Phone bottom navigation now orders Runs, Search, Home, Chat, Terminal (Icebox was there briefly in 2026-11-09-icebox-phone; it opens from Search). Shared rail markup/CSS stay identical in board, notes and video. On the board, a visible terminal in the workspace or Terminal page hides the phone rail; the header Menu button reveals it without unmounting sessions. Navigation to another view resets that reveal. Desktop rail is unchanged.

- Explore uses its own compass SVG symbol (`t-explore`) in the run detail tabs, inheriting the same stroke and theme colour as other tab icons.
