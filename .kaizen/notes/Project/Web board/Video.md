# Video

Part of [[Web board]].

## In plain words
The Video page: a library of videos with their versions, where you play, compare, keep or revert a render and ask the agent for another.

## Where it lives
- Video page (`/video`, `web/video.html` + `web/video.ts` bundled to `web/video.js`, server side `cli/video.ts`): the kaizen-video skill's folders as a library. Places are the library folder (`board.video_dir`, default `~/.kaizen`) then every known project with a `videos/` folder; the page names one by index, a video by folder name (`okName`), and a file by `/video/f/<place>/<name>/<v|o>/<path>` (v = `videos/<name>/`, o = `output/<name>/`), each resolved through `inside()` (realpath, no `..`, no symlink out). `GET /video/list`, `GET /video/film`; `POST /video/save` (only `title`/`sub`/`kick`/`items` of existing beats plus `platforms`, atomic write, then a build), `/video/job` (`build`/`preview`/`render`; render = one `make_film.py --format <f> --render` per shape the platforms need), `/video/cancel`. Jobs are one global queue run with `Bun.spawn` argv arrays and `env: process.env`, output in `videos/<name>/.kaizen-job.log`, state pushed through `changed()`. The editor's Versions list starts with the Draft (the live build), then one group per version. Versions live in `cli/versions.ts`:

  - **Filing:** every listing of a video first files settled renders (unchanged for 15 s) from the scripts' `output/<name>/<preset>/`. Each moves by rename into `output/<name>/versions/<letter>/<n>/`, with a recipe copy of the video folder's small files in `videos/<name>/versions/<letter>/<n>/`. Letters are internal keys only: the page names a version "<video> · <preset>" (`vtitle`, "(2)" for a repeated preset) and its revisions v1, v2. The store is `videos/<name>/versions.json` (`revising`, `versions[{letter,preset,current,trying,revs}]`), written atomically under a `.versions.lock`.

  - **First sight:** a store-less video's existing renders become letters, oldest first, with master.sh's `previous/` copies as history, marked `recipe:false` (they cannot be revised).

  - **Actions:** `POST /video/version` (`versionAction`: revise, keep, revert, restore, delete, new) is refused during a job or a send. Revise copies a recipe back into the draft and sets `revising`, so the next render files as that version's single try. Keep makes the try current, and the old revision stays as history. Revert deletes the try and restores the current recipe. Restore swaps a history revision in, and the draft follows it when that version is being revised. Revise, revert and that restore start a build.

  - **Ask Claude:** `askFor` tells the agent which version the draft holds.

  - **The page:** clicking a row plays it in the player (the draft as the built page, a file as a plain `<video controls>`). Below 640 px rows stack, with actions at least 44 px tall.

  - **Older files:** a `videos/<name>/out/` file or a still-settling render (kind `new`) keeps the old row; the former can be deleted (`POST /video/delete` → `deleteOutput`, which refuses `o/versions/` paths). Render final hides while a version is shown, and reads "Rendered" when a render in the draft's preset is newer than the draft's build (`Output.at`, `Video.builtAt`); the page re-reads the list every 5 s while a video is open, since the board does not watch video folders. The built `film/index.html` is served with a small player injected (`window.__kz`: play/pause/seek driving `__timelines.main` from a clock and starting each `<audio data-start>`), shown in a scaled iframe; the page talks to it with `postMessage`. `KAIZEN_VIDEO_SKILL` points the scripts at another skill copy (tests use a fake one). The side menu's Video item is in board.html, notes.html and video.html; the rail test holds all three equal. New video / Ask Claude: `GET /video/presets` (film presets have `style.json`, footage ones `index.html`, template ones `preset.json`; a preset folder with a `.hidden` file comes back with `hidden: true` and the form leaves it out; a template preset is offered only for a brief, and its request points the agent at `references/promo.md` and `make_promo.py`; a footage preset only for footage (`requestFor` refuses one on a brief); a film preset under either start, tagged with its kind, and a cross pick adds a line telling the agent the build script bridges engines; a brief start takes an optional assets folder, checked like the footage folder, that the request says to copy into `videos/<name>/inputs/` for `intake.py`), `POST /video/new` and `/video/ask` build the request in `requestFor()`/`askFor()` from whitelisted values only (the brief or the user's words go between `<<<`/`>>>` as data) and call `launchRun(..., { skill: "kaizen-video", cwd: <place>, card: true })`: the prompt starts `/kaizen-video` (other agents are told to use the skill), the agent runs in the place's folder, and with `cwd` set the folder is not `remember`ed as a project; a session record is written only where the folder has a `.kaizen` (a project place, not the library). `noteAgent()` ties the terminal key to the video; `/video/list` returns `agents` (alive, asking, from `ptyState`), and the page mounts that terminal (`/term.js` `kzTerm`) in `#dock`, which sits in the editor's right column behind a Form/Terminal tab (Form by default; the tab gets a marker while the agent asks). `#dock` is parked outside `#editbody` while the editor redraws, then put back, so the session survives; the terminal starts only when its tab is shown, since one started hidden draws nothing. Send (`#sendp` under the editor, drawn only on the user's own actions so a `changed` event never wipes a message being typed; `drawSendState` redraws the status and recent sends): `GET /video/devices[?fresh=1]` runs `localsend.discover()` (multicast announce on 224.0.0.167:53317 with `reuseAddr`, replies by `POST /api/localsend/v2/register` to a temporary `Bun.serve` or by multicast; cached 2 min) and hands the page fingerprints as ids; `GET /video/chats` runs `hermes send --list whatsapp --json`. `POST /video/send {p,name,file,via,to,text}` sends only `video.outputFile()` (one of that video's listed `outputs()` entries: mp4, srt, thumb), only to a fingerprint from the last discovery or a chat id from the last Hermes list (both held in `cli/web.ts`), one send per video (`startSend`), state in `/video/list` as `send` plus the last 5 of `sends` (log: `videos/<name>/.kaizen-sends.json`, last 50). "sent" is written only when the sender returned ok: LocalSend's upload 200, or Hermes exit 0 with `{success:true}`. LocalSend in HTTPS mode demands a TLS client certificate and takes its SHA-256 as the sender's fingerprint: `identity()` in `cli/localsend.ts` builds a self-signed RSA cert in DER by hand (node:crypto signs, Bun cannot issue). For MP4s at or below 64 MiB, Hermes runs as argv `send -t <id> --json -- "<text>\nMEDIA:`<abs path>`"`; text with `MEDIA:` is refused, since Hermes attaches every `MEDIA:` path it finds. Hermes reads `~/.hermes` from `HOME` (or `HERMES_HOME`): a board with a scratch `HOME` cannot list chats.

- Phone navigation shares the board menu order: Runs, Search, Home, Icebox, Chat, Terminal. Terminal links to the all-project terminal page. See [[Web board/Layout and look]].
