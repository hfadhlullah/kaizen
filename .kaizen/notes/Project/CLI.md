# CLI

## What it does
- `kaizen prune` also removes launch records (`sessions/<key>.json` with `.pid`/`.run`) older than a week whose run is abandoned, gone, or never existed (`pruneSessions` in `cli/state.ts`). It skips live agents, runs in flight, and done runs, whose records a follow-up resumes. Lists unless `--yes`. Settings → General → Cleanup does each kind separately through `/cleanup` in `cli/web.ts`.
`kaizen` / `kaizen-agent` (both `cli/install.ts`, see `package.json` `bin`) is one top-level script that installs the workflow as links into the agent's folders, and dispatches subcommands (a first word not in `COMMANDS` is refused with `unknown command`, never run as an install; `cli/install-unknown.test.ts` fails if a dispatched word is missing from that list): `setup`, `web`, `settings`/`config`, `upgrade`, `uninstall`, `prune`, `sources`/`gather`/`icebox`, `browser login`, `issue`, `computer` (desktop control, only while its skill is on; `cli/computer.ts`), `remember`/`recall` (global knowledge, `cli/knowledge.ts`), `stats [<id>] [--json]` and `related <path...>` (read-only, `cli/stats.ts`: counts and medians over every run, a run's tokens from its Claude session log inside the run's time window, earlier runs that changed the given files), `state <id> key=value` (the one writer for a run's `state.json`: `setRunState()` in `cli/state.ts` over `setStage`, refusing unknown `stage`/`awaiting` words and `stage=done`, which stays `kaizen done`; every stage or awaiting change, and `kaizen done`, appends a line to `runs/<id>/stages.log`, the only source of stage times), and `automation list|add|run|pause|resume|rm|runs` (`cli/automations.ts`), and `docs lint` (`cli/docs.ts`). With no subcommand in an installed setup it opens the [[Terminal board]]. Flags and behaviour for users: `docs/guide.md` ("Install", "Under the hood").

## Where it lives
- `cli/workers.ts` — `kaizen worker init|start|status|config|report|merge|set` (dispatch in `cli/install.ts`): orchestration, off by default. All state is `runs/<id>/workers.json`; `start` only writes a request and waits up to 30 s for the board. Settings (`orchestration.enabled|max_workers|permissions|worker_model.<tool>`) are frozen into the file at `init`. `merge` refuses unless every worker succeeded, and a conflict resets the run's branch to its saved sha and sets the run's blocker. A worker with `after:` branches off the worker it follows; `merge` also refuses a branch that changed paths outside its `owns:` and lists any folder or branch it could not remove. A request older than 60 s is stale: the board ignores it. Never uses `prefersBypass`.
- `cli/automations.ts` — schedules that start a run: rules in `<state>/automations.json`, history in `automation-runs.json`, claims in `automation-claims/`. Five-field cron (no names), minute-walk `nextRun`/`dueSince`. A fire goes through `launchRun` as `auto <request> [automation <name> fire <id>]`: auto mode, every stage, never yolo. Claimed by an atomic `mkdir` per due minute so two boards fire once; skipped with a stored status for precheck, overlap (one open run per rule; a run is open while its stage is not done, while its terminal lives, and a launch whose run never shows the marker stays open for a day), 24/day cap, missed beyond grace (default 720 min), unavailable agent. The run is found later by the `fire <id>` marker in its request. Fires only while a board runs. `shellArgv` picks `cmd /c` or `sh -c` for the precheck (unit-tested; a real Windows run is not).
- `cli/install.ts` — everything above; `initProject()` writes a project's `.kaizen/`, its gitignore block and the `## Kaizen workflow` block in `CLAUDE.md` (`writePointer()`).
- No agent found: `noAgent()` shows a picker; an agent with an `install` command in `AGENTS` (Claude Code, Codex, Gemini CLI, OpenCode) is installed after a Yes, `addInstallerBins()` puts `~/.local/bin`, `~/.opencode/bin` and npm's global bin on PATH, `detect()` re-reads it, the agent is offered once for sign-in, and the install continues. Cursor, Antigravity, a failed install or a missing npm fall back to the docs link. `Bun.which` needs `{ PATH: process.env.PATH }` to see a PATH changed at runtime.
- `cli/setup.ts` — `kaizen setup`: numbered steps for project (`projectStep()`), preset, board, and phone, which links Tailscale and rechecks when it is missing (writes `~/.kaizen/web-hosts`, prints a QR from `cli/qr.ts`); install asks only Enter, then offers it. `install.ts` passes it `select`, so it stays testable.
- `cli/look.ts` — banner, `c` and next steps: monochrome, emphasis is bold so it follows the terminal theme. Upgrade output filters on the `+ ` of `step()`; keep that prefix.
- `cli/qr.ts` — dependency-free QR encoder (byte mode, ECC L, versions 1-6), half-block output.
- `cli/docs.ts` — read-only Project vault lint; reports broken links, metadata, coverage and staleness with a nonzero exit on findings. `cli/docs.test.ts` exercises small temporary projects.
- `cli/settings.ts` — the full-screen settings browser over `config.yml`; the medium preset now fixes all review severities within its two-round limit.
- `cli/install.test.ts`, `cli/settings.test.ts`.
- `cli/worktree.ts` also backs the board's Git tab: branch against base, pull request (`gh`, GitHub remotes only, one background look per run every 30 s, so a request never waits on GitHub). A failed `git cherry` counts as not landed.

## How it connects
- `cli/knowledge.ts` owns `~/.kaizen/knowledge/<track>.md`; `trackOf()` maps a planner's own track word (`software`, `docs`, `code+writing`) to the stored track before `recall` and `remember`: `remember` (secret check, opt-out via `knowledge.global` in the config chain, append or explicit `--replace`), `recall` (tag + word scoring), and the Claude Code SessionStart hook that install merges into `~/.claude/settings.json` and uninstall removes. It imports nothing from `state.ts` so the hook stays fast. Its flags and line format are the stable interface; the ranking may change.
- Links [[Workflow]] files into `~/.claude/skills`, `agents`, `commands`. Skills are linked by folder name, so `skills/media/kaizen-deck` lands as `skills/kaizen-deck`; a renamed skill's old link (`RENAMED_SKILLS`, now incl. `kaizen-motion`, folded into `kaizen-video`) is dropped by uninstall and cleared by install once it dangles and its target folder has that name.
- `web` starts the [[Web board]]; `sources`/`gather`/`icebox` and `browser login` drive [[Sources and icebox]].

## Watch out
- **Never run `kaizen uninstall` against the real install or this checkout** — it deletes `$KAIZEN_HOME`; test in a scratch copy with scratch `HOME` (`.kaizen/memory.md`, header of `cli/install.test.ts`).
- `kaizen worktree start|land <id>` must run from the project folder; `locate()` maps a run worktree back to its project, because the worktree holds a partial `.kaizen` (the committed notes) but none of the runs.
- `install.ts` has no exports, so its logic is tested by running it, or by reading a literal from source (the gitignore test).
- Never run `bun cli/install.ts --yes` from this checkout to "fix" `--check`: it repoints the global links (`.kaizen/memory.md`).
- `settings.ts` reads config keys by indentation; keep a key's nesting depth exact (`.kaizen/memory.md`).
- A `SETTINGS` row with `when: [key, value]` only has an effect while that other key holds that value; `listSettings()` returns the reason as `idle` and both settings screens dim the row but keep it editable. A row must be a key in `config.default.yml` (a test checks).
- `removeEverything()` lazy-imports from `cli/dashboard.ts`; moving those helpers breaks uninstall (`.kaizen/memory.md`).

- `--init-project` makes the installer set up the folder it runs in without asking; `kaizen setup` uses it with `--yes`.

- `kaizen setup` is dispatched before the no-agent guard: it installs nothing, and CI runners have no agent (2026-10-25-ci-checks-fail).
- The Windows launcher `kaizen.cmd` calls bun by full path (`process.execPath`): cmd.exe on some machines fails to find bun on PATH even when PowerShell can. POSIX keeps bare `bun` because version managers put bun under versioned paths. `kaizen web --shortcut` asks Windows for the Desktop (`GetFolderPath('Desktop')`), since OneDrive moves it (2026-10-27-windows-bun-not-recognized).
- `auto_accept` (top-level in `config.default.yml`, column 0 for `lineOf`): settings row shown only in `auto` mode; not part of the presets, so it reads from the defaults (false).

- `kaizen done <run id> [--user-approved]`: finishes a run via `finishRun`; exits 1 with an ask-the-user message while the review gate waits (see [[Workflow]]).

- `kaizen handoff start <run>|done|blocked "<reason>"` — hands a worktree run to a second agent; `start` exits 3 for "build here". See [[Workflow]].
- `cli/settings.ts` `lineOf()` reads config.yml by regex on indentation, so any new key must keep its exact nesting depth; comments at any indent are safe, a re-indented key silently reads as absent.
- `select()` in `cli/install.ts` has no initial-index parameter: the default answer is whichever option is listed first.
- `herdr pane run` types text into the pane's interactive shell, it does not exec: tabs trigger completion and are lost, and quoting is whatever that shell speaks.
- A backlog item's `path:line` is a snapshot from the run that wrote it and rots as the file moves (`cli/install.ts:402` pointed at the `$HOME` guard on 2026-09-07 and at wordmark colour code by 2026-09-30). Re-locate by the symbol the item names before acting on it.
- On this machine the global skill links (`~/.claude/skills/kaizen`) point at `~/kaizen`, a separate clone from the development checkout in `~/Projects/Husein/kaizen`. `bun cli/install.ts --check` from the checkout therefore reports every link missing, and a skill change is live only after `~/kaizen` has it. Never run `bun cli/install.ts --yes` from the checkout to "fix" that: it repoints the global links.
- `cli/install.ts` is a top-level script with no exports; its logic cannot be unit-tested. Exercise it in a scratch folder with `HOME` set to a scratch home and `KAIZEN_HOME` set to a disposable copy of the checkout — never the checkout itself: `kaizen uninstall` recursively deletes `$KAIZEN_HOME`, and on 2026-10-01 that wiped this checkout (.git, .kaizen, every session's uncommitted work).
- `removeEverything()` on win32 walks every drive (`searchRoots` + `findProjects`) and strips kaizen links from each project found; a test that runs `install.ts uninstall` mutates real projects on Windows whatever HOME it sets, so such tests must skip win32.
- herdr and macOS Terminal launches type `exec sh <script>` into the tab's shell (`findTerminal` in `cli/state.ts`): the exec is what makes the tab close when the agent ends. Tabs launched before a launcher change keep the old behaviour, so judge a launcher fix on a freshly launched tab. The one-shot script holds the tab open only on exit 126/127 (agent never started).
- `agent.*` keys are read through `configTexts()` in `cli/state.ts` (project then global, first file that sets the key wins). A new `agent.*` key that reads only one file brings back the bug where a silent project `config.yml` hides the global setting. Config regexes must also allow comment lines between `agent:` and the key: the shipped config has them.
- A run's tool and model come from `runAgent()` (latest session record, else `state.json` `agent`); `/decide` and `/fix` must keep going through `launchRun(it, dir, id)` with no pick, or a run switches tools mid-flight.
- A test can reach `launchRun` safely only where no terminal is found: on Linux, a child with PATH limited to fake tools and `DISPLAY`/`WAYLAND_DISPLAY`/`TERMINAL`/`TMUX` blanked returns `ok:false` with the manual line. On macOS `findTerminal` always drives Terminal.app, so such a test must be Linux-only.
- Board decisions resume a run's conversation through `SESSION_FLAGS` in `cli/state.ts`. Claude and gemini take an id at launch. Codex, agy and opencode pick their own id, which `find` reads back from the tool's files (codex rollouts, agy `conversations/*.db`, `opencode.db`). agy's `history.jsonl` never records an `agy -i` launch. Any `find` change must keep the window bounded, or one run claims another run's conversation. (2026-10-15-resume-other-agents)
- Some config keys have no code reader because only a prompt reads them (`spec*.md`, `agents/*.md`, `SKILL.md`): before calling a key dead, grep the prompts too. Every `SETTINGS` row in `cli/settings.ts` must be a key in `config.default.yml` (test in `cli/settings.test.ts`). (2026-10-23-settings-cleanup)
- Agent-invoked CLI commands (remember, card, …) run with cwd anywhere inside the project, often the run dir; resolve the project by walking up to `.kaizen/` (`locate()`), never `cwd/.kaizen` or `basename(cwd)`. (2026-10-27-global-knowledge)
- `runReport()` in `cli/state.ts` dates a run by its report mtimes, capped at `state.json` `updated` once the run is done. Without the cap, any rewrite of a finished run's `03-impl.md` made it claim later runs' uncommitted changes to the files it names (2026-10-30, git-tab run).
- Automations (cli/automations.ts) link a fire to its run by a `fire <id>` marker in 00-request.md; changing how a run's request is written breaks overlap protection.
