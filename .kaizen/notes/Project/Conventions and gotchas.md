# Conventions and gotchas

## In plain words
The house rules that apply everywhere in this project and are not obvious from any one file: how several agents share one folder safely, what never to run, and the traps that have bitten before.

## What it does
The rules that are not visible in any one file. Cross-area lessons are in `.kaizen/memory.md`, kept by kaizen's reviewer; lessons about one area sit in that area's note under *Watch out* (moved there 2026-11-03). This note groups the ones that apply everywhere.

## Where it lives
- `.kaizen/memory.md` — cross-area lessons (not committed in this repo); area lessons are in the area notes.
- `design.md` — visual system for every surface; check contrast by calculation, not by its claim (`.kaizen/memory.md`).

## Shared tree
- More than one session works in this checkout at once. Never `git stash` or `git checkout` a path to get a baseline, and never append cleanup commands to a build; take baselines from a `git worktree` (`.kaizen/memory.md`).
- A run now builds in its own worktree (`.kaizen/wt/<id>`, branch `kaizen/<id>`), so the stash and checkout ban only matters for runs without one. Never `git worktree remove` one that holds unlanded work. See [[Workflow]].
- Two runs in one tree can land in one commit; check `git log --stat -1` before believing nothing is committed (`.kaizen/memory.md`).

## Code style
- Comments explain why, at the top of a file and above non-obvious functions; `ponytail:` comments mark deliberate shortcuts with their ceiling (e.g. `cli/notes.ts`).
- Tests are plain `bun:test` files in `cli/*.test.ts` and `bot/test/`; not every module has its own (`cli/dashboard.ts` and `cli/web.ts` do not).
- Optional tools (git) are shelled out to with a catch: `Bun.spawnSync` throws when the binary is missing (`.kaizen/memory.md`).
- Every `Bun.spawn`/`spawnSync` of a console program from the board passes `windowsHide: true`: a board started from the Windows shortcut has no console, so each child otherwise flashes a new console window (#16, the 60 s `/phone` poll).
- Board pages redraw with `innerHTML`, which drops an open `<details>`/combo and swallows a click whose element is replaced mid-press. Background redraws no longer exist for the React pages (a popup is never redrawn), and `whenIdle()` is gone; the old pages that remain (side menu, panel body, terminals) redraw only on their own events.
- `design.md` now has monochrome as the default palette, with blue as the alternative (`data-color=blue`, `kz-color`). Green, amber and red stay for state.
- Root docs and repo metadata (`README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `CLAUDE.md`, `.github/`, ignore and format files) and the vendored `.claude/skills` are listed here for coverage.

## React front end (2026-11-14, run 2026-11-14-frontend-rewrite-phase1)

New UI is React 19 + shadcn/ui (Radix) + Tailwind v4 + Zustand, bundled by `bun run build:web` into the committed `web/dist/board.js` and `web/dist/ui.css`; users install nothing and `dependencies` stays empty (every package is an exact-pinned devDependency). Pages move over one at a time; Tasks list and task page are first. Old `web/board/` code shrinks each phase.

**`web/` top level** is folders and `README.md` only (page shells in `web/html/`, the whole-tree test in `web/checks/`) (a test fails on another file there). Entry sources live in an app folder (`web/notebook/`, `web/term/`, `web/video/`, `web/annotate/`), generated bundles only in `web/dist/` (never edit; `bun run build:web`); `web/ui/theme.css` is the Tailwind theme. The server serves bundles at flat URLs (`/board.js`, `/ui.css`, `/notebook.js`, `/term.js`, `/term.css`, `/video.js`, and `/notebook-kit.js`, the notebook's on-demand kit bundle) from `web/dist/`; keep those URLs when moving files, an upgrade leaves old pages open. The gitignored `.kaizen/config.yml` `git.generated` should read `web/dist/* bot/web/app.js`.

**Three levels, imports only downward** (`web/checks/structure.test.ts` fails otherwise): `web/ui/` generic shadcn pieces (may import only `web/lib/core/utils.ts`, kebab-case, one per file, the only place a Radix package or cmdk is imported) -> `web/components/` kaizen pieces built from `ui/` (one component per file, file name is the export) -> `web/pages/` one per view, layout plus data. `web/lib/` holds rules, stores (Zustand), actions and hooks, no JSX; it imports only lib. **Feature folders** (`web/README.md` is the map): `components/` and `lib/` hold only folders (`shared`, `task`, `decision`, `icebox`, `board`, `run`, `git`, `settings`, `phone`, `home`, `project`, `search`, `markdown`; lib adds `core` for `api`, `host`, `utils`, `format`, `labels`, `toast`, `store`, `ask`, `board.ts` and `brief`, and `url`), each with an `index.ts`; a folder stays at 25 source files or fewer (`*.test.ts` are not counted). Anything outside a folder imports it through the index (inside a folder, files import each other directly); a component two features use goes to `shared`. Exceptions, listed in `checks/structure.test.ts`: `ui/` takes `lib/core/utils.ts` directly, and six `web/board` bridge files (`workspace`, `ws-tabs`, `labels`, `search`, `dictation`, `update`) import one small lib file directly, because a barrel would pull the board's stores (they read `localStorage` and `document` at import) into the notebook and Video bundles and into DOM-less tests. Tests live beside the code they test (`web/lib/git/git.test.ts`, `web/components/task/tasks.test.ts`; `checks/structure.test.ts` stays at `web/`), import the file they test directly, and no `index.ts` exports them; there is no `tests/` folder. Lib never imports `web/board`: the bridge `web/board/react-mount.ts` hands the old code's functions over once through `setHost()` (go, newTask, runPopup, attention, scope, and for the Icebox the project list and pickers, dictation, the click sound, `dataUrls`, Settings). The old key handler reaches a React page through `react` in `views.ts` (`react.iceKeys`), and the server's `changed` event reaches it as `kz-changed`.
**Imports:** across folders use the aliases `@web/ui`, `@lib/<feature>` and `@components/<feature>` (tsconfig `paths`; a folder alias is its `index.ts`), never `../../`; siblings in one folder stay relative. `web/ui/index.ts` is the kit barrel, one line per ui file.

**Rules.** Popovers, menus, selects, pickers, dialogs and tooltips come from `ui/` and render into `#kz-portal` (`portalRoot()`); a page never builds one. Styling uses theme names only (`bg-background`, `text-muted-foreground`, `border-border`, never hex or `rgb(`); `web/ui/theme.css` maps the board's CSS variables, so light, dark, blue and motion work unchanged. Button `variant` is `primary` (the one main action of an area), `default`, `ghost`, `danger`; `size` `md` or `sm`; an icon-only control is `IconButton`, never a `Button`. Every input goes through `Field` (label, control, help, error with `aria-describedby`). Data loading and actions live in `lib/<feature>` hooks (`useTasks`, `useTask`, `runAction`, `sendMessage`), not in components, so two places showing the same decision share one code path. A `border-<side>` plus an arbitrary colour needs `border-[color:...]`, or tailwind-merge drops one of them.

**Component map** (today's pattern -> piece): `.btn` -> `ui/button`; `.ib` -> `icon-button`; `ico()` -> `ui/icon` (the board's sprite); filter popup -> `filter-menu`; "..." menu -> `action-menu`; `combo` picker -> `picker`; `.sel` -> `ui/select`; `.ice-chip` -> `chip`; status dot/word -> `status-badge`; approve/answer/project strip -> `decision-bar`; labelled input with button -> `inline-form`; label+control+help+error -> `field`; chat -> `chat-bubble`, `typing-dots`; empty list -> `empty-state`; row -> `task-row`; outputs -> `result-view`, `result-checks`, `artifact-view`; confirm -> `confirm-dialog`; `toast()` -> `lib/core/toast.ts` (old `board/toast.ts` forwards once the board mounts it; the notebook and Video pages keep their own so React stays out of their bundles); pager -> `pager`. Icebox (phase 2): filter popup with pickers -> `filter-popover` + `picker` (groups, icons, counts); item menus -> `choice-menu` (Kind, Collection) and `snooze-menu`; `modal()` prompt -> `collection-dialog`; request rows and cards -> `request-row`, `request-card`, `request-phone-row`; drawer -> `ui/sheet`; switch -> `ui/switch`; segmented Cards/Sort -> `segmented`. Board (phase 3): card -> `board-card` (`status-mark`, `card-footer`, `card-kids`, menu = `action-menu` with icons, separators and counts); column -> `board-column` (`ui/tabs` for To do / Backlog, `severity-menu`, `clear-menu`); inline or dialog forms -> `card-form`, `run-form`, `task-form` on `form-frame` and `attach-button`, shown by `board-popups`; workspace card -> `ws-card`; the run panel's footer strip and the task page's decision sections are one `decision-bar` (`layout` section or strip) with `revise-form`, `plan-answers-form`, `task-reply-form`, wired to the run actions by `run-footer`; Fix findings -> `fix-form` in a portal (`fix-host`). Run view chrome and git (phase 3C): tab bar `run-tabs`, menus `run-add-menu`, pane `pane-header`, History / wait / empty `run-history`, `run-wait`, `run-empty`, panel header `panel-head` (`phase-steps`, `run-progress`), `panel-tabs`, `run-picker`, `key-hint`, `project-notes`, header switch `board-mode-switch`, Source control `git-tab` and its `git-*` pieces. Built in later phases: `ui/dialog` consumers outside the Board, the side menu (`workspace.ts`, shared with the notebook and Video bundles). Settings (phase 4): a settings row -> `Field` with `row` (label and help left, control right, stacked under 520 px by a container query on the section box) around `Switch`, `Segmented`, `Stepper` (‹ value ›), `Select`, `CommitInput` (saves on blur or Enter); `confirm()` -> `ask()` in `lib/core/ask.ts` drawn by `AskHost`; the page's rows come from `lib/settings/settings.ts` as `Item`s and `settings-item.tsx` draws each by kind.

**Old code reaches React through `react` in `web/board/views.ts`** (registered once in `main.ts`; `initPanel()` runs after it because it mounts the panel header parts): `drawBoard`, `drawGit`, `drawHead`, `drawMode`, `drawSettings`, `mountRunPart`, `popup`, `closeForm`, `formOpen`, `drawFooter`, `drawFix`, `fixReset`, `answered`, `resume`. Old modules shared with the notebook and Video bundles import nothing from `web/lib` that pulls React (`views.ts` registry only). `web/lib/run/run-actions.ts` holds what a card, the panel and the task page ask the server to do (`resumeRun`, `archiveCard`, `decideRun`, `acceptRun`, `acceptTask`, `answerTask`, `fixFindings`); a new button that does one of these calls it, never a second `post`.

**`Field` hands the control its props and the label's id:** `{(props, labelId) => <Input {...props} />}`; spread `props` only on a real form control, and use `labelId` for a group (segments, a stepper) through `aria-labelledby`. `Field` takes an optional `id` when something outside needs a fixed one (Settings' `#s-<key>` ids are what tests and the CDP walks click).

**Add a shadcn piece:** copy its source into `web/ui/`, change the imports to `../lib/core/utils.ts`, restyle with theme names to the board's sizes (`--btn-*`, `--r-*`, `--fs-*`), make its portal use `portalRoot()`, import the Radix part from `radix-ui`.

**Legacy layer.** (Not empty yet: the side menu, run view, panel body and terminal pages still use it, and the notebook and Video copies share the side-menu part.) `board.html` wraps all its CSS in `@layer legacy`, declared before `theme, base, components, utilities`, so Tailwind utilities always win over old rules and old rules never restyle new ones. Tailwind's reset is scoped to `.kz-ui` (each React root and `#kz-portal`), not global; `.kz-keep` marks a legacy element docked into a React page (search box `#bq`, `#newtop`) that the reset must skip. Unlayered CSS (`term.css`) outranks the layer, and layered `!important` reverses priority: check both when touching either. Do not put an old element's id on a `.kz-ui` root: the reset zeroes its padding.

**Phase 5 additions (Home, chat, Search, Phone, onboarding, dialogs).** One `AskHost` lives in the shared portal for every `ask()` (the old `confirm()`/`alert()` calls in `web/board` are gone; `video.ts` keeps its own `confirm()`). Other portal-level hosts, all mounted in `initReact()`: `AddProjectDialog`, `WsMenu`, `FileViewer`, `SearchPalette`, `OnboardingDialog` (and its Continue popup), `UpdateCard`, `PhoneSheets`. Old code opens them through a small Zustand store in `web/lib` (`openAdd`, `openWsMenu`, `openFile`, `useSearch`, `openSheet`), never by importing a component. Parts of the old header or window that stay in `board.html` get a React root through `react.mountRunPart(el, part)` (the project and Showing pickers, the Home window's "+" menu). Markdown for chat text is `web/components/markdown/markdown.tsx` over `web/lib/markdown/markdown.ts` (blocks as data, no HTML); `md()` in `web/board/markdown.ts` still feeds the panel's documents and the notes editor. The notebook and Video bundles share `workspace.ts` with the board and carry no React: anything `workspace.ts` calls must not import a component (see the kit paragraph below for how the Notebook opens them). Two traps from this phase: a module-level `const ask = ...` in an old file silently shadows `import { ask }` (the bundler does not complain; `workspace.ts` aliases the import as `askYes`), and the CSS-dead check by class name misses classes built at run time and classes a library draws (`xterm-*`, `cm-*`), so a removal is confirmed by comparing old and new screenshots.

- Popup tests in a page: an open Radix layer has `data-state=open`; old board code marks hidden popups with `hidden` but they keep `role=dialog`/`menu`, so never test for the role alone.

**React hosts inside old elements (final fix round).** A React root mounted once into an old element (`#ptabs`, `#psub`, `#hx`, `#pfoot`, the pane `.ph`) is never wiped by old code: no `innerHTML`/`textContent`/`replaceChildren` on that element; publish to its store instead, or append beside the host. `web/checks/structure.test.ts` guards `settings.ts`, `tasks-page.tsx` and the `workspace.ts` openers. `workspace.ts` is also in the notebook and Video bundles, which mount no React: anything it opens through a store (Add a project, the worktree menu, Search) goes through `onBoard()`, then `kitFor()` on the Notebook (below), and only on Video or when the kit fails to load through `leave()`, which sends the person to the board (`?add=`, `?search=1`) after the open note is flushed (`kz-leave`).

**The Notebook's kit (roadmap 2, phase 1).** `web/notebook/kit.ts` is its own bundle, `web/dist/notebook-kit.js` (IIFE, React + search palette, Add a project, worktree menu, `AskHost`, `Toaster`; about 142 KB gzip), fetched with `/ui.css` by `web/notebook/kit-loader.ts`. Phase 1 loaded it on first use; since phase 2 `initRail()` loads it when the page starts, because the side menu's Projects list and filter are React drawn by the kit into `#plist` and `#pfilter-host` (the Notebook now fetches about 150 KB gzip of kit at every load, and `notebook.js` shrank by 6 KB). The kit's zustand stores (`useSearch`, `useAddProject`, `useWsMenu`, `useAsk`) live in that bundle, a second copy: shared side-menu code must call the loaded kit's (`kitFor()` in `workspace.ts`, `S` in `search.ts`), never import the store and set it, or it writes to a copy nothing draws. `kitFor()` also hands the kit what only the page knows through `setHost` (`gitProjects`, `wsHref`, `navigate` = `leave`, `pickProject`) and points the old toast at the kit's. A page opts in with `<html data-kit>` (`notes.html`); Video has no kit and keeps the board redirect and the browser's right-click menu. Every page load the palette starts goes through `go()` in `search.ts` and `host.navigate` in the Add sheet, both `leave()` on the Notebook, so the 600 ms autosave is written before the page goes. `notes.html` wraps its CSS in `@layer legacy` like `board.html`, except the `#editor`/`.cm-*` rules and `@view-transition`, which stay unlayered (CodeMirror's own styles are unlayered and would beat layered editor rules). The kit's popups render into `#kz-kit` (found by `portalRoot()`); never give it the id `kz-portal`, which means "this is the board" to `onBoard()`.

**Run workspace panes (roadmap 2, phase 3).** Never move a pane element to change the layout: `RunPanes` keeps one flat list of keyed `Pane`s and gives each its rectangle (`lib/run/layout.ts` `rects()`), because moving a node reloads a frame and, for a terminal, would remount it. Everything that reads where panes are (the Ctrl+Space arrows) uses `rects()`/`boxesOf()`, not `getBoundingClientRect()`. Layout state is `lib/run/layout-store.ts`; `run-view.ts` must not keep a tree, build pane or frame elements, or touch `kz-runtabs` (a structure test checks it). A pointer drag listens on the `window` as well as capturing the pointer. Legacy CSS classes inside a `kz-ui` root need `kz-keep` or Tailwind (see Run workspace, Watch out).
