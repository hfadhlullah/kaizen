# Conventions and gotchas

## In plain words
The house rules that apply everywhere in this project and are not obvious from any one file: how several agents share one folder safely, what never to run, and the traps that have bitten before.

## What it does
The rules that are not visible in any one file. Cross-area lessons are in `.kaizen/memory.md`, kept by kaizen's reviewer; lessons about one area sit in that area's note under *Watch out* (moved there 2026-11-03). This note groups the ones that apply everywhere.

## Where it lives
- `.kaizen/memory.md` — cross-area lessons (not committed in this repo); area lessons are in the area notes.
- `design.md` — visual system for every surface; check contrast by calculation, not by its claim (`.kaizen/memory.md`).

## Shared tree
- More than one session works in this checkout at once. Never `git stash` or `git checkout` a path to get a baseline, and never append cleanup commands to a build; take baselines from a `git worktree` (`.kaizen/memory.md`).
- A run now builds in its own worktree (`.kaizen/wt/<id>`, branch `kaizen/<id>`), so the stash and checkout ban only matters for runs without one. Never `git worktree remove` one that holds unlanded work. See [[Workflow]].
- Two runs in one tree can land in one commit; check `git log --stat -1` before believing nothing is committed (`.kaizen/memory.md`).

## Code style
- Comments explain why, at the top of a file and above non-obvious functions; `ponytail:` comments mark deliberate shortcuts with their ceiling (e.g. `cli/notes.ts`).
- Tests are plain `bun:test` files in `cli/*.test.ts` and `bot/test/`; not every module has its own (`cli/dashboard.ts` and `cli/web.ts` do not).
- Optional tools (git) are shelled out to with a catch: `Bun.spawnSync` throws when the binary is missing (`.kaizen/memory.md`).
- Every `Bun.spawn`/`spawnSync` of a console program from the board passes `windowsHide: true`: a board started from the Windows shortcut has no console, so each child otherwise flashes a new console window (#16, the 60 s `/phone` poll).
- Board pages redraw with `innerHTML`, which drops an open `<details>`/combo and swallows a click whose element is replaced mid-press. Background redraws no longer exist for the React pages (a popup is never redrawn), and `whenIdle()` is gone; the old pages that remain (side menu, panel body, terminals) redraw only on their own events.
- `design.md` now has monochrome as the default palette, with blue as the alternative (`data-color=blue`, `kz-color`). Green, amber and red stay for state.
- Root docs and repo metadata (`README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `CLAUDE.md`, `.github/`, ignore and format files) and the vendored `.claude/skills` are listed here for coverage.

## React front end (2026-11-14, run 2026-11-14-frontend-rewrite-phase1)

New UI is React 19 + shadcn/ui (Radix) + Tailwind v4 + Zustand, bundled by `bun run build:web` into the committed `web/dist/board.js` and `web/dist/ui.css`; users install nothing and `dependencies` stays empty (every package is an exact-pinned devDependency). Pages move over one at a time; Tasks list and task page are first. Old `web/board/` code shrinks each phase.

**`web/` top level** is folders and `README.md` only (page shells in `web/html/`, the whole-tree test in `web/checks/`) (a test fails on another file there). Entry sources live in an app folder (`web/notebook/`, `web/term/`, `web/video/`, `web/annotate/`), generated bundles only in `web/dist/` (never edit; `bun run build:web`); `web/ui/theme.css` is the Tailwind theme. The server serves bundles at flat URLs (`/board.js`, `/ui.css`, `/notebook.js`, `/term.js`, `/term.css`, `/video.js`, `/annotate.js` (the annotator's page script, also served by the proxy) and `/notebook-kit.js`, the notebook's on-demand kit bundle) from `web/dist/`; keep those URLs when moving files, an upgrade leaves old pages open. The gitignored `.kaizen/config.yml` `git.generated` should read `web/dist/* bot/web/app.js`.

**Three levels, imports only downward** (`web/checks/structure.test.ts` fails otherwise): `web/ui/` generic shadcn pieces (may import only `web/lib/core/utils.ts`, kebab-case, one per file, the only place a Radix package or cmdk is imported) -> `web/components/` kaizen pieces built from `ui/` (one component per file, file name is the export) -> `web/pages/` one per view, layout plus data. `web/lib/` holds rules, stores (Zustand), actions and hooks, no JSX; it imports only lib. **Feature folders** (`web/README.md` is the map): `components/` and `lib/` hold only folders (`shared`, `task`, `decision`, `icebox`, `board`, `run`, `git`, `settings`, `phone`, `home`, `project`, `search`, `notes`, `dictation`, `markdown`; lib adds `core` for `api`, `host`, `utils`, `format`, `labels`, `toast`, `store`, `ask`, `board.ts` and `brief`, and `url`), each with an `index.ts`; a folder stays at 25 source files or fewer (`*.test.ts` are not counted). Anything outside a folder imports it through the index (inside a folder, files import each other directly); a component two features use goes to `shared`. Exceptions, listed in `checks/structure.test.ts`: `ui/` takes `lib/core/utils.ts` directly, and six `web/board` bridge files (`workspace`, `ws-tabs`, `badge`, `labels`, `search`, `update`) import one small lib file directly, because a barrel would pull the board's stores (they read `localStorage` and `document` at import) into the notebook and Video bundles and into DOM-less tests. Tests live beside the code they test (`web/lib/git/git.test.ts`, `web/components/task/tasks.test.ts`; `checks/structure.test.ts` stays at `web/`), import the file they test directly, and no `index.ts` exports them; there is no `tests/` folder. Lib never imports `web/board`: `web/pages/board/host-bridge.ts` hands the old code's functions over once through `setHost()` (go, newTask, runPopup, attention, scope, and for the Icebox the project list and pickers, the note editor, the click sound, `dataUrls`, Settings). The old key handler reaches a React page through `react` in `views.ts` (`react.iceKeys`), and the server's `changed` event reaches it as `kz-changed`.
**Imports:** across folders use the aliases `@web/ui`, `@lib/<feature>` and `@components/<feature>` (tsconfig `paths`; a folder alias is its `index.ts`), never `../../`; siblings in one folder stay relative. `web/ui/index.ts` is the kit barrel, one line per ui file.

**Rules.** Popovers, menus, selects, pickers, dialogs and tooltips come from `ui/` and render into `#kz-portal` (`portalRoot()`); a page never builds one. Styling uses theme names only (`bg-background`, `text-muted-foreground`, `border-border`, never hex or `rgb(`); `web/ui/theme.css` maps the board's CSS variables, so light, dark, blue and motion work unchanged. Button `variant` is `primary` (the one main action of an area), `default`, `ghost`, `danger`; `size` `md` or `sm`; an icon-only control is `IconButton`, never a `Button`. Every input goes through `Field` (label, control, help, error with `aria-describedby`). Data loading and actions live in `lib/<feature>` hooks (`useTasks`, `useTask`, `runAction`, `sendMessage`), not in components, so two places showing the same decision share one code path. A `border-<side>` plus an arbitrary colour needs `border-[color:...]`, or tailwind-merge drops one of them.

Old code reached React through `react` in `web/pages/board/views.ts`** (registered once in `main.ts`; `initPanel()` runs after it because it mounts the panel header parts): `drawBoard`, `drawGit`, `drawHead`, `drawMode`, `drawSettings`, `mountRunPart`, `popup`, `closeForm`, `formOpen`, `drawFooter`, `drawFix`, `fixReset`, `answered`, `resume`. **`Field` hands the control its props and the label's id:** `{(props, labelId) => <Input {...props} />}`; spread `props` only on a real form control, and use `labelId` for a group (segments, a stepper) through `aria-labelledby`. `Field` takes an optional `id` when something outside needs a fixed one (Settings' `#s-<key>` ids are what tests and the CDP walks click).

**Add a shadcn piece:** copy its source into `web/ui/`, change the imports to `../lib/core/utils.ts`, restyle with theme names to the board's sizes (`--btn-*`, `--r-*`, `--fs-*`), make its portal use `portalRoot()`, import the Radix part from `radix-ui`.

**Legacy layer.** (Not empty yet: the side menu, run view, panel body and terminal pages still use it, and the notebook and Video copies share the side-menu part.) `web/ui/legacy/board.css` (built with the kit into `/board.css`; the notebook's is `notes.css`) wraps its CSS in `@layer legacy`, declared before `theme, base, components, utilities`, so Tailwind utilities always win over old rules and old rules never restyle new ones. Tailwind's reset is scoped to `.kz-ui` (each React root and `#kz-portal`), not global; `.kz-keep` marks a legacy element docked into a React page (search box `#bq`, `#newtop`) that the reset must skip. Unlayered CSS (`term.css`) outranks the layer, and layered `!important` reverses priority: check both when touching either. Do not put an old element's id on a `.kz-ui` root: the reset zeroes its padding.

**Phase 5 additions (Home, chat, Search, Phone, onboarding, dialogs).** One `AskHost` lives in the shared portal for every `ask()` (the old `confirm()`/`alert()` calls in `web/board` are gone; `video.ts` keeps its own `confirm()`). Other portal-level hosts, all mounted in `initReact()`: `AddProjectDialog`, `WsMenu`, `FileViewer`, `SearchPalette`, `OnboardingDialog` (and its Continue popup), `UpdateCard`, `PhoneSheets`. Old code opens them through a small Zustand store in `web/lib` (`openAdd`, `openWsMenu`, `openFile`, `useSearch`, `openSheet`), never by importing a component. Parts of the old header or window that stay in `board.html` get a React root through `react.mountRunPart(el, part)` (the project and Showing pickers, the Home window's "+" menu). Markdown for chat text is `web/components/markdown/markdown.tsx` over `web/lib/markdown/markdown.ts` (blocks as data, no HTML); `md()` in `web/lib/notes/md-html.ts` still feeds the panel's documents and the notes editor. The notebook and Video bundles share `workspace.ts` with the board and carry no React: anything `workspace.ts` calls must not import a component (see the kit paragraph below for how the Notebook opens them). Two traps from this phase: a module-level `const ask = ...` in an old file silently shadows `import { ask }` (the bundler does not complain; `workspace.ts` aliases the import as `askYes`), and the CSS-dead check by class name misses classes built at run time and classes a library draws (`xterm-*`, `cm-*`), so a removal is confirmed by comparing old and new screenshots.

- Popup tests in a page: an open Radix layer has `data-state=open`; old board code marks hidden popups with `hidden` but they keep `role=dialog`/`menu`, so never test for the role alone.

**React hosts inside old elements (final fix round).** A React root mounted once into an old element (`#ptabs`, `#psub`, `#hx`, `#pfoot`, the pane `.ph`) is never wiped by old code: no `innerHTML`/`textContent`/`replaceChildren` on that element; publish to its store instead, or append beside the host. `web/checks/structure.test.ts` guards `settings.ts`, `tasks-page.tsx` and the `workspace.ts` openers. `workspace.ts` is also in the notebook and Video bundles, which mount no React: anything it opens through a store (Add a project, the worktree menu, Search) goes through `onBoard()`, then `kitFor()` on the Notebook (below), and only on Video or when the kit fails to load through `leave()`, which sends the person to the board (`?add=`, `?search=1`) after the open note is flushed (`kz-leave`).

**The Notebook is React in its own bundle (roadmap 2, phases 1, 2 and 6).** `notebook.js` bundles React itself (about 344 KB gzip; the lazy `notebook-kit.js` is gone, so there is no late load to time out, fail or mount twice). `web/notebook/notebook.ts` is a 24-line entry: `mountKit()` (`kit.ts`: one `#kz-kit` container with the search palette, Add a project, worktree menu, `AskHost` and `Toaster`, and the side menu's Projects list and filter into `#plist` and `#pfilter-host`), the React page (`pages/notebook-page.tsx` over `components/notebook`, state and rules in `lib/notebook`), `initRail()` and `startVault()`. In `?embed=1` only the toasts and questions mount (no palette, no list, no `initRail()`), so an embedded note tab is the editor alone. `mountKit()` also registers the stores as `window.kzKit` for the code the board and Video bundles share (`workspace.ts`, `search.ts`): they reach the stores through `kitFor()` / `S` instead of importing them, because Video must not carry React; on the Notebook both routes lead to the same module copy now, so the dead-store trap of phase 1 cannot happen there. `kitFor()` also hands the kit what only the page knows through `setHost`. A page opts in with `<html data-kit>` (`notes.html`); Video has none and keeps the board redirect and the browser's right-click menu. Page loads the palette starts go through `leave()`, which fires `kz-leave`; the notebook answers it by flushing the autosave. `notes.html` links `/ui.css` and wraps its CSS in `@layer legacy` like `board.html`, except the `#editor`/`.cm-*` rules and `@view-transition`, which stay unlayered (CodeMirror's own styles are unlayered and would beat layered editor rules). The page's chrome keeps its legacy class names (`.hdr`, `.side`, `.nt`, `#meta`, ...) and draws outside `.kz-ui`; only the project Picker sits in a `kz-ui` box. The kit's popups render into `#kz-kit` (found by `portalRoot()`); never give it the id `kz-portal`, which means "this is the board" to `onBoard()`.

**The note editor is one component (roadmap 2, phase 6).** `lib/notebook/engine*.ts` holds CodeMirror 6 (live preview widgets and decorations, click rules, the `/` and `[[` menus) behind `createEditor(parent, text, host)`; `components/notebook/editor-pane.tsx` makes it in a layout effect and destroys it on unmount, and the page keys it by `doc`, a counter `openNote()` bumps, so a redraw, a rename or a refresh from disk never remakes it (cursor, scroll and undo history stay). The engine reads the page only through the `EditorHost` it is given. Saving is `lib/notebook/autosave.ts`, a state machine with an injected timer and request: edit starts a 600 ms wait, `flush()` writes now and waits for a save in flight, a 409 is a conflict that stops saving until Keep mine / Load theirs. Every way out flushes first: switching notes, `go()`, the `kz-leave` event (Ctrl+K), `visibilitychange` hidden, and `pagehide` (a keepalive request); `beforeunload` still asks while text is unsaved. The `/` menu is CodeMirror's own autocomplete tooltip, styled in `notes.html`; it is the one popup this page does not draw with the kit. In `lib/notebook`, `history` is no longer shadowed, but keep writing `window.history` there out of habit. The pure text rules (`text.ts`) also serve `cli/`: `web/notebook/notes-lib.ts` re-exports that one file (never the lib index, whose zustand is a dev dependency).

Traps met: (1) a concise effect arrow that returns a value (`useEffect(() => el?.scrollIntoView())`) makes React call that value as the cleanup ("c is not a function"): use braces. (2) A hover popover that closes returns the focus to its trigger (Radix `onCloseAutoFocus`), and an `onFocus` that opens it opens it again: open on `:focus-visible` only and cancel the return focus. (3) Drag handles listen on the window, not only through pointer capture (CDP and some browsers do not retarget moves to the captured element). (4) `Array(NaN)` in a track count: a grid with no tiles needs at least one track. (5) `term.js` puts the phone's key bar after the terminal element, outside `.term`: the host must be `kz-keep` or the kit's preflight strips its styling (`TerminalPane` wraps it in `kz-keep contents`). (6) `git add` of `bot/web/app.js` with every bundle rebuild: its first line holds the source hash. The Project context pane's open button is hidden by `board.html` at every width. Left for later: the in-card terminal's own chrome in `web/term/term.ts` (find box, paste, reconnect strip, font size and the phone key bar are plain DOM inside the xterm bundle: a separate lazily loaded bundle with no React, and the soft-keyboard focus rules there need a real phone to verify).
