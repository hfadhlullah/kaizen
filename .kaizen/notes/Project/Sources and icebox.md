# Sources and icebox

## In plain words
Places kaizen reads requests from, such as shared sheets, docs and social posts. Each request waits in the icebox until someone turns it into a task; what kaizen reads there is never obeyed as a command.

## What it does
Shared links (sheets, docs, social searches) kaizen reads for requests; each request lands in the project's icebox until someone promotes it to a task. Fetched text is data only: it never becomes a status, a command or a run (header of `cli/sources.ts`). Social sources are read by kaizen's own headless browser (`cli/browser.ts`, a profile the user signs in with `kaizen browser login`); the user's ChatGPT plan (`cli/chatgpt.ts`) or the agent via `/kaizen gather` picks which posts fit. A gathered post can be answered from the Icebox: ChatGPT drafts (`draftReply`, in a style from `REPLY_STYLES`; Regenerate passes the old draft as `avoid`), the user edits and approves, and the browser posts it (`sendReply`). User guide: `docs/guide.md` ("Request sources").

## Where it lives
- `cli/sources.ts` — sources, fetching, `sift` (sheet parsing), the icebox. Images: an icebox item's `images` (https links, max 4) sit outside its dedup key; sheets read them from `htmlview` by row number, docs from the html export by line, agents and `--posts` pass `img <url>` tokens in notes (`takeImages`). Google image links expire (403 later), so the board never opens a kept link: `GET /ice-image?dir&id&i` (`cli/web.ts`) reads the source again via `freshImages` and redirects to the fresh one.
- Swipe view (`iceSwipe` in `web/board/icebox.ts`, CSS `.sw*` in `web/board.html`): one waiting request at a time from the same filtered `order` as the list; drag past 100 px, arrow keys or buttons post `promote` / `dismiss` per item; Undo restores only the last dismiss (a promote already made a task); skip only reorders this session. Session counts live in `iceSwipe`; the daily streak is `localStorage` `kz-ice-streak:<dir|all>`. On desktop `.sw` is full width with `height: calc(100dvh - 130px)` (min 420 px) so it fits the tab; under 640 px it is `position:fixed` full screen. Every card names its project (`.sw-proj`). A held or flying card is lifted to `position:fixed` (`lift()`/`drop()`) so `#pbody`/`.app` overflow cannot crop it; fly-off and spring-back use `element.animate` (no animation library: zero runtime deps). While the card is held, `openSources()` defers (`swHeld`/`swLate`) so a server change cannot drop the drag. Swipe click goes through `playSound("pop")` unless `soundPick()` is off.
- Items typed by hand: the capture box at the top of the Icebox posts `/icebox {op:"add", text, board, files}`; `capture()` (wrapping `addRow()`, as `addItem()` does) stores it as `source: "manual"`, deduped by the same row key as gathered items. In All projects the box has its own project picker (`cap.dir`, defaulting to the one project shown, else the first).
- The Icebox page itself (capture box, boards bar, Cards | Sort, item menus): [[Sources and icebox/Icebox page]].
- Your own captures (2026-11-09-icebox-personal-inbox, run 1 of the icebox-inbox roadmap): optional item fields `kind` (`client` | `finding` | `people`, labels in `KINDS`), `sorted` (`me` | `agent` | `ai` | `rules`; `rules` reads as unsorted), `board`, `tags` (max 8 × 24 chars, lowercase, `cleanTags`), `snoozed` (local `YYYY-MM-DD`), `link` (`{ url, title?, summary? }`). No migration: `kindOf(item, boards)` returns a chosen kind, else the rule (client board → client, social source → people, other gathered → client, manual → finding), recomputed each read. `ingest()` stores the rule kind with `sorted: "rules"`. Boards live in `boards.json` per state dir (`readBoards`, `saveBoard`, `removeBoard` only when empty); a board marked `client` is the client name. `capture()` checks kind/board/tags/dup first, then reads the first http(s) link with `readLink()` (Firecrawl `scrape(url, { formats: ["summary"] })` from `cli/research.ts` when a key is set, else the page `<title>` through `fetchText(..., "html")`, public https only), then writes synchronously. Changes: `editItem` (own `manual` items only: write-back finds a gathered row by its text), `setKind`, `setTags`, `setBoard`, `snooze` (`snoozeUntil`: `1d`/`1w`/`1m`/date, future, ≤ 1 year; waiting items only), `unsnooze`; `isSnoozed(item, now)` needs no write when the date passes. `promote()` labels own items "Your note" and drops the outside-text line only when every picked item is the user's; a chosen kind and any board go in as one `Kind: … · Board: …` line. Terminal: `kaizen icebox add|edit|kind|tag|board|snooze|unsnooze|boards` (text only from `--file`, stdin, or typed words; never built by an agent on the command line; `CLAUDECODE`/`KAIZEN_RUN_ID` mark a given kind `sorted: "agent"`). Route `/icebox` ops `add` (kind, board, client, tags), `edit`, `kind`, `tag`, `board`, `snooze` (`until`), `unsnooze`, behind the same `strict()` guard; `GET /sources` adds `kind`, `sorted`, `asleep` per item and a `boards` list. The board drops `asleep` items from the list, its count, Swipe and the side-menu number.
- `cli/browser.ts` — finds Chrome/Chromium/Edge, drives it over the DevTools protocol (Bun `WebSocket`, no dependency), reads posts by their links (`POST`), `login()`; `postLink()` and `sendReply()`/`replyOn()` post a reply (selectors per platform in `REPLY`). Its fixed waits (page settle, scroll passes, reply confirm) go through `nap()`, scaled by `KAIZEN_BROWSER_PACE` (default 1); `cli/browser.test.ts` runs at 0.1.
- `cli/chatgpt.ts` — Sign in with ChatGPT, judging read posts by number, and `draftReply()`; both go through `ask()`, the one streaming Responses call.
- `skills/kaizen/gather.md`, `skills/kaizen/discover.md` — the agent side.
- Terminal: `kaizen sources|gather|icebox` (and the icebox verbs above), `kaizen gather --posts <link>` (what the agent judges), `kaizen browser login [platform]` in `cli/install.ts`.

## How it connects
- Panels and routes in the [[Web board]] (`/sources`, `/icebox`, `/reply`, `/chatgpt`).
- Promoted items become tasks on the board, and tasks start [[Workflow]] runs. A promoted item leaves the Icebox list and shows under the Promoted category (like Dismissed and Done; the page's count is `status === "new"` only); `markDone()` (run on each `GET /sources` and by the write-back timer) sets it `done` once a done run has a request line equal to its task, and done items sit under the Done category beside Dismissed.

## Watch out
- Icebox ids are hashes of the item's text (`idOf`), made once. Anything that changes an item's text (`editItem`) leaves its id behind, so `addRow` salts the key until the id is unused; and write-back matches a gathered item to its sheet row by text, so a gathered item's text is not to be changed.
- Social gathers judge posts against what the project is for: `about()` in `cli/chatgpt.ts` sends the README (else the notebook Index), first 1500 chars, to ChatGPT; `gather.md` tells the agent the same. Without either, it falls back to generic "asks for something".
- ChatGPT answers only post numbers (`{ keep: [...] }`); the icebox text is the post's own as read. Never let the model write request text.
- The browser only opens the source link and post links on its platform or host (`readPage`); post links are found by URL shape, not CSS classes, so a platform redesign breaks less.
- `~/.kaizen/browser/` holds live sign-in cookies (0700). A visible login window locks the profile; a read meanwhile says to close it.
- The timed gather (`sources.every`) reads social sources through ChatGPT when `sources.agent` is `chatgpt` and it is connected; otherwise it skips them and only Gather reads them. TikTok often lays a closable captcha over posts it already shows: `readPage` clicks `#captcha_close_button` and reads on, failing only when no posts come through. Instagram opens each post page, so a 40-post read takes ~3 minutes.
- A source's "Auto gather" switch off sets `paused: true` in `sources.json` (`setPaused`, POST /sources `op: "paused"`): the timed gather skips it; Check now and Gather still read it.
- A source whose `seen` list is empty reports "no requests found", never "nothing new" (`record()`).
- A `github.com/<owner>/<repo>/issues` link is read from the public API (`exportUrl` kind `github`, `fetchText(..., json)`): open issues, pull requests dropped, notes `#n · link` only so an edited body is not a new item. Private repos answer 404; the 60/h unauthenticated limit answers 403 (shown as the sign-in note).
- `readPage` stops after 3 scans with nothing new only once some post was seen; an empty page scans all 12 rounds (~20 s), since TikTok can render its search late.
- `sift` finds a sheet's header by shape; test any change against a fixed set of sheet shapes, old vs new side by side (`.kaizen/memory.md`). A row with a blank first cell and blank status takes the status of the row above: the TSV export leaves merged NO/STATUS cells blank below their top row.
- A named request column (`DETAIL`) loses to a column holding over 3× its request-like text in open rows: some sheets name the page in `DETAIL` and write the request in `NOTES`.
- The Sources panel rebuilds on every action; controls need an id and an explicit step (`.kaizen/memory.md`).
- The Sources drawer stays shut until asked for (`srcShow`), even with no sources; the empty Icebox then says what it is for and offers Add a source, which opens the drawer.
- The Add a source form sits at the top of the Sources drawer, collapsed behind the header's Add button (`srcAdd`) once a source exists; it stays open across rebuilds while any field holds text, and closes after a successful add.

- Reply styles: only `promo` and `helpful` send the README to ChatGPT, so `casual`/`fun` cannot name the project. The style from the client is checked with `Object.hasOwn` (a plain lookup lets `constructor` through). The board keeps the style per project (`kz-reply-style:<dir>`) and shows the picker and Regenerate only when ChatGPT is connected.
- Replying posts publicly and cannot be undone. `/reply` `draft` writes nothing; only `send` with the user's text posts, and pressing the platform's send button stamps `replied` on the item even when the page never confirmed, so a retry cannot double post. `REPLY` selectors in `cli/browser.ts` are per platform and break on a redesign; the fixture test only covers the X shape. Threads replies in the inline composer under the post: its send is an icon button (`svg[aria-label="Reply"]`) that appears only once text is typed; there is no "Post" button unless the composer is expanded (issue #6). `FIND` looks for the send button nearest the box first (walking up from `[data-kaizen-box]`), then the last dialog, then the page.

- `cli/writeback.ts` / `cli/google.ts` — closing the loop. `writeBacks()` (run by a 60 s timer in `cli/web.ts`; page loads only read) reports each done item (`run`, `row` kept by `ingest`) to its source when `Source.writeback` is on: GitHub via `gh issue close --comment` (args as an array), sheets via the Sheets API (re-reads the row and compares its text first, finds or adds the `Status` header). `written` / `writeError` live on the item; failures retry, successes never repeat. Google OAuth uses the user's own Desktop client (`~/.kaizen/google.json`, 0600), set in Settings → Google; routes `/google`, `/google-callback`.
- `sift` in `cli/sources.ts` recognises a sheet header by shape (a label-only row in the first five non-blank rows with a `HEADER` or `Status` cell not repeated in that column); the Done/Finish skip only works where that succeeds. Test any change to it with: a `#` header cell, a one-word title (`Feedback`) above the header, an unnumbered type column, a repeated header, and a names or reply column longer than the requests.
- In `sift` (`cli/sources.ts`) loosening the header test trades one shape for another: judge any change by running a fixed set of sheet shapes through the old and new version side by side (copy `git show HEAD:cli/sources.ts` to a scratch file with its `./` imports made absolute), not by the new test alone.
- Since 2026-10-15-request-sources-icebox, gathering writes `icebox.json` (per state dir), never `inbox.md`; `promote()` in `cli/sources.ts` is the only path from gathered text to an idea and carries the `obeyed` command-word guard. Any new path into Ideas from outside text must go through it. Icebox dedup keys a row on its request text plus its other cells (`rowKey`), so two rows sharing a category-like request cell stay two items; a hand-typed idea still blocks any row with the same text (`ideaKey`).
- Social sources (x/twitter, tiktok, instagram, threads hosts, `socialOf` in `cli/sources.ts`) are never fetched: `gatherSource` records AGENT_ONLY and the agent fills them through `kaizen gather --stdin`. `kaizen gather` therefore exits 1 whenever a project has one.
- Instagram and Threads serve `/favicon.ico` with `Cross-Origin-Resource-Policy: same-origin`, so the board cannot load them as `<img>`; `fav()` in `web/board.html` draws the four social platforms from bundled sprite marks (`i-b-*`) and asks only other hosts for `/favicon.ico`. (2026-10-15-source-favicons)
- The ChatGPT-plan Responses API with `store: false` sends `response.completed` with `output: []`; the answer exists only in `response.output_item.done` events (`gatherSource` in `cli/chatgpt.ts`). A fake stream that puts the answer in `completed` passes tests while the real thing fails.
- Since 2026-10-15-browser-social-gather, social sources are read by kaizen's own headless Chromium (`cli/browser.ts`, profile `~/.kaizen/browser/`) when the board's Gather goes through ChatGPT or `/kaizen gather` runs `kaizen gather --posts`; `cli/sources.ts` `gatherSource` (timer, `kaizen gather`) still records AGENT_ONLY. Web search (ChatGPT `web_search`, `site:` queries) found zero posts on X, TikTok, Instagram and Threads alike — do not go back to it.
- Chromium's `SingletonLock` is a dangling symlink: `existsSync`/`readFileSync` say it is absent; only `lstatSync` sees it. A second Chromium on a busy profile hands its URLs to the running one and exits at once.
- Browser tests that spawn a fixture server in the test process must run the reader with async `Bun.spawn`; `spawnSync` blocks the event loop and the page never answers. CI's windows-latest has Chrome, so browser tests run there: guard Linux-only tools (`ss`, `pgrep`).
- Replies to gathered posts (`/reply`, 2026-10-15-icebox-reply) post publicly through `replyOn` in `cli/browser.ts`; tests must only drive it against a local fixture with an explicit platform, never a real post link. `postLink()` is what decides an icebox item is a social post; a send that pressed the platform's button stamps `replied` even unconfirmed, by design.
- Fixing a broken `REPLY` selector: probe the real page through `browse()` in the kaizen profile, type with `Input.insertText` and dump the buttons, but never click send. Threads (2026-10) replies inline under the post; its send icon only renders once text is typed, so dump after typing.
- Headless Chrome under a scratch HOME/USERPROFILE never starts on Windows runners and never answers Page.navigate on macOS; browser tests keep the profile in the scratch home but hand Chrome the real home. `Bun.spawn` without `env` passes the process's startup environment, not later `process.env` edits. (2026-10-15-ci-macos-windows)
