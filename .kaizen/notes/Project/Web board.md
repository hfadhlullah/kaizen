# Web board

## What it does
`kaizen web` runs a loopback HTTP server over `cli/state.ts` and serves one HTML page that only ever sees JSON (header of `cli/web.ts`). From it you start runs, approve or revise plans, pick findings to fix, commit and push, and open Notes, the icebox and settings. User-facing tour: `docs/guide.md` ("In a browser"). Look and feel: `design.md`.

The visible menu is Home, Icebox, Ideas and Board, then the Projects list, with Settings, Report an issue, Keyboard shortcuts and a single sun/moon theme toggle on one bottom row; Video remains at `/video` without a menu entry. Sizes follow Orca's scale through tokens on `:root` (same line in board/notes/video.html): `--row` 28px (rail items, Projects rows, run tabs), `--row-h` 32px (project group header), `--ico`/`--ico-s` 14/12px, `--btn-xs`/`--btn-s`/`--btn` 24/32/36px (`.theme button`, `.psec button`/`.rib`, `.rbtn` 24; `.ib`, `.btn` min-height 32), `--tabbar` 36px, `--pane-h` 24px (split pane header), `--fs-xs/-s/-l` 11/12/14px with `--fs` 13px, `--gap` 6px, `--padx` 8px; the rail is 280px; phone sizes are untouched. Radii were deliberately not taken from Orca. On wide screens only the centre panel is rounded (12px; everything else 4px) and the side menu and footer sit flat on the outer canvas with no borders. The other session's right project pane (`#context`, Files/Notes/Terminal) is hidden on desktop by one rule in `board.html` (`@media(min-width:641px){#context,#ctx-open{display:none!important}}`) and an override restores the Board's five columns over its three-column rule; its markup and `context.ts` are untouched, so reconcile both when that work lands. Selecting a card on the Board still opens the detail drawer; the drawer never shows the agent terminal (`#pterm` hidden, `panel.ts`), only the run view's centre tab does. On phones (max-width 640px) the bottom tab bar is Home, Chat, Runs and Settings only: the Board, Ideas and the Icebox are set up on a computer, and `go()` sends a phone asking for them to Home; a card opened on a phone opens its run workspace. Phone Home (`web/board/phone.ts`, `#phome`) lists Devices (this computer with project/active/waiting counts, then the other Tailscale computers from `/phone`'s `self`/`computers`, a tap opening `https://<tailnet name>/`), the 12 most recent runs and usage; Runs (`?view=device`) groups this computer's runs Waiting on you / Active / Done. Chat is `?view=chat` (desktop folds it into Home). The usage footer and the side-panel button are hidden on phones; the header is one row, title and one action. The rail's phone CSS sits inside the shared side-menu block, so notes.html and video.html carry it too. The top-left wordmark is smaller, and the new-idea planning details field is taller and labelled.

## Where it lives
- `cli/web.ts` — the server: routes such as `/state`, `/run`, `/backlog`, `/decide`, `/fix`, `/commit`, `/events`, `/vault`, `/pty`.
- `cli/web.ts` also serves `/project-tree` and `/project-text` for registered projects. The tree is one level at a time and skips hidden/generated entries and symlinks; text preview is capped at 64 KiB and downloads are plain-text attachments. `cli/project-tree.test.ts` checks path and content boundaries. `web/board/context.ts` draws the right-side Notes, Files and Terminal session list; Notes open in the existing notebook editor.
- `cli/install.ts` dispatches `docs lint` before the default terminal board starts; it adds no web route.
- `cli/state.ts` — everything kaizen knows about a project's `.kaizen/`, shared with the [[Terminal board]]: runs, cards, findings, backlog, git, launching agents.
- `cli/pty.ts` + `web/term.ts` — the in-card terminal (agent runs inside the board). Bun has no PTY on Windows, so there `cli/conpty.ts` runs a ConPTY host: Windows PowerShell compiles C# with `Add-Type` and talks to the board over pipes. Resize is the in-band `ESC]kzr;c;r BEL`, and the agent runs under an inner `powershell -EncodedCommand` so `.cmd` shims resolve. When that agent ends, the footer offers Resume: `/resume` continues an in-flight run with a prompt, and on a waiting or done run reopens its conversation with nothing sent (refused when none is on disk). `launchRun` drops inherited Claude Code session variables (`CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, …): a board started inside a Claude session would otherwise launch child agents that save no transcript, leaving nothing to resume (#14). While the agent sits on a question (`asking()` in `cli/pty.ts`: Claude Code / Codex prompt text, read after 700 ms of quiet, only output since the last keystroke, and not when an agent's working line (`WORK`: Claude Code `(Ns ·`, Codex `•`/`esc to interrupt`, Gemini `(esc to cancel, N`, opencode `esc interrupt`; never a bare "Esc to cancel", Claude's question footer) follows the last question — a redraw used to keep it amber for a minute) `/state` carries `pty.asking` and the card shows an amber `i-ask` mark. A decision on a run started in Yolo keeps Yolo (`launchRun`). A conversation that opens another run (a follow-up) hands its session to that run: `ownerOf()` (`cli/state.ts`) gives a launch to the newest run that recorded its conversation id after it started, ahead of the run it was launched for, unless that run is still in flight, so the new card gets the terminal and Resume; the parent can still resume that conversation (`firstSession`). xterm.js has no touch scrolling, so `web/term.ts` turns a swipe into `scrollLines`, or into SGR wheel reports when the agent tracks the mouse (a full-screen Claude Code does). It renders with `@xterm/addon-webgl` (the DOM renderer lagged on constant redraws; context loss falls back to DOM), and resizes are debounced 100 ms since each makes the agent redraw. `@xterm/addon-web-links` makes URLs clickable (new tab) and `@xterm/addon-search` backs a `.termtools` strip top-right of every terminal: ⌕ opens a search box (Enter/Shift+Enter, Esc; Ctrl/Cmd+Shift+F from the terminal), plus Paste when there is no phone key bar. On a phone (`pointer: coarse`) the terminal gets a swipeable chip row (1 2 3 Esc ^C arrows ↵ ⇧⇥ Ctrl Alt ⋯; keys fire on click, not pointerdown, so a swipe of the row presses nothing; Ctrl opens an a–z pad, ⋯ holds Search, Paste, Raw keyboard) and a message box whose Send types the text and presses Enter 60 ms later, so a TUI does not take it as a paste. The run panel header shows a Plan → Build → Review → Done step bar (`steps()` in `web/board/panel.ts`; abandoned runs and ideas keep chips); with the terminal open the panel is 62% wide above 900px, full width on phones. `/file` serves a card's `attachments/` only; in Preview and notes, `attach()` (`web/board/markdown.ts`) rewrites those links and shows any other relative link as its path, since it would open the board's "not found". A plain left click on a `/file` or `/ice-image` link opens it in a `<dialog>` over the board (`web/board/viewer.ts`: `<img>` for images, else an `<iframe>`), with Open in new tab beside Close; a modifier or middle click keeps the browser's tab.
- Child cards: a card whose `parent` (from a `Parent:` / `Follow-up of:` line, `parentOf` in `cli/state.ts`) names a run on the board that is not archived and not done is drawn only as a row inside that run's card (`kidsOf`/`nested` in `web/board/cards.ts`): a collapsed `N children · M done` toggle, an orange dot when a child waits on you, and rows that open the child's own panel; a run row is labelled with its run name (like the card header), wrapped, title in the tooltip. Once the parent is done, archived or gone, children are back in their own columns.
- Ideas column tabs (`ideasTab` in `web/board/cards.ts`, kept as `kz-ideas-tab`): the column's title is two icon tabs with counts, **Ideas** (default, `s-idea`) or **Backlog** (`i-clock`), never mixed; the selected tab also shows its word. An empty Ideas list shows the hint "Add an idea to start a run" (`HINT[0]`). Backlog lists `backlogCards()` (`cli/state.ts`, sent as `/state` `backlog`, outside `boardCards()` so its pinned order and the terminal board are untouched): the open lines of every non-abandoned run's `06-backlog.md` plus the orphanage `backlog.md`, most severe first; a filter icon in the header (Backlog only) opens a severity menu (High+ · Medium · Low · No severity, from `parseItem`, which reads `<where>: <sev>: …` with ranges/backticks in the place, `1. <sev> — …`, and a bracketed tag such as `Finding 1 (medium)`, `(review 2, low)` or `[low]`, never a severity loose in prose; `store.sevMenu`, closed by the outside-click handlers in `main.ts`/`keys.ts`). A card is (state, source run or `orphan`, n), n numbered as `backlogLines()` numbers them, the same numbering notebook `#backlog-N` links use. Clicking opens the source run's Backlog tab with the item marked (`openAt` in `panel.ts`). Run posts `/run` with `backlog: {source, n}`: the server reads the line itself and launches with notes `Parent: <source>`, `Backlog: <source>#<n>` (and `Backlog item: <raw line>` when tidy shortened it). `startedBacklog()` finds those lines in run requests: a live child hides the card, an abandoned one gives it back, and `markBacklogDone()` (60 s loop beside `markDone`) rewrites the source line to `done: … | <child id>` once the child is done. Reject posts `/backlog` `{op: "reject", source, n, reason}` and writes `rejected: … | reason` in place (`closeBacklog`, raw bytes so CRLF/BOM survive). Lines are never removed or reordered.
- "Back to idea" on a run card still in Planning (card menu, `web/board/cards.ts`) posts `/to-idea {id}`: `runToIdea()` (`cli/state.ts`) refuses unless `stage` is `plan`, then `abandonRun` + `setArchived`, and writes the idea back open with a fresh `added` stamp (the `started` inbox line the request contains, notes kept; else the request's first line minus `/kaizen [mode]`). The fresh stamp is what stops the old run retiring it again; a run whose request is under 2 s old still would (`after()` slack in `boardCards`).
- Add sheet (since run 2026-10-29-board-new-project-form; `openAdd()` in `web/board/add-project.ts`, modelled on Orca's "Add a project"): the Projects header `+` (`#padd`, `initRail()` in `web/board/workspace.ts`, no longer New idea: that lives on the Ideas/Board header button) opens a chooser, Existing folder, then "Other ways to add": Clone from URL, Create new project, New workspace (only when a git project exists), each a form with Back to add options and an inline `.err` line. The project picker's "New project…"/"Clone…" and a project row's `+` open the same sheet (`start: create|clone|ws`). A project added lands via `localStorage kz-proj` + reload (the sheet says "Project added/created/Cloned/already added" for 0.9 s first). Server side, all in `cli/web.ts` before the generic POST block (which would `canonState()` a `..` away) and all `strict()` (same host:port, JSON content type), argv only, validators in `cli/add-project.ts`: `POST /add-project {path}` (existing folder, `.kaizen` made, `already` true when registered), `POST /new-project {name,to,git,check}` (folder + `.kaizen` + `git init -q -- <to>`, a failed init is reported as `git:false`, not rolled back; non-empty target 409), `POST /clone {url,to,check}` (`cloneInto()`: `git clone -- url to`, `GIT_ALLOW_PROTOCOL=https:ssh`, no prompts, ssh BatchMode, 5 min kill, a folder it made is removed on failure; `gitUrl()` takes only `https://`, `ssh://`, `user@host:path`, host letters/digits/dots/dashes not leading `-`, no credentials, no `..`; ext::, file:, git://, http://, local paths refused), `GET /branches?dir=` (known project only; `branchesOf()`: `for-each-ref` local + origin, `def` = origin/HEAD, else main/master, else current), `POST /worktree {dir,branch,base?}` (base must be one of `branchesOf()`, never option-like; `git worktree add --no-track -b <branch> -- <path> <base>`). `destDir()` refuses root, home, `~/.kaizen`, any `.git`/`.kaizen` segment, `..` in the text, Windows-bad names and any place below a known project or a folder with a `.kaizen` (a nested `.kaizen` shadows the outer project's runs; home's own `.kaizen` is exempt). Tests: `cli/add-project.test.ts` (validators, branchesOf, cloneInto with an injected spawn and, with the protocol list opened, a real local repo), guards and happy paths in `cli/usage.test.ts`. Not done: a clone's progress, sparse checkout, setup scripts, hosts; the old `kz-new-idea` listener in `main.ts` has no sender now.
- Home (`/`, the default view; Board moved to `/?view=board`): `web/board/home.ts` + server `cli/chat.ts`. Chats live in `~/.kaizen/chats/<id>.json` (id `^[\w-]{1,80}$`), each with an optional `project` (a state dir the board lists). Each message runs `codex exec --json --skip-git-repo-check -s workspace-write --add-dir <each other listed project folder> -m gpt-6-luna -c model_reasoning_effort=medium [resume <thread>] -` in the project folder, or in `~/.kaizen/chats/scratch` with no project, so the agent reads and edits any listed project by path without switching; this Home chat model and effort are fixed independently of per-project agent settings. The message goes on stdin after `brief()` (the chat's project, the board's projects, every listed project's runs with `awaiting` set via `readRuns`, where run files live, how to move, kaizen exists), with `CHILD_ENV` scrubbed. The agent moves a chat with a line `[[kaizen:project <folder>]]` or `[[kaizen:new-project <name>]]`: stripped from the reply (`takeMoves`), applied after the turn by `moveChat` — only to a listed project, or created by `makeProject` (`cli/web.ts`, shared with `POST /new-project`) — streamed as a `project` event and a `project` step; the page then `pick`s that project so the board follows. For development the brief makes the agent ask first: a kaizen run (lite/full, an installed agent from `board.agents`, a project) or handle it in chat. A line `[[kaizen:run <project> | <lite|full> | <agent> | <request>]]` is stripped by `takeMoves` and applied by `startRun` through `board.run` (`launchRun` as `POST /run` does), only for a listed project and installed agent; it adds a `project` step and a `run` event and does not move the chat. Routes `GET /chats`, `GET /chat?id=`, `POST /chat` (`{id, text, project}`, NDJSON: `chat`, `text`, `step`, `project`, `error`, `done`), `/chat/stop`, `/chat/delete`. One turn per chat; a turn outlives the page. Stop also cancels the stdout reader. Run ids the agent names that are cards become "Open <id>" buttons. The chat list is a panel toggled at Home's top left (`kz-hist`; a drawer on phones, toggled by `#hsidetop` beside the header title, with the `.htop` row hidden, "New chat" icon-only, and a fresh chat laid out chat-app style: greeting centred, one swipeable chip row and the input at the bottom); only messages new since the last draw animate (`seen`), the first send is a view transition (`view-transition-name: hbox`). Phone bar: Board, Notes, Home (center), Terminal, More (Icebox, Video, Settings), by CSS `order`.
- Chat popup (`GET /popup`, `web/popup.html`, inline script with no build step): a minimal window on the same `/chat` routes, plain text only, last chat kept in localStorage `kz-popup-chat`, Esc closes it. `kaizen chat [--port N]` (`cli/install.ts`) starts the board daemon when it is down and opens Chromium `--app=…/popup` with its own profile `~/.kaizen/chat-window`. On Hyprland it floats, pins and puts the window bottom-right by address, Lua grammar first and then the classic one, as Hermes's HUD does. Chromium on Wayland ignores `--class`, so the window is found by class prefix `chrome-127.0.0.1__popup`. Running it again while the window is open kills that window: one hotkey toggles it. When `python3 cli/chat-window.py --check` passes (GTK 3 + WebKit2GTK 4.1), the window is that see-through WebKitGTK shell instead (class `kaizen-chat`); Chromium windows are always opaque. The page is transparent: shadowed bubbles that pop in, a pill input, buttons top-right. Handoff with Home: Home's `#hpop` icon (desktop widths) posts `/popup/open {id}`, which runs `kaizen chat --show --chat <id>` (opens `/popup?chat=<id>`, never toggles closed), moves the active board window (title `kaizen`) to `special:kaizen` and focuses the popup. The popup's back icon posts `/popup/board`: the board window hidden in `special:kaizen` (else any) comes to the active workspace and is focused — `xdg-open /` when none — then `kaizen chat --close` closes the popup, saving its position. Back also sends the popup's chat id; the server keeps it until `GET /popup/handoff` takes it, and Home (web/board/home.ts) polls that every 1.5 s while Home is shown — a window returning from a special workspace fires no focus event — and opens that chat. Both routes trust their caller: the server is loopback-only, but Tailscale serve forwards to it. Buttons are a round icon rail beside the chat. Its grip handle posts "drag" to `window.webkit.messageHandlers.kaizen`; `chat-window.py` answers with `begin_move_drag` (the handle hides in Chromium). `kaizen chat` saves the window's Hyprland position to `~/.kaizen/chat-window.json` when it toggles it closed and reuses it while it lies on a connected monitor; Esc closes without saving. Setting `board.chat_hotkey` (global, text, default `SUPER + ALT + SPACE`): `bindChatHotkey` in `cli/settings.ts` writes a marked block into `~/.config/hypr/bindings.lua` (`pcall(hl.unbind…)` + `o.bind`) or `hyprland.conf` (unbind + bind); runs on save and from `kaizen chat` when no block exists yet. Keys are validated before they reach the Lua/conf file.
- `web/board.html` — the page: markup, CSS, the side-menu script, and the notifier marker.
- Side menu (identical markup and CSS in `board.html`, `notes.html`, `video.html`; `cli/notes.test.ts` holds them equal): Home, Icebox (inbox-tray icon, `#rail-srcs` source icons and `#ice-n` count of `new` items), Ideas, Board, then the Projects list (`#plist`) and Settings + Report an issue + Keyboard shortcuts (`#kbd`, hidden on notes/video) at the bottom. The rail's own icons are `r-*` symbols inside the `<nav>`. `web/board/workspace.ts` draws it on all three pages: `onBoardCards()` in `badge.ts` hands it the cards of the badge's `/state?all=1` fetch (or the board's own all-projects cards), so no extra `/state`; `/sources` is fetched at most every 30 s. Rows: ideas plus unarchived runs, done/abandoned only for 24 h after `moved`; state icon `.si` (`stateOf`: idle/plan/build/review/wait/done/stalled/aband) and `subline()` (stage word plus awaiting label or age; no step or round counts, the data has none). Rows sort by state (waiting, planning, building, reviewing, stalled, idea, done; newest first) and projects by their most urgent card; each row is one 28px line: title, then the subline in small mono at the right. The filter button opens a popover (All projects + a checkbox per project with search past 6, Active runs / Ideas / Done toggles; a dot while filtered; saved per browser). Every + New idea (rail, Ideas, workspace) opens the form over the current page and stays there; the modal shows the project picker unless one project is pinned, preset to the page's project, and refuses Add until one is chosen. A row is the board's deep link (`?dir=&run=`/`&idea=`); on the board the `kz-open-card` event opens the card in place instead (a row of a project other than the picked one first switches the board to it with `pick()` from `projects.ts`, since `/state` holds only the picked project's cards), `kz-new-idea` likewise for +.
- Projects list = workspaces (since run 2026-10-29-board-workspace-sidebar; `drawList()` in `web/board/workspace.ts`): every project from `/state` `projects` with its `workspaces` (`workspaces()` in `cli/worktree.ts`: `git worktree list --porcelain`, main checkout first as the registered folder, prunable/bare and detached-outside-project skipped, real paths, 10 s cache; a non-git folder is one "workspace"; the global queue is its own). No run rows. Each `/state` run card carries `ws` (`wsOf()`: its `state.json` `worktree` while on disk, else the project); the rail puts a card whose `ws` is not listed, and every idea, under the main checkout (`wsOfCard`), so a waiting run never vanishes. A row: `stateOf` dot of its most urgent listed card, count of the runs the panel's picker lists (`pickable()`: waiting + active, a button that opens the picker, a sibling of the row's link inside `div.wsr`, not nested in it), link `/?view=ws&dir=&ws=`. A ws address opens the workspace centre (next bullet); `markCurrent()` lights the ws row, also for an old `?view=run&id=` link. Filter "done" = workspaces holding only finished runs. The project row's `+` (git projects, hover) opens the add sheet's New workspace form (project, branch name, base branch) → `POST /worktree {dir, branch, base?}` (`strict()`, registered non-global dir, `addWorktree()`: `git check-ref-format --branch`, no leading `-`, `git worktree add -b <branch> <project>/.kaizen/wt/<slug>`, argv only).
- Workspace centre (since run 2026-10-29-board-workspace-centre; `?view=ws&dir=&ws=`, `web/board/run-view.ts` with the pure parts in `web/board/ws-tabs.ts`): one centre per workspace, its saved layout under `kz-runtabs` key `ws:<dir>:<path>` (`wsKey`). `migrate()` moves old per-card keys (`run:`/`idea:`) into their workspace once, merging tabs, hidden ids and screens (an item stays in one screen); a key no card on the board owns is left alone. **Runs are not tabs** (run 2026-10-29-board-run-picker-panel): the centre holds only terminals and the Browser. Tabs: for each live run (`liveIn()`: not archived, not `finished()`; a `done` run with `accept: "needs"` still counts) and each idea with an open agent, its terminals (`stageTabs()`: a terminal a stage claimed is titled `Plan · Claude Code`, `Build · …`, `Review · …`, the rest keep the agent's name, numbered when several; ids `agent:<pty key>`), shells whose `run` is that run's key, and the `wait:` note; then the workspace's own shells (`/shell {ws, run: <ws key>}`; the server stores `ws` on each shell record) and tabs opened by hand (Browser, Preview, notes, History). Saved `kind:"run"` tabs and `rn:` hidden ids from older layouts are dropped in `saved()`. Nothing about run tabs is stored server-side: `kept.json`, `POST /kept`, `readKept`/`setKept` and `Run.kept` are gone (a stale `kept.json` is ignored). One xterm per tab, mounted once per pane. **The run panel** `#panel` stays docked in `.app`'s right column (340px, icon strip inside) and shows one run, picked in the picker at the top of its header (`web/board/run-pick.ts`: `#ppick` trigger with the run's state dot and title, `#ppop` popover, class `.ppop`/`.pk`, not `.menu-pop`, which `main.ts` removes on an outside press). `pickable()` lists the runs not over, waiting on you first (`awaiting()`), then newest; a History group at the bottom lists `historyOf()` (done/abandoned, newest first, shown read-only: panel class `ro`, whose CSS hides only the edit buttons (Archive/Restore/Resume/Abandon/Approve); the git buttons stay). A done, approved run whose `/state` card `git` mark is `pending` (commit or push still to do; `gitDue()`) is not `finished()`: it stays pickable, counts as `awaiting()`, shows `stateOf` `wait` (via `gitDue()`, so an archived run does not) and "waiting on you · commit" or "· push" (the card's `gitDue` field from `cardsGit`'s optional `due` map: `commit` while files are changed, `push` once committed and ahead; `dueWord()`) until the mark turns `pushed`, then moves to History. `chosen()` keeps the pick (`picked` map per workspace key, sticky) while it is still pickable or History, else the first of the list (the waiting run, else the newest), else none: the panel is then `parked` (`display:none`) and `#rside` hidden, so the terminal is full width. A run that starts waiting later does not replace the pick: the trigger gets an amber `.pdot`, and with the panel collapsed `#rside` gets `data-dot` (desktop collapsed = `rflip`, phone collapsed = no `rflip`); the panel never pops open. Picking a run, or the panel's Plan / Work / Review strip, never touches the centre. `mountPanel()` calls `open(c)` only when `store.openKey` differs. An address `?view=run&id=` or `&idea=` resolves to the card's workspace (`wsOfCard`) and sets that run as the pick on every navigation; a fresh visit to a workspace (another workspace or another page before) drops the old pick, so waiting-first applies again; one made during the visit stays; (`showRunView(nav)`; a `/state` refresh does not), a finished one read-only. The side menu's row count is a `button.wcount` (sibling of the row's `<a>`, laid over its right end) showing the picker's size; it fires `kz-pick-run {dir, ws}` (answered in `initRunView`: opens the workspace, expands the panel, drops the picker down; the notebook and video pages, which do not answer, just open the workspace). The tab bar's `#rside` collapses the panel (`rflip`, a width slide). Phones (≤640px): the panel is a bottom sheet opened by `#rside` (sticky at the bar's right, 44px; `rflip` means open there, closed on desktop) and closed by its `#pclose` (which also shuts the picker); picker trigger and rows are 44px. A workspace with no tab at all opens a plain shell (`POST /shell {dir, ws, run: <ws key>}`, no agent) once per visit; "New agent here" in + starts the default agent. Tab titles cap at 180px with an ellipsis. Settings in the side menu is the gear icon only. A live run with no agent terminal still resumes its recorded Claude session (`openAgent(c, false, false)`, `ws` sent).
