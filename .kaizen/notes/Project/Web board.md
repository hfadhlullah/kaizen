# Web board

## What it does
`kaizen web` runs a loopback HTTP server over `cli/state.ts` and serves one HTML page that only ever sees JSON (header of `cli/web.ts`). From it you start runs, approve or revise plans, pick findings to fix, commit and push, and open Notes, the icebox and settings. User-facing tour: `docs/guide.md` ("In a browser"). Look and feel: `design.md`.

## Where it lives
- `cli/web.ts` — the server: routes such as `/state`, `/run`, `/backlog`, `/decide`, `/fix`, `/commit`, `/events`, `/vault`, `/pty`.
- `cli/state.ts` — everything kaizen knows about a project's `.kaizen/`, shared with the [[Terminal board]]: runs, cards, findings, backlog, git, launching agents.
- `cli/pty.ts` + `web/term.ts` — the in-card terminal (agent runs inside the board). Bun has no PTY on Windows, so there `cli/conpty.ts` runs a ConPTY host: Windows PowerShell compiles C# with `Add-Type` and talks to the board over pipes. Resize is the in-band `ESC]kzr;c;r BEL`, and the agent runs under an inner `powershell -EncodedCommand` so `.cmd` shims resolve. When that agent ends, the footer offers Resume: `/resume` continues an in-flight run with a prompt, and on a waiting or done run reopens its conversation with nothing sent (refused when none is on disk). `launchRun` drops inherited Claude Code session variables (`CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, …): a board started inside a Claude session would otherwise launch child agents that save no transcript, leaving nothing to resume (#14). While the agent sits on a question (`asking()` in `cli/pty.ts`: Claude Code / Codex prompt text, read after 700 ms of quiet, only output since the last keystroke, and not when an agent's working line (`WORK`: Claude Code `(Ns ·`, Codex `•`/`esc to interrupt`, Gemini `(esc to cancel, N`, opencode `esc interrupt`; never a bare "Esc to cancel", Claude's question footer) follows the last question — a redraw used to keep it amber for a minute) `/state` carries `pty.asking` and the card shows an amber `i-ask` mark. A decision on a run started in Yolo keeps Yolo (`launchRun`). A conversation that opens another run (a follow-up) hands its session to that run: `ownerOf()` (`cli/state.ts`) gives a launch to the newest run that recorded its conversation id after it started, ahead of the run it was launched for, unless that run is still in flight, so the new card gets the terminal and Resume; the parent can still resume that conversation (`firstSession`). xterm.js has no touch scrolling, so `web/term.ts` turns a swipe into `scrollLines`, or into SGR wheel reports when the agent tracks the mouse (a full-screen Claude Code does). It renders with `@xterm/addon-webgl` (the DOM renderer lagged on constant redraws; context loss falls back to DOM), and resizes are debounced 100 ms since each makes the agent redraw. `@xterm/addon-web-links` makes URLs clickable (new tab) and `@xterm/addon-search` backs a `.termtools` strip top-right of every terminal: ⌕ opens a search box (Enter/Shift+Enter, Esc; Ctrl/Cmd+Shift+F from the terminal), plus Paste when there is no phone key bar. `/file` serves a card's `attachments/` only; in Preview and notes, `attach()` (`web/board/markdown.ts`) rewrites those links and shows any other relative link as its path, since it would open the board's "not found". A plain left click on a `/file` or `/ice-image` link opens it in a `<dialog>` over the board (`web/board/viewer.ts`: `<img>` for images, else an `<iframe>`), with Open in new tab beside Close; a modifier or middle click keeps the browser's tab.
- Child cards: a card whose `parent` (from a `Parent:` / `Follow-up of:` line, `parentOf` in `cli/state.ts`) names a run on the board that is not archived and not done is drawn only as a row inside that run's card (`kidsOf`/`nested` in `web/board/cards.ts`): a collapsed `N children · M done` toggle, an orange dot when a child waits on you, and rows that open the child's own panel; a run row is labelled with its run name (like the card header), wrapped, title in the tooltip. Once the parent is done, archived or gone, children are back in their own columns.
- Ideas column tabs (`ideasTab` in `web/board/cards.ts`, kept as `kz-ideas-tab`): the column's title is two icon tabs with counts, **Ideas** (default, `s-idea`) or **Backlog** (`i-clock`), never mixed. Backlog lists `backlogCards()` (`cli/state.ts`, sent as `/state` `backlog`, outside `boardCards()` so its pinned order and the terminal board are untouched): the open lines of every non-abandoned run's `06-backlog.md` plus the orphanage `backlog.md`, most severe first; a filter icon in the header (Backlog only) opens a severity menu (High+ · Medium · Low · No severity, from `parseItem`, which reads `<where>: <sev>: …` with ranges/backticks in the place, `1. <sev> — …`, and a bracketed tag such as `Finding 1 (medium)`, `(review 2, low)` or `[low]`, never a severity loose in prose; `store.sevMenu`, closed by the outside-click handlers in `main.ts`/`keys.ts`). A card is (state, source run or `orphan`, n), n numbered as `backlogLines()` numbers them, the same numbering notebook `#backlog-N` links use. Clicking opens the source run's Backlog tab with the item marked (`openAt` in `panel.ts`). Run posts `/run` with `backlog: {source, n}`: the server reads the line itself and launches with notes `Parent: <source>`, `Backlog: <source>#<n>` (and `Backlog item: <raw line>` when tidy shortened it). `startedBacklog()` finds those lines in run requests: a live child hides the card, an abandoned one gives it back, and `markBacklogDone()` (60 s loop beside `markDone`) rewrites the source line to `done: … | <child id>` once the child is done. Reject posts `/backlog` `{op: "reject", source, n, reason}` and writes `rejected: … | reason` in place (`closeBacklog`, raw bytes so CRLF/BOM survive). Lines are never removed or reordered.
- "Back to idea" on a run card still in Planning (card menu, `web/board/cards.ts`) posts `/to-idea {id}`: `runToIdea()` (`cli/state.ts`) refuses unless `stage` is `plan`, then `abandonRun` + `setArchived`, and writes the idea back open with a fresh `added` stamp (the `started` inbox line the request contains, notes kept; else the request's first line minus `/kaizen [mode]`). The fresh stamp is what stops the old run retiring it again; a run whose request is under 2 s old still would (`after()` slack in `boardCards`).
- Project picker "New project…" (`web/board/projects.ts`): a dialog with the name and a location (Pick…); `POST /new-project` (`cli/web.ts`) puts it in the Projects folder setting else `~/Projects`, or a typed/picked `to`, refuses a non-empty folder and any name Windows cannot hold (path characters, trailing dot or space, CON/NUL/COM1…; checked on every platform, at Create only, and on the last segment of a typed location), reports a failed mkdir as a message, makes the folder and `.kaizen`, registers it, and the page switches to it. Find (`/find`) only registers folders that already have `.kaizen`, so this is how a brand-new folder gets onto the board.
- Project picker "Clone from GitHub…" (`web/board/projects.ts`) opens a `<dialog>` (`modal()` in `web/board/dom.ts`) with the https/ssh link, the destination and a Pick… button; `POST /clone` (`cli/web.ts`, link checked by `githubRepo()` in `cli/sources.ts`) runs `git clone -- <link> <dir>` as an argv array with `GIT_TERMINAL_PROMPT=0` and ssh `BatchMode`, into the Projects folder setting else `~/Projects` (`check: true` returns that default; the page lets the user edit it, or leave it empty to pick a parent folder with `/pick-folder`; a typed `to` may use `~` and is resolved against home), makes a missing folder and its parents, refuses an existing non-empty one, makes `.kaizen`, registers the project, and the page switches to it.
- `web/board.html` — the page: markup, CSS, the side-menu script, and the notifier marker.
- Video page (`/video`, `web/video.html` + `web/video.ts` bundled to `web/video.js`, server side `cli/video.ts`): the kaizen-video skill's folders as a library. Places are the library folder (`board.video_dir`, default `~/.kaizen`) then every known project with a `videos/` folder; the page names one by index, a video by folder name (`okName`), and a file by `/video/f/<place>/<name>/<v|o>/<path>` (v = `videos/<name>/`, o = `output/<name>/`), each resolved through `inside()` (realpath, no `..`, no symlink out). `GET /video/list`, `GET /video/film`; `POST /video/save` (only `title`/`sub`/`kick`/`items` of existing beats plus `platforms`, atomic write, then a build), `/video/job` (`build`/`preview`/`render`; render = one `make_film.py --format <f> --render` per shape the platforms need), `/video/cancel`. Jobs are one global queue run with `Bun.spawn` argv arrays and `env: process.env`, output in `videos/<name>/.kaizen-job.log`, state pushed through `changed()`. The editor's Versions list starts with the Draft (the live build) and then each rendered file labelled by its preset (`output/<name>/<preset>/`); clicking one plays it in the player (the draft as the built page, a file as a plain `<video controls>`). A rendered row can be deleted (`POST /video/delete` → `deleteOutput`: only a listed finished MP4 plus its srt/thumb, never during a job or send). Render final hides while a version is shown, and reads "Rendered" when a render in the draft's preset is newer than the draft's build (`Output.at`, `Video.builtAt`); the page re-reads the list every 5 s while a video is open, since the board does not watch video folders. The built `film/index.html` is served with a small player injected (`window.__kz`: play/pause/seek driving `__timelines.main` from a clock and starting each `<audio data-start>`), shown in a scaled iframe; the page talks to it with `postMessage`. `KAIZEN_VIDEO_SKILL` points the scripts at another skill copy (tests use a fake one). The side menu's Video item is in board.html, notes.html and video.html; the rail test holds all three equal. New video / Ask Claude: `GET /video/presets` (film presets have `style.json`, footage ones `index.html`, template ones `preset.json`; a preset folder with a `.hidden` file comes back with `hidden: true` and the form leaves it out; a template preset is offered only for a brief, and its request points the agent at `references/promo.md` and `make_promo.py`; a footage preset only for footage (`requestFor` refuses one on a brief); a film preset under either start, tagged with its kind, and a cross pick adds a line telling the agent the build script bridges engines; a brief start takes an optional assets folder, checked like the footage folder, that the request says to copy into `videos/<name>/inputs/` for `intake.py`), `POST /video/new` and `/video/ask` build the request in `requestFor()`/`askFor()` from whitelisted values only (the brief or the user's words go between `<<<`/`>>>` as data) and call `launchRun(..., { skill: "kaizen-video", cwd: <place>, card: true })`: the prompt starts `/kaizen-video` (other agents are told to use the skill), the agent runs in the place's folder, and with `cwd` set the folder is not `remember`ed as a project; a session record is written only where the folder has a `.kaizen` (a project place, not the library). `noteAgent()` ties the terminal key to the video; `/video/list` returns `agents` (alive, asking, from `ptyState`), and the page mounts that terminal (`/term.js` `kzTerm`) in `#dock`, which sits in the editor's right column behind a Form/Terminal tab (Form by default; the tab gets a marker while the agent asks). `#dock` is parked outside `#editbody` while the editor redraws, then put back, so the session survives; the terminal starts only when its tab is shown, since one started hidden draws nothing. Send (`#sendp` under the editor, drawn only on the user's own actions so a `changed` event never wipes a message being typed; `drawSendState` redraws the status and recent sends): `GET /video/devices[?fresh=1]` runs `localsend.discover()` (multicast announce on 224.0.0.167:53317 with `reuseAddr`, replies by `POST /api/localsend/v2/register` to a temporary `Bun.serve` or by multicast; cached 2 min) and hands the page fingerprints as ids; `GET /video/chats` runs `hermes send --list whatsapp --json`. `POST /video/send {p,name,file,via,to,text}` sends only `video.outputFile()` (one of that video's listed `outputs()` entries: mp4, srt, thumb), only to a fingerprint from the last discovery or a chat id from the last Hermes list (both held in `cli/web.ts`), one send per video (`startSend`), state in `/video/list` as `send` plus the last 5 of `sends` (log: `videos/<name>/.kaizen-sends.json`, last 50). "sent" is written only when the sender returned ok: LocalSend's upload 200, or Hermes exit 0 with `{success:true}`. LocalSend in HTTPS mode demands a TLS client certificate and takes its SHA-256 as the sender's fingerprint: `identity()` in `cli/localsend.ts` builds a self-signed RSA cert in DER by hand (node:crypto signs, Bun cannot issue). For MP4s at or below 64 MiB, Hermes runs as argv `send -t <id> --json -- "<text>\nMEDIA:`<abs path>`"`; text with `MEDIA:` is refused, since Hermes attaches every `MEDIA:` path it finds. Hermes reads `~/.hermes` from `HOME` (or `HERMES_HOME`): a board with a scratch `HOME` cannot list chats.
- Terminal page (`?view=terminal`, `web/board/terms.ts`, rail item in both `board.html` and `notes.html`): every card with an in-card session (`pty` from `/state`), Ideas to Done, as tiles headed `<run name> - <project name>`. A layout switch (Grid √n with the last tile spanning its row, Side by side, Stacked); drag a header onto a tile to swap, drag the borders to resize, maximise / hide / open card per tile. Layout is per browser in `localStorage` `kz-terms`. Each tile is another `kzTerm` mount on `/pty` (`attachPty` takes several listeners); mounts survive `/state` ticks and close when a session goes or the page is left. A phone (≤640px, `matchMedia` made on first show) shows one tile at a time, full height, picked from a row of tabs above it (dot + name, the first by default, not saved); Maximise and the splits are hidden there, and a header double-tap does nothing. Stacked tiles made every swipe land on a terminal, so the page could not be scrolled. A tile whose agent is asking gets `.asking`: a pulsing amber border (static ring under reduced motion), and on any board page, while the tab is hidden, a session that starts asking after the first `/state` raises `notifyUser()` tagged `ask:<pty key>` so several tabs show one (`load()` in `web/board/api.ts`; only with permission already granted). A dropped `/pty` socket (any close but `ended`) shows Reconnect in the tile's top-right strip and retries by itself after 1, 2, 4, 8, 15 s (`connect()` in `web/term.ts`, card panel too); a reopen resets the screen, since the board replays the whole session on attach. The side menu's Terminal entry carries a count of live hidden tiles (`termsBadge()`, `data-n` pill, called from `render()` and `openTerms()`; board.html only). An ended session's tile sorts last, is dimmed and labelled `ended`, offers Resume when it is a run (`resume()`, the page stays put), and its × closes it with no Hidden chip; when the board drops the session after `KEEP_MS` (10 min, `cli/pty.ts`) it calls `onChange`, so the tile leaves at once. A done or abandoned run's ended session is not shown at all (`ptyOf` in `cli/web.ts`), and the minute done-sweep (`sweepSessions`, 1 min grace) closes its live agent unless the user typed after Done: for a card session that is `ptyState().typed`, set by `writePty` only for real keys — xterm's focus, mouse and query answers (`REPORT`) reach the tty too and used to keep every looked-at agent open.
- `web/board/*.ts` — the page's script, one module per part (`cards.ts` columns, `panel.ts` run panel, `settings.ts`, `icebox.ts`, `projects.ts`, `dictation.ts`, `markdown.ts`, `live.ts`…), wired up by `main.ts` and bundled into `web/board.js` (served at `/board.js`) by `bun run build:web`. State that more than one module writes lives on the one `store` object in `store.ts`; everything else stays in the module that owns it.
- Hosts: the Host guard and `local()` (write Origin check) accept loopback plus the exact names in `KAIZEN_WEB_HOSTS` or `~/.kaizen/web-hosts` (`webHosts()` in `state.ts`, read per request; `kaizen setup` writes the file), for `tailscale serve`; `GET /manifest.webmanifest` makes the board installable on a phone (guide: "From your phone").
- Update alert: `GET /version` (running vs npm `latest`, cached 6 h) puts a dot on the Settings menu item and an Update bar at the top of Settings; Check for updates appears in both the alert and the quiet row, asks `/version?fresh=1`, and refreshes or clears the alert and dot from the response. A failed check leaves the existing alert in place. `POST /upgrade` runs `install.ts upgrade` in the server, then spawns a new board on the same port, which stops this one through the stale-board path in `web()`; the page reloads on the new boot id. On Windows the board cannot do that (Windows will not rename `~/kaizen` while the board holds files in it), so it starts a detached `install.ts upgrade --wait <pid> --restart <port>` (output in `~/.kaizen/upgrade.log`) and exits; that process waits for the board to go, upgrades, and starts a board on the port whatever the outcome. The helper runs from a copy of `cli/` in `~/.kaizen/upgrader/`, so nothing runs out of `~/kaizen`; the next board reads `upgrade.log` once at start and, when it failed, `/version` carries `failed` and the Update bar shows "Last update failed: …".

## Watch out
- The New idea form (`ideaForm()` in `web/board/cards.ts`) opens in a modal (`newIdea()`, via `modal()`) from the top bar's New idea, the empty board's button and the `n` key; the `+` in the Ideas column header opens the same form inline at the top of Ideas (`store.mode = "new"`). It takes files by Attach or paste: the idea is added through `/inbox` first, then the files go to `/note` (`for: <idea text>`), which saves them under `attachments/` and links them in the idea's notes. A failed upload leaves a text-only idea. `requestOf()` makes the links absolute when the run starts. Add is a split button: its chevron opens a menu with Start run, which does the same add, then reloads, finds the new idea card and passes it to `startRun()` with no kind, so `/run` launches it with the project's runner and default agent.
- Each inbox bullet carries a hidden `<!-- added:<ms> -->` stamp (`writeInbox` sets it for new text, keeps it otherwise; stamps are used once per line, so re-adding words an old line holds gets a fresh stamp). `boardCards` retires an idea only against runs whose `00-request.md` is not older than that stamp, so an old run with the same words cannot swallow a new idea. Unstamped legacy lines match as before.
- A started idea also retires when its board launch record (`sessions/<key>.json`, same text) is owned by a run per `ownerOf` — the run's `state.json` `session` matching the launch's id — so a run that reworded the request does not leave the idea stuck in planning beside it.
- `web/board.html` is not served verbatim: `notifier()` from `state.ts` is written over a `/*notifier*/` marker (`.kaizen/memory.md`).
- Installed as a phone app (`display-mode:standalone`) the body is `position:fixed;inset:0`, because iOS `100dvh` leaves the home-indicator strip black; both pages use `viewport-fit=cover` plus safe-area padding on phones and in standalone at any width; on phones the page background is `--bg` so the inset strips show no dark band.
- `render()` (`web/board/cards.ts`) rebuilds `#board` on every `changed` event; fields need a `draft()` key (`.kaizen/memory.md`).
- A card's one ask is a button on its face (`.act`): a waiting run's `actionOf()` label ("Review plan", "See findings", "Review work") opens it, a resumable stalled run gets Resume (`approvals.ts` `resume`). The card menu's Open item uses the same `actionOf()`; `cli/board.test.ts` lifts that declaration out of the source with the menu.
- Each column sorts waiting runs first, then by its Newest/Oldest order: runs by `moved`, ideas by `added` (the inbox stamp, on the card from `cli/state.ts`) across every project, inbox position only as tiebreak.
- Icebox "Add" opens a `modal()` form like the new-idea one (text, attach, mic, project combo in All projects); `/icebox` `add` takes `files`, saved to `<state>/attachments/` and linked in the item notes. Done cards (column 4, not the archive) are `compact`: one line, no footer. Empty Planning/Building/Review show a dashed hint (`li.hint`).
- `render()` sets `document.title` to `(n) kaizen` while n cards need you: runs waiting on you plus cards whose live agent is asking (`pty.asking`).
- The header filter box `#bq` sits outside `#board`, so redraws keep its text; `draft()` keeps it over a reload. `/` focuses it when no panel is open (in an open panel `/` still goes to `#sq`); Escape clears it. It matches title, request text and run id.
- Card notes (`chat()` in `web/board/chat.ts`): each plain line written as `Label: … Label: …` renders one paragraph per label with the label bold (`pretty()`, built on `brief()` in `web/board/markdown.ts`); markdown lines (lists, headings, tables, quotes) and fenced code are left as written.  The note box itself formats as you type (`rich()` in `web/board/rich.ts`): a contenteditable editor over the hidden textarea, which stays the value for drafts, dictation and send; `toMd()` turns the editor back into markdown on each edit, and typing `**b**`, `` `c` ``, `- `, `1. ` or `# ` re-renders it with `md()`. `*i*` formats as italic. Ctrl/Cmd+B bold, Ctrl/Cmd+E code; Shift+Enter is a soft line break in a paragraph (written as two trailing spaces, which `md()` renders as `<br>`) and a new item in a list; pasted text comes in plain. `brief()` labels are a capitalised word plus up to three lowercase words, or two to four ALL-CAPS words (`OPEN QUESTION`), each optionally followed by `(…)` before the colon.
- `web/board.js` is committed and hash-checked: after editing `web/board/`, run `bun run build:web` or `cli/notes.test.ts` fails. A module that assigns another module's variable must go through `store`: an imported binding cannot be assigned.
- Commit & push stages the whole working tree, and runs commit the paths backticked in `03-impl.md` (`runGit()`; `.kaizen/memory.md`).
- What counts as a run's for Commit & push and the card's git mark is judged per run (`runGit` / `cardsGit`): a changed file is its only when its report is newer than the file's last commit (so a run committed by its agent is not offered edits other sessions made since), and it is ahead only by its own unpushed commits (`aheadBy`): each commit goes to one run — the one whose report has the commit subject as a line, else the one naming most of its files, else the last to report — not by the branch being ahead.
- A run's `moved` (the running-vs-stalled signal) is the newer of `state.json` and `progress.md`, so a builder ticking its Work list stays running. Session owner lookups read every run once per call through `runIndex` (`ownerOf`'s third argument); `openSessions` drops `.pid` files whose process is gone or whose number another process now holds (`isSession` false; `null` when the system cannot say keeps it).
- Card fields needing git go in `cardsGit` (`/state`), not `boardCards()` (`.kaizen/memory.md`).
- A global `ul{display:flex}` in `board.html` hits lists in rendered markdown (`.kaizen/memory.md`).
- Settings and the Icebox share one panel and fill it after a fetch: `openSettings()` / `openSources()` must keep the `store.pageGen` check (`go()` bumps it), or a slow answer paints one page under the other's title. Switching to one of them clears the body to a Loading line before the fetch, or the old page shows under the new title until it answers.
- On phones the footer status strip (`.ftr`) is hidden. `#fbtn`, right of the project selects, opens it as a fixed sheet (`statusSheet()` in `cards.ts`). The button shows an amber dot while a run waits and an accent dot while a filter or the archive is on. Both the button and the sheet are off on desktop and on paged views.
- The "Showing" combo (`#showc`) opens its list from its right edge on phones, so it stays on screen.
- On phones (≤640px) the side menu is a bottom tab bar. It is CSS only, in the shared `/* side menu */` block of `board.html` and `notes.html`. The bar is in the page flow (`order:2`), not fixed, and it owns the bottom safe-area inset, so the body drops its own. The logo and the theme toggle are hidden there; theme is in Settings. Open panels (`aside`, fixed) cover the bar.
- Settings and the Icebox are full width: `aside.docked` header and body pad 28px each side (16px under 900px), no centred column.
- The Icebox is titled in the board header (`markView()` sets the `h1`) and hides the docked panel's header; the project picker shows folder names only, full path in the tooltip. The rail lists Icebox first, in both `board.html` and `notes.html` (a test holds them line for line).
- Popups: `web/board/main.ts` closes every open `.menu-pop` on a capture-phase `pointerdown` outside it, so only the newest one stays (card menus use stopPropagation, so bubble listeners never saw those clicks). New popups should be a `.menu-pop` inside a `.combo` to get this for free.
- Project logos: `cli/logo.ts` `projectLogo()` (fixed names only); `/state` projects carry `logo`, `GET /project-logo?dir=` serves it sandboxed; `plogo()` in `web/board/projects.ts` draws it or the folder initial.
- The server keeps no current project: each page sends its pick as `x-kz-dir` (`dirHeader()` in `web/board/api.ts`) and `cli/web.ts` resolves the project per request, so a phone picking another project never moves a desktop tab. `/cd` only checks the folder (and sets up a fresh one).
- Motion: Settings → Browser → Motion (`system`/`full`/`reduce`, `kz-motion` in localStorage) sets `<html data-motion>` from the head script of both `board.html` and `notes.html` (`setMotion`, beside `setTheme`). The reduced-motion CSS rule applies under the OS preference unless `data-motion=full`, and always under `reduce`; it covers the `::view-transition-*` pseudos too. `motion()`/`vt()` in `web/board/dom.ts` gate JS motion: `load()` (`web/board/api.ts`) gives a card that changed column the same `view-transition-name` on its old and new element and renders inside `vt()`, so it slides; a card that starts waiting or asking gets `.flash` for one render (`store.flash`). Rail clicks and popstate run `go()` inside `vt()` (crossfade), but `go()` itself stays synchronous for callers that open a panel right after. Board ↔ Notes crossfade via `@view-transition{navigation:auto}`. Notebook's sheet deal (`lift()`) honours `data-motion` too.
- Settings controls (`ctl()` in `web/board/settings.ts`): a switch for on/off, a `.bar` segment per value for the preset and numbers, and a `.step` stepper (`‹ value ›`, ids `<id>-prev`/`<id>-next`) for every other choice, Theme included. `stepper()` keeps the position and wraps at the ends: the shown value changes on each click, a config row saves 300 ms after the last click (one POST per burst), Theme applies at once. ←/→ press the arrows, the group is named by its row's `<label id="<id>-l">`, and the re-render puts focus back on the arrow pressed (`refocus()`).
- A settings row whose `idle` reason is set (from `when` in `cli/settings.ts`) gets `.srow.off`: dimmed, still clickable, reason appended to its hint.
