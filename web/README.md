# web/ — the board's front end

The board is React (Tailwind + Radix through `ui/`) built into `dist/board.js`. Each page is one small `App`
(`pages/board/App.tsx`, `pages/notebook/App.tsx`, `pages/popup/App.tsx`) rendered into `<div id="root">`; there is no `board/` folder any more: the
engines that react to the server and the router live in the feature folders of `lib/`, the page's glue in `pages/board/`. `bun run build:web` bundles everything into `dist/`
and a test fails when the committed bundles are stale. `checks/structure.test.ts` enforces the rules below.

## What is in web/

Only folders and this file; `checks/structure.test.ts` (which checks the whole tree, so
it stays here; it also fails on any other file at this level).

| Path | Holds |
|---|---|
| `html/` | `board.html`, `notes.html`, `popup.html`: shells of about 12 lines (the head, `<div id="root">`, the page's one stylesheet and one script; no inline CSS, markup or script, a test holds it). `video.html` is still a whole page. |
| `notebook/` | The Notes page's entry (`notebook.ts`: boots the shell, renders `pages/notebook/App.tsx`), `kit.ts` (registers the kit's stores as `window.kzKit` for code shared with Video), `kit-loader.ts` (hands that kit to shared code) and `notes-lib.ts` (re-exports `lib/notebook/text.ts` for `cli/`). |
| `popup/` | The chat popup's entry (`popup.ts`): renders `pages/popup/App.tsx` (`kaizen chat`), bundled to `dist/popup.js`. |
| `term/` | The in-card terminal's entry (`term.ts`, xterm.js) with its font and paste helpers and their tests. |
| `video/` | The Video page's entry (`video.ts`). |
| `annotate/` | `annotate.ts`: the annotator's page-side script (the part injected into the framed page: picker, overlay, note box, picture of the pick), bundled to `dist/annotate.js`. It imports only `lib/annotate/page.ts`. |
| `ui/`, `components/`, `pages/`, `lib/` | The board's layers, below. `ui/theme.css` is the Tailwind theme the kit is built from; `ui/legacy/` holds the page styles that were inline in the shells (`board.css`, `notes.css`, `popup.css`), moved unchanged and not yet rewritten as utilities. |
| `dist/` | Generated by `bun run build:web`, committed, never edited: `board.js`, `notebook.js`, `popup.js`, `term.js`, `video.js`, `annotate.js`, and the stylesheets `ui.css` (the kit; Video links it), `board.css` and `notebook.css` (the kit and the page's styles, one link per page), `popup.css`, `term.css`. |
| `sounds/` | The notification sounds the board plays. |

The server keeps serving the bundles at their old flat URLs (`/board.js`, `/ui.css`, `/notebook.js`,
`/term.js`, `/term.css`, `/video.js`, `/annotate.js`; the new `/board.css`, `/notebook.css`, `/popup.css` and `/popup.js` are in `AT_START` in `cli/web.ts`, which a test checks for every file in `html/` and `dist/`); only the files on disk moved, so a board that is
running during `kaizen upgrade` and old pages keep working. Entry sources are grouped by app because each
bundle's imports are the app's own helpers plus the layers below; `lib/` may import
a helper from an app folder (`notebook/notes-lib.ts`).

## Layers (imports only go downward)

```
pages/  ->  components/<feature>/  ->  ui/  ->  lib/core/utils.ts
                     \-> lib/<feature>/ (lib imports only lib)
```

| Folder | Holds |
|---|---|
| `pages/` | `board/`, `notebook/` and `popup/` each hold the page's `App.tsx` (providers, shell, the page picker, popups); the board's App is split into `header`, `pages`, `panel`, `portal`, `help` and `host`. Beside them one file per page: tasks, task, icebox, board, home, terminal, settings and notebook. Composes components; no logic of its own. The Board's App holds no state and is the page picker: the router (`lib/router`, no router library) holds the view the address names, `useRouteClasses` sets the `<body>` classes that show one page area, a page is drawn the first time its view opens (`Once`) and kept after, and the panel's body is one component (`pages/board/panel.tsx`) that shows what `lib/run/panel-store.ts` says and unmounts what it replaces. |
| `components/<feature>/` | Pieces a page draws. Popups, dialogs and menus come from `ui/`, never hand-built, no `innerHTML`. |
| `ui/` | Flat, one file per control (button, dialog, popover, select...). The only place that touches Radix or cmdk. |
| `lib/<feature>/` | Rules, stores (zustand), actions (requests) and hooks for one feature. No JSX. |
| `boot/` | `boot.ts`, built to `dist/boot.js` (1 KB): a blocking script in the head of the board and the Notebook that puts the stored theme, colour, motion and menu fold on `<html>` before the first paint (the one script besides the bundle; no inline script). |
| (no `board/`) | The old `board/` plumbing is gone and none is left as a named exception: the engines (`init…` functions that react to `lib/server` and `lib/router`) are in their feature folders (`lib/run`: the panel as `panel-store.ts`, `panel-actions.ts`, `panel-derive.ts` (pure) and the `usePanelRun` hook; `workspace.ts` (lifecycle) with `ws-derive.ts`, `ws-store.ts`, `ws-draw.ts`, `ws-actions.ts`, `kept.ts` and the `useRunLifecycle` hook, `card-terminal.ts`; `lib/board`: `snapshot.ts`, `on-state.ts`, `popups.ts`, `nav.ts`; and `lib/home`, `lib/terminal`, `lib/context`, `lib/git`, `lib/settings`, `lib/project`, `lib/search`, `lib/rail/rail-boot.ts`), and the page's glue in `pages/board/` (`main.ts`, `use-boot.ts` (the App's start-up effects), `views.ts`, `keys.ts`, `live.ts`, `host-bridge.ts`, which also answers `host.open`: what a page opens in place). The test `web/board is gone` fails on a new `web/board/` folder or an import of one; `BY_DESIGN` in `checks/structure.test.ts` names the only files left imperative on purpose (the terminal engine, the annotator's page script, CodeMirror, the note editor, dictation, the gestures), each with a signature the file must still show; every other `.ts` file in `lib/` and `pages/` is a module under the rules (no polling the server but `lib/server`, no page class but `lib/router`, no look-up of an element by id or selector but the named places, never a file that only forwards). |

## Rules

- **Index.** Every feature folder has an `index.ts` exporting what other folders use. Import another
  folder through it (`../../lib/task/index.ts`), never a file inside it. Inside a folder, import files
  directly (that keeps barrels out of cycles). `import type` follows the same rule.
- **Size.** A folder over 25 files is split by feature.
- **Where to add a thing.** Used by one feature: that feature's folder. Used by two: `shared` (a
  component) or `core` (a helper), and add it to the index. A new feature: a folder in `components/`
  and `lib/` with an `index.ts`, and a row in the table above.
- **Names.** Kebab-case files (`task-row.tsx`, `use-task.ts`); the file's main export is its
  PascalCase name; hooks start with `use-`; stores end `-store`, request functions `-actions`.
  Tests live beside the code they test as `*.test.ts` (in the feature folder, , import the file they test directly, and are not counted in the 25-file limit; an `index.ts` never exports them. `checks/structure.test.ts` stays in `web/` because it checks the whole tree.
- **Nothing draws by hand.** No `innerHTML`, `insertAdjacentHTML`, `DOMParser`, `createContextualFragment`, hand-built dialog or `x.createElement(...)` on any document anywhere in `web/` except `video/` (its own page, no React) and the named files in `EXEMPT` (`checks/structure.test.ts`), each with its reason and the most uses it may keep (a new use fails until the count is raised on purpose): `term/term.ts` (xterm's own bundle: find box, paste, reconnect strip and the phone key bar, whose `pointerdown` + `preventDefault` keeps the soft keyboard open; turning it into React needs a controller API out of the engine and a real phone to check), `lib/notes/rich.ts` (the note editor's contenteditable engine), `annotate/annotate.ts` (injected into the framed page), the two CodeMirror widget files, `pages/tasks-page.tsx` (one span in the header), and Video's fallback toast (`lib/core/notices.ts`). A stale line fails the test.
- **Exceptions.** `ui/` takes `lib/core/utils.ts` directly. A few bridge files (`rail-boot`, `search-rows`, `ws-tabs`, `ws-board`, and the board's `main.ts` and `use-boot.ts`) import small lib files
  directly because they run in the notebook and Video bundles or in DOM-less tests, where a
  barrel would pull in the board's stores (list: `BRIDGE_DIRECT` in `checks/structure.test.ts`).
- **Core's type imports.** `lib/core/api.ts` and `store.ts` use `import type` from `lib/task` and
  `lib/icebox` for data shapes; erased at build, so no runtime cycle.

## Imports
Across folders always use an alias (tsconfig `paths`, resolved by Bun), never `../../`:
`import { Button } from "@web/ui"`, `import { useGit } from "@lib/git"`, `import { ActionMenu } from "@components/shared"`.
A folder alias means its `index.ts`; a file alias keeps its extension (`@lib/core/labels.ts`, only the listed bridge files).
Inside one folder import siblings relatively (`./card-footer.tsx`). New ui files get one line in `web/ui/index.ts`.
