# web/ — the board's front end

The board is React (Tailwind + Radix through `ui/`) built into `dist/board.js`; `board/` is the older
bridge layer that mounts it. `bun run build:web` bundles everything into `dist/` and a test fails when the
committed bundles are stale. `checks/structure.test.ts` enforces the rules below.

## What is in web/

Only folders and this file; `checks/structure.test.ts` (which checks the whole tree, so
it stays here; it also fails on any other file at this level).

| Path | Holds |
|---|---|
| `html/` | `board.html`, `notes.html`, `video.html`, `popup.html`: the page shells the server sends. Inline CSS and a `<script src>` tag to a bundle. |
| `notebook/` | The Notes page's entry (`notebook.ts`, CodeMirror) and its text rules (`notes-lib.ts`, also used by `cli/` and the board); `kit.ts` (entry of the React bundle the page loads at start: its Projects list and filter, Search and project sheets) and `kit-loader.ts`. |
| `term/` | The in-card terminal's entry (`term.ts`, xterm.js) with its font and paste helpers and their tests. |
| `video/` | The Video page's entry (`video.ts`). |
| `annotate/` | `annotate.js`: the annotator script, plain JS written by hand (not generated), served as-is. |
| `ui/`, `components/`, `pages/`, `lib/`, `board/` | The board's layers, below. `ui/theme.css` is the Tailwind theme the kit is built from. |
| `dist/` | Generated by `bun run build:web`, committed, never edited: `board.js`, `ui.css`, `notebook.js`, `notebook-kit.js`, `term.js`, `term.css`, `video.js`. |
| `sounds/` | The notification sounds the board plays. |

The server keeps serving the bundles at their old flat URLs (`/board.js`, `/ui.css`, `/notebook.js`, `/notebook-kit.js`,
`/term.js`, `/term.css`, `/video.js`, `/annotate.js`); only the files on disk moved, so a board that is
running during `kaizen upgrade` and old pages keep working. Entry sources are grouped by app because each
bundle's imports are the app's own helpers plus the board's `board/` modules; `board/` and `lib/` may import
a helper from an app folder (`notebook/notes-lib.ts`, `term/term-font.ts`).

## Layers (imports only go downward)

```
pages/  ->  components/<feature>/  ->  ui/  ->  lib/core/utils.ts
                     \-> lib/<feature>/ (lib imports only lib)
```

| Folder | Holds |
|---|---|
| `pages/` | One file per board page: tasks, task, icebox, board, home, settings. Composes components; no logic of its own. |
| `components/<feature>/` | Pieces a page draws. Popups, dialogs and menus come from `ui/`, never hand-built, no `innerHTML`. |
| `ui/` | Flat, one file per control (button, dialog, popover, select...). The only place that touches Radix or cmdk. |
| `lib/<feature>/` | Rules, stores (zustand), actions (requests) and hooks for one feature. No JSX. |
| `board/` | The bridge: plain modules that mount the React pages (`react-mount.ts`) and drive the rest of the board. Being replaced; add nothing new here. |

## Feature folders

`components/<f>/` and `lib/<f>/` use the same name when both exist.

| Folder | What it is |
|---|---|
| `shared` | Pieces two or more features use: chip, icon button, field, picker, segmented, pager, project mark, empty state, confirm dialog and `AskHost`, mic/attach buttons, and the hooks `use-draft`, `use-narrow`, `use-pager`. |
| `core` (lib only) | Generic helpers and the base model: `api`, `host`, `utils`, `format`, `labels`, `toast`, `store` (the Tasks pages' state), `ask`, plus `board.ts` (the card/run model) and `brief`. |
| `task` | The Tasks list and one task: rows, status badge, chat bubbles, result view, artifact frame; `useTasks`, `useTask`, `useDock`. |
| `decision` | The decision bar a task or run waits on, and its forms (revise, reply, plan answers). |
| `icebox` | Icebox requests (row, card, phone row, swipe deck), capture box, sources (card, form, drawer), collections, board/kind/snooze menus. |
| `board` | The Kanban board: card, column, popups, the New task / run / card forms, the mode switch. |
| `run` | The run panel and run view: head, tabs, history, picker, footer, wait/empty states, file viewer, fix form; the centre's panes (`run-panes`, `pane`, `pane-gutter`, `terminal-pane`, `browser-pane`) and panel grip; in `lib/run`: the pane layout rules (`layout`) and its saved store (`layout-store`), the Browser's history (`browser`), `run-actions`. |
| `git` | The run's Source control tab. |
| `settings` | Settings page rows, nav, sections, update bar; settings store and actions, update check, mic choice. |
| `phone` | Phone setup (QR, WhatsApp card), the phone-sized new-run sheets, and the phone's Home and Runs pages (agents, devices, runs, usage chips; `lib/phone`: their rules, the store, the taps' requests, the run sheet's swipe rules) with the tap tick. |
| `home` | Home: chat list, messages, composer, onboarding dialog; the home store; the floating Home window (its tabs, drag, minimized sidebar row and "+" menu; `lib/home/home-window.ts` holds its rules and requests, the terminal is `run`'s `TerminalPane`). |
| `project` | Project picker, Add project dialog, workspace menu, branch rules. |
| `rail` | The side menu's Projects list (rows, folds, pins, project drag, agent chips, task links, worktree right-click menu) and its filter; rules, store and requests in `lib/rail`. Rows keep the board's legacy classes. |
| `resources` | The footer resource popup: Memory, Storage, Terminals; store, requests and sizes in `lib/resources`. |
| `search` | The search palette and its matching. |
| `markdown`, `url` | The markdown renderer (component and parser) and `safeUrl`, kept apart so the notebook bundle takes only `safeUrl`. |

## Rules

- **Index.** Every feature folder has an `index.ts` exporting what other folders use. Import another
  folder through it (`../../lib/task/index.ts`), never a file inside it. Inside a folder, import files
  directly (that keeps barrels out of cycles). `import type` follows the same rule.
- **Size.** A folder over 25 files is split by feature.
- **Where to add a thing.** Used by one feature: that feature's folder. Used by two: `shared` (a
  component) or `core` (a helper), and add it to the index. A new feature: a folder in `components/`
  and `lib/` with an `index.ts`, and a row in the table above.
- **Names.** Kebab-case files (`task-row.tsx`, `use-task.ts`); the file's main export is its
  PascalCase name; hooks start with `use-`; stores end `-store`, request functions `-actions`.
  Tests live beside the code they test as `*.test.ts` (in the feature folder, or in `term/` next to `term-font.ts`), import the file they test directly, and are not counted in the 25-file limit; an `index.ts` never exports them. `checks/structure.test.ts` stays in `web/` because it checks the whole tree.
- **Exceptions.** `ui/` takes `lib/core/utils.ts` directly. Seven `board/` bridge files import one small
  lib file directly because they run in the notebook and Video bundles or in DOM-less tests, where a
  barrel would pull in the board's stores (list: `BRIDGE_DIRECT` in `checks/structure.test.ts`).
- **Core's type imports.** `lib/core/api.ts` and `store.ts` use `import type` from `lib/task` and
  `lib/icebox` for data shapes; erased at build, so no runtime cycle.

## Imports
Across folders always use an alias (tsconfig `paths`, resolved by Bun), never `../../`:
`import { Button } from "@web/ui"`, `import { useGit } from "@lib/git"`, `import { ActionMenu } from "@components/shared"`.
A folder alias means its `index.ts`; a file alias keeps its extension (`@lib/core/labels.ts`, only the listed bridge files).
Inside one folder import siblings relatively (`./card-footer.tsx`). New ui files get one line in `web/ui/index.ts`.
